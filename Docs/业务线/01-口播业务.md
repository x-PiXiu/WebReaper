# 口播业务详细分析

> 最后更新：2026-08-31
> 定位：口播视频业务的服务端实现细节分析

---

## 一、业务概述

口播业务是 WebReaper 的核心业务之一，提供**数字人+对口型视频**的批量生产能力。

**核心价值**：
- 跨视频人物一致性（同一分身产出的系列视频形象统一）
- 批量生产（一个分身+多篇文案=多个视频）
- 傻瓜式操作（向导引导，用户无需专业技能）
- B-Roll 单阶段（29号计划：配置+生成+插入一体化）

## 二、用户旅程

```
┌─────────────────────────────────────────────────────────────────────────┐
│ 阶段0  数字分身准备（一次性）                                            │
│   上传形象照/视频 → 创建主体 → 自动生成10s形象视频 → 分身可用             │
└─────────────────────────────────────────────────────────────────────────┘
                                    ↓
┌─────────────────────────────────────────────────────────────────────────┐
│ 阶段1  台词来源（向导第①步，三选一）                                     │
│   ① 粘贴爆款链接提取文案（抖音/B站/长尾平台）                            │
│   ② 上传参考音/视频 → ASR 提取                                          │
│   ③ 手写/粘贴文案                                                       │
└─────────────────────────────────────────────────────────────────────────┘
                                    ↓
┌─────────────────────────────────────────────────────────────────────────┐
│ 阶段2  口播生成向导（傻瓜式分步）                                        │
│   选品牌人设 → 选出镜形态 → 选音色（默认已选中）                          │
│   → 选B-Roll片段（可选，29号计划）→ 生成                                 │
└─────────────────────────────────────────────────────────────────────────┘
                                    ↓
┌─────────────────────────────────────────────────────────────────────────┐
│ 阶段3  系统自动处理                                                     │
│                                                                         │
│  文本驱动（默认）：                                                       │
│    lip_sync(video_url, text, voice_id) → 口播视频                       │
│    → 定位时间轴 → 合成B-Roll → 最终视频                                  │
│                                                                         │
│  音频驱动（用户上传音频时）：                                             │
│    lip_sync(video_url, audio_url) → 口播视频                            │
│    → 定位时间轴 → 合成B-Roll → 最终视频                                  │
│                                                                         │
│  ⚠️ 不需要单独TTS步骤，Vidu lip_sync API 一步到位                        │
└─────────────────────────────────────────────────────────────────────────┘
                                    ↓
┌─────────────────────────────────────────────────────────────────────────┐
│ 阶段4  发布分发                                                          │
│   选平台/账号 → 发布 → 作品库跟踪                                       │
└─────────────────────────────────────────────────────────────────────────┘
```

**29号计划改进**：B-Roll 插入从"生成后手动操作"改为"生成前配置+系统自动执行"，用户只需一次操作。

**关键澄清**：口播视频生成不需要单独的 TTS 步骤。Vidu 的 lip_sync API 本身就支持：
- **文本驱动**：传入 `text` + `voice_id`，Vidu 内部生成语音+对口型（一步到位）
- **音频驱动**：传入 `audio_url`，直接用音频对口型

## 三、涉及的生成端点

| 端点 | sub_type | 用途 | 输入 | 输出 |
|------|----------|------|------|------|
| 主体注册 | `subject` | 创建数字分身 | 形象照+名称 | server_id |
| 参考生视频 | `reference2video` | 生成形象视频/口播视频 | 主体+prompt | 视频 |
| 对口型 | `lip_sync` | 视频+音频/文本→口播 | 视频+音频/文本 | 视频 |
| 语音合成 | `tts` | 文本→音频 | 文本+音色 | 音频 |
| 声音克隆 | `voice_clone` | 音频样本→专属音色 | 音频样本 | voice_id |
| B-Roll合成 | `compose` | 画面插入 | 源视频+片段 | 合成视频 |

> **注意**：`digital_human` 端点仍有旧数据（8月12-26日测试数据），但新流程已转向 `lip_sync + reference2video`。

### 4.3 对口型生成（lip_sync）

**入口**：`POST /api/v1/generation/submit` (sub_type=lip_sync)

**Vidu lip_sync API 两种驱动模式**：

| 模式 | 参数 | 说明 |
|------|------|------|
| **音频驱动** | `video_url` + `audio_url` | 直接用音频对口型 |

```go
// prompt_placeholder.go - Translate()
func (t *PlaceholderTranslator) Translate(
    ctx context.Context,
    provider string,
    subType string,
    params entity.GenerationParams,
    refs []entity.PromptRef,
    tenantID string,
) (entity.GenerationParams, error) {
    // ① 解析 @名称 占位符
    matches := placeholderRegexp.FindAllStringSubmatch(prompt, -1)

    // ② 分类：素材引用 vs 主体引用
    // 素材引用：在 refs 中有对应的 PromptRef
    // 主体引用：在 refs 中没有，可能是已注册的主体名称

    // ③ 处理素材引用（复用 translateRefs）
    if len(materialRefs) > 0 {
        params, _ = translateRefs(subType, cap, params, materialRefs)
    }

    // ④ 处理主体引用（按厂商规则）
    if len(subjectNames) > 0 {
        rule := t.providerRules[provider]
        if rule.KeepSubjectRef {
            // Vidu 模式：保留 @name，添加 subjects 数组
            params["subjects"] = buildSubjectsArray(subjects)
        } else {
            // 其他厂商模式：移除 @name
            prompt = removeSubjectPlaceholders(prompt, subjectNames)
            params["prompt"] = prompt
        }
    }
}
```

```go
func (uc *GenerationUseCase) chainBrollAfterGeneration(ctx context.Context, sourceTask entity.GenerationTask, segments []BrollSegment) {
```

#### 4.7.3 插入逻辑改进（29号计划）

| 极端情况 | 改进前 | 改进后 |
|----------|--------|--------|
| 片段比时间窗长 | `shortest=1` 截断 | 不截断，播完整个片段 |
| 片段比时间窗短 | `tpad=clone` 定格 | 播完后显示原片 |
| 图片片段 | 循环视频 | 静态显示到时间窗结束 |
| 时间窗重叠 | 校验报错拒绝 | 后续片段优先 |
| 同句重复插入 | 校验报错拒绝 | 保持拒绝 |

**核心理念**：时间窗是**起始标记**（片段从这里开始播放），不是**严格边界**。

### 4.8 台词时间轴定位（timeline）

**入口**：`POST /api/v1/generation/tasks/:id/timeline`

**处理流程**：

```go
// videocompose/timeline.go - LocateTimeline() [line 79]
func (uc *UseCase) LocateTimeline(ctx context.Context, tenantID, taskID string, force bool, linesOverride []TimelineLineOverride) ([]TimelineLine, string, error) {
    // ① 文字修正模式（只改各行text，时间窗不动）
    if len(linesOverride) > 0 {
        meta.Lines[o.Index].Text = o.Text
        return meta.Lines, meta.ScriptSource, nil
    }

    // ② 缓存命中（非force）
    if meta, ok := parseTimeline(task.TimelineJSON); ok && !force {
        return meta.Lines, meta.ScriptSource, nil
    }

    // ③ 下载成片
    mediaPath, cleanup, _ := uc.safeDownloadTaskMedia(ctx, task)

    // ④ 静音检测
    segs, _ := uc.av.DetectSpeechSegments(ctx, mediaPath)

    // ⑤ 台词配对
    script := taskScript(task)
    if script != "" {
        // A/B路径：台词行与语音段配对
        lines := splitLines(script)
        meta = alignSegments(segs, lines)
    } else {
        // C路径：ASR全文→按段时长比例切行
        audioPath, _ := uc.av.ExtractAudio(ctx, mediaPath)
        text, _ := uc.transcriber.Transcribe(ctx, audioPath, "audio/mpeg", 0)
        meta = splitBySegments(segs, text)
    }

    // ⑥ 保存时间轴
    uc.saveTimeline(ctx, task, meta)
    return meta.Lines, meta.ScriptSource, nil
}
```

**三种配对模式**：
- **M==N**：语音段数=台词行数，直接配对（direct）
- **M>N**：语音段多于台词行，按字符比例合并相邻段（estimated）
- **M<N**：语音段少于台词行，按字符比例拆分段（estimated）

**关键代码位置**：
- `internal/usecase/videocompose/timeline.go:79` - LocateTimeline
- `internal/usecase/videocompose/timeline.go:201` - alignSegments
