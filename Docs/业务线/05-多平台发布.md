# 多平台发布详细分析

> 最后更新：2026-09-01（对齐提交 8eb08bc：API 通道删除 / 全自动矩阵全放行 / N1 分身+上传音频两步链）
> 定位：多平台内容分发业务的服务端实现细节分析（含音频内容的生产→发布链路，§4.7）

---

## 一、业务概述

多平台发布把口播/图文/文章作品一键分发到 7 个平台（知乎/小红书/抖音/快手/B站/视频号/YouTube），
提供**半自动**（生成预填发布链接，用户手动完成）与**全自动**（RPA 浏览器代发）两种模式，
配套账号绑定/健康巡检/配额限流/定时发布/发布后互动数据回读。

**全自动矩阵（2026-09-01 全放行）**：`verifiedAutoForms`（account.go:530-538）从 2 格扩至
7 平台 9 格——用户确认 7 平台 PublishAuto 代码全部实现，选择器失败会**报错**（不静默丢失），
逐步真机校准即可。
⚠️ 🔴 **P1·门禁与执行层的已知落差**：小红书 `PublishAuto` 执行层目前**仅实现 image**，
video/article/audio 仍返回"暂未实现"（auto_channel.go:377-385）——而矩阵已放行小红书 video，
该组合的自动任务会通过校验、进入执行后**必失败**（详见 §8.2 #1）。

**通道轴（2026-09-01 删 API）**：`TransportAPI` 常量、Resolve 的 API case、OAuth 账号前置 api 候选
均已删（用户确认不用官方 API 通道）。现仅 link/rpa 两条通道，候选链 `[rpa → link]`；
恢复路径记录在 publish_transport.go:20-21 注释（常量 + 一个 case + 一个候选元素）。

## 二、用户旅程

```
【账号池】绑定账号（扫码 QRLogin / 抖音官方 OAuth）→ 健康巡检（10min 周期）
      OAuth 双时钟续期：access 到期前 48h 刷新；refresh 窗口关前 7 天续期
      （抖音 15天/30天续5次 → 最长 195 天）
      ※ OAuth 账号体系完整保留（account.go:267-310），仅"API 发布通道"删除
          ↓
【发布向导·五步】① 平台与形态（健康账号多选卡；前端形态仅 文章/图文/视频 三项——
      无 audio 选项，服务端声明的小红书 audio 只暴露在 channels 端点）
      ② 标题与正文（服务端 adapt-preview 预览各平台截断/清洗）
      ③ 素材（AssetPicker 复用） ④ 平台参数（B站分区/标签/全自动/自动选号/定时）
      ⑤ 预览确认（多平台适配预览 + 配额拦截 + 完备性检查）
          ↓
【发布执行】半自动：生成预填链接新窗口打开 → 用户手动发 → 标记已发布（此刻才记配额）
      全自动：账号池取号（最久未用优先）→ 通道轴 [override＞]rpa→link 启动前降级
      → RPA 上传/填表/点发布 → 成功取作品链接
      定时：scheduled_at 到期由定时任务（5min 扫描）执行
          ↓
【发布后】互动数据回读（24h 批量+单条手动刷新）→ 提及率前后对比（GEO 效果追踪）
      → 复测（手动/自动 6h）→ 发布记录 Tab 统计
```

**音频内容旅程**（生产侧详见 §4.7 及 01/04 号文档）：
上传音频/TTS → lip_sync 对口型成片 →（可选 B-Roll 合成）→ 进"我的作品"（deliverable 子类型）
→ 分发中心按 video 形态发布（音画已在同一 mp4）。

## 三、发布通道（7 平台）

| 平台 | 支持形态 | 关键约束 | 全自动（verifiedAutoForms） | 半自动 URL |
|------|---------|---------|--------|-----------|
| 知乎 | article | 标题≤100 | ✅ article | zhuanlan.zhihu.com/write（正文不预填 CSRF） |
| 小红书 | image/video/article/audio（声明） | 标题≤20、图片≥1（仅 image 有约束） | image ✅；video 放行但🔴P1（RPA 执行层报"暂未实现"→必失败，§8.2 #1） | creator.xiaohongshu.com/publish/publish?target={ct}（audio 直达 target=audio） |
| 抖音 | video | 标题≤55、视频≥1 | ✅ video | creator.douyin.com/creator-micro |
| 快手 | video | 标题≤80、视频≥1 | ✅ video（与抖音同构实现，非 stub） | cp.kuaishou.com/article/publish/video |
| B站 | video | 标题≤80、必填标签+分区≤10 | ✅ video（分区选择器待真机校准） | member.bilibili.com/platform/upload |
| 视频号 | video+image | 标题≤40（RPA 层仅留汉字截16字） | ✅ video+image | channels.weixin.qq.com/platform/media |
| YouTube | video | 标题≤100、隐私性 public/unlisted/private | ✅ video（panda upload spec 移植） | studio.youtube.com/channel/me/videos/upload（cookie 双域种值） |

**小红书 audio 形态现状**：服务端 `SupportedContentTypes` 声明 audio（auto_channel.go:311-313）、
半自动按 ContentType 拼 `target=` 直达正确发布页（:316-322，audio 可用）；但 RPA 未实现（:380-382 报错）、
Constraints 无 audio 条目、前端 `PublishForm` 枚举无 audio（wizardModel.ts:3）——UI 上用户实际选不到（§8.2 #10）。

**RPA 技术要点**：抖音四级降级上传+网络响应拦截取 aweme_id（douyin_channel.go:338-348 只取 paths[0]，
封面走独立 CoverURL :452-460）；快手发布成功以"跳回内容管理页"为校准信号、视频链接待人工补录（:307）；
小红书 closed Shadow DOM 穿透补丁（导航前重写 attachShadow 强制 open，auto_channel.go:346-364）；
B站标签 JS 设值+CDP 回车防中文双插入、发布按钮 iframe/micro-app 全文档穿透；
健康预检=导航后 URL 回落登录页即标过期；cookie 滚动回写续期（抖音/快手/YouTube 通道，douyin_channel.go:95）。
**DRY_RUN 演练**：`PUBLISH_DRY_RUN=true` 走完上传+填表+截图但**绝不点发布**（真机校准选择器用）。
**素材消费约定**：RPA 上传按"图片[]（小红书图文全量）或视频[0]（其余平台）"处理——
`downloadMediaToTemp` 扩展名推断只有 jpg/jpeg/webp/mp4/mov/webm，默认 `.png`，
**无 mp3/m4a/wav 分支**（auto_channel.go:649-662）。

## 四、服务端实现细节

### 4.1 发布主流程（PublishUseCase.Publish，account.go:617-716）

```
mode 默认 semi-auto（:623-626）→ registry.Get(platform) → validateCapability（:470-515 服务端强校验
  形态支持 + Constraints：TitleMaxRunes/MinImages/MinVideos/RequireTags/MaxTags/RequireCategory；
  校验的是 Channel 声明而非 verifiedAutoForms，无 audio 专用约束字段）
→ checkPublishLimit（:419-435 品牌 RateLimit.MaxPerDay 限流；无配置不限流，记账失败不阻断）
→ 内容预处理：剥思考标签 + Markdown 转纯文 → 知乎追加公开站链接（:606-615 仅 zhihu）
  + 门店地址注入（:650-652 防重）→ 标题空/<4字 → ExtractTitle(正文)
→ job 落库（pj-{nano}，pending；透传 ContentType/MediaURLs/CoverURL/Tags/Category/Privacy）
→ 定时：ScheduledAt 未来 → 直接返回（:681-688），定时任务执行（半自动到期回 pending 供确认 :943）
→ 全自动 publishAuto / 半自动生成 ExternalURL
```

**通道轴降级**（:762-795）：候选 `[rpa, link]`（account.go:771）；管理后台 override 由
`Registry.Chain` 头插（publish_transport.go:165-186）；RPA 通道 cookie 缺失或凭证 Resolve 失败
短路下一通道；全链无可用凭证 → 旧路径兜底直解 cookie（:796-830，报"无可用发布通道（rpa 凭证缺失）"）。
**降级只发生在启动前**——执行中失败落库报错、不自动换通道重发（视频可能已实际发出，重发=重复发布事故）。
`ErrTransportDegradable`（transports.go:91-93）是通道层可降级信号，当前主要用于启动前预检场景。

### 4.2 全自动执行（publishAuto，account.go:719-870）

通道未实现 AutoPublishChannel → 直接降半自动（:719-736）；未指定账号 → 账号池 Acquire
（active + 最久未用优先，:741-750）；running 落库 → 后台 goroutine（5min 超时）PublishAuto
→ published/failed → Release 回池（:860-862）→ `trackPublishEffect`（:879-896 发布前后提及率，
仅 BrandID 非空触发；追踪失败只记 ErrorMsg 不影响 published 状态）。
成功记 `publish_usage_stats`（配额依据，:856-857）；半自动用量在 MarkPublished 才记（:1166-1175）。
僵尸清扫：启动时 ReapStaleJobs(30min)。

### 4.3 内容适配（content_adapter.go）

DefaultPlatformConfigs 按平台声明 标题/描述/标签上限 + Emoji 密度 + CTA 策略（:29-102，
视频号标题 16 字仅汉字、知乎/YouTube 100、B站 80 实测）；`Adapt`（:126-228）：截断加省略号/
换行限制/Emoji 移除/标签提取合并/随机 CTA。
预览端点 `POST /merchant/publish/adapt-preview`（router_geo.go:175，前端失败时 localAdaptPreview 兜底）。

### 4.4 账号体系

- 实体：CookieEncrypted（AES-GCM）/Health(active|expired|banned，banned 不可恢复)/AuthType(cookie|oauth)
- 绑定：扫码（知乎四方式）+ 抖音 OAuth（同 open_id 重新授权=续期，account.go:66-122）
- 巡检：AccountHealthTask 10min；OAuth 双时钟续期（:267-310）——API 通道删除后该体系完整保留，
  OAuth 账号仍走半自动/RPA；`TransportRequest.APIToken` 字段仍在且被赋值（publish_transport.go:34、
  account.go:791），属删除残留（§8.2 #9）
- 账号池 + 品牌绑定（BrandAccountSelector 绑定优先回退全局）+ 人设隔离（persona_isolator）

### 4.5 定时与自动闭环

- ScheduledPublishTask 5min（tasks_automation.go:29-30）：ListScheduledDue → ExecuteScheduledJob（:915-946）→ 站内通知
- AutoPublishTask 5min（auto_publish.go:49-50）：生成→发布闭环（开关 auto_publish_enabled，仅 video/image，半自动）
- AutoMonitorAfterPublishTask 10min（auto_monitor_after_publish.go:42-43）/ AutoRecheckTask 6h（tasks_automation.go:83-84）
- VideoMetricsTask 24h（video_metrics_task.go:25-26，批量回读）

### 4.6 发布后数据回读

单条 RefreshJobMetrics（published + 可解析视频 ID 才可回读）→ socialSearch.GetVideoDetail
→ video_metrics 时间序列；批量 VideoMetricsTask 每日（500 条、2s 间隔防风控）；
聚合 AnalyticsSummary（指标卡+14 天趋势+作品列表）。
**半自动限制**：手动发布无作品链接 → 无法回读（前端显示"链接未追踪"）。

### 4.7 音频内容的生产与发布链路（2026-09-01 新增）

音频在发布域是"二等公民"：**生产链完整**（生成域，详见 04 号），**发布侧仅小红书声明 audio 形态**
且实际只有半自动直达可用。发布的主要内容形态是"音画合一的 mp4"（video）。

#### ① 音频素材的三个来源

| 来源 | 链路 | 产物 |
|------|------|------|
| 上传音频 | `POST /media/assets`（media_handler.go:29-86；扩展名白名单含 mp3/m4a/wav，音频 ≤20MB）→ material 资产，`InferTypeFromMime` 按 `audio/` 前缀标 MaterialTypeAudio | 素材库音频（lip_sync 输入 / ASR 文案提取输入） |
| 独立 TTS | 统一提交 `type='audio'`（endpoint_selector.go:310-313 → tts 端点） | 音频素材——**不进作品库**（works.go:226-229 materialSubTypes） |
| 文本驱动端内合成 | lip_sync 只传 text+voice_id，Vidu 端内合成语音 | 成片（无独立音频产物） |

#### ② 口播管线：音频与视频的结合（useLipSyncPipeline.ts）

| 路径 | 步骤 | 服务端行为 |
|------|------|-----------|
| 真人视频 + 上传音频 | 单步（:132-149） | materials=[video,audio] → selector `VideoCount>0 && AudioCount>0` → lip_sync（endpoint_selector.go:225-229） |
| 分身 + 上传音频（**N1 修复后两步链**，:159-187） | ① reference2video 生成分身**纯画面**（无音频）→ ② ①产物视频 + 上传音频 → lip_sync | ① 命中 subjects 最优先分支（:211-218，参数仅 prompt+subjects）；② 走 video+audio 规则。前端两步链规避"subjects+音频"同传；**服务端已加守卫**——该组合现在显式报错并提示两步链，不再静默丢音频（endpoint_selector.go:211-222，§8.1） |
| 分身 + 文本 | 单步（:188-202） | subjects+text → reference2video 文本驱动，端内合成语音 |

- lip_sync 端点 `/ent/v2/lip-sync`（endpoints.go:339-394）：`video_url` 必填；`audio_url`/`text` 二选一，
  **audio_url 优先**（同传时上游以音频为准，speed/voice_id/volume 失效）；异步任务+回调。
- `buildLipSyncParams`（endpoint_selector.go:398-409）：video_url=视频素材 SourceURL（或 params.video_url
  直传）、audio_url=Audios[0].SourceURL；素材支持 ID 与 `/media/` URL 双匹配反查（:110-181）。
- **对口型完全由 Vidu API 完成**；本地 ffmpeg 不做混音——B-Roll 合成只 overlay 画面，
  主视频音轨 `-map 0:a:0 -c:a copy` 直拷（mediaav/compose.go:12,69），纯音频片段会被拒绝（compose.go:176-178）。
- B-Roll 台词时间轴 C 路径（上传音频成片、无 script）：ffmpeg 抽音轨 → ASR 全文 → 按语音段
  比例切台词行（timeline.go:139-152）；ASR 另一消费方是文案提取（`/generation/transcript/*`，24h 缓存）。

#### ③ 音频内容进入发布的路径

```
lip_sync / reference2video / digital_human / compose 等 deliverable 子类型 → 我的作品（works.go:234-238）
      → 分发中心选作品 → PublishInput{ContentType:'video', MediaURLs:[mp4]}（音画已在同一 mp4）
音频直发（PublishInput 声明 ContentType:'audio'，MediaURLs=mp3，account.go:583-586）：
      仅小红书声明该形态——半自动 target=audio 直达可用；
      RPA 报"暂未实现"、前端无 audio 选项 → 现状 UI 不可达（§8.2 #10）
```

#### ④ 发布侧音频的缺口清单

- 前端 `PublishForm = 'article' | 'image' | 'video'`——无 audio（wizardModel.ts:3，PublishWizard formOptions 三项）；
- 小红书 Constraints 无 audio 条目（`ChannelConstraints` 结构本身只有 min_images/min_videos 字段，
  entity/account.go:185-193）；
- RPA 素材下载无音频扩展名分支（默认 `.png`，auto_channel.go:649-662）；
- 无任何平台的 RPA 分支按 `ContentType=='audio'` 上传音频文件。
