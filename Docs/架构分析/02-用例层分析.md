# 用例层（Usecase Layer）分析

> 整洁架构的应用层：编排业务流程，协调领域对象和外部服务

## 1. 用例层概述

用例层是**业务逻辑的核心**，负责：
- 编排领域对象完成业务流程
- 协调多个 Repository 和 Service
- 实现应用级业务规则（如配额检查、缓存失效）
- 定义输入/输出 DTO（Data Transfer Object）

**设计原则**：
- 只依赖 Domain 层的实体和 Port 接口
- 不依赖具体的 Adapter 实现
- 业务流程清晰可读

## 2. 核心用例分析

### 2.1 GenerationUseCase（内容生成用例）

**位置**：`internal/usecase/generation/generation.go`

**业务定位**：统一生成任务的核心编排器

#### 2.1.1 核心职责

```go
type GenerationUseCase struct {
    provider   port.GenerationProvider    // 生成服务提供商（Vidu/Mock）
    registry   port.EndpointRegistry     // 端点注册表
    repo       port.GenerationTaskRepository  // 任务仓储
    asset      port.MediaAssetStore      // 媒体资产存储（可选）
    quotaGate  port.QuotaStore           // 配额检查门（可选）
    usageRec   port.UsageRecorder        // 用量记录器（可选）
    submitSem  chan struct{}              // 并发节流信号量
    nonceStore port.CallbackNonceStore   // 回调防重放
    notifier   port.TaskNotifier         // 任务终态通知（可选）
    callbackURL string                   // 公网回调地址
}
```

#### 2.1.2 核心业务流程

**提交任务流程**：
```
1. 参数校验（端点注册表）
2. 配额检查（quotaGate）
3. 并发节流（submitSem）
4. 参数翻译（PromptRef → 上游参数格式）
5. 本地媒体内联（inlineLocalMedia）
6. 回调地址注入（injectCallbackURL）
7. 调用 provider.Submit()
8. 任务落库（repo.Save()）
9. 用量记录（usageRec）
```

**查询任务流程**：
```
1. 从仓储读取任务（repo.Get()）
2. 判断是否终态（IsTerminal）
3. 非终态 → 调用 provider.Query() 更新状态
4. 终态 → 转存产物（asset.Store）
5. 任务状态更新（repo.Save()）
6. 终态通知（notifyTerminal）
```

**回调处理流程**：
```
1. Nonce 判重（nonceStore.Seen）
2. 任务查找（repo.FindByProviderTaskID）
3. 状态更新（repo.Save()）
4. 终态通知（notifyTerminal）
```

#### 2.1.3 关键设计模式

**策略模式**：
- `provider`：不同服务商的生成策略（Vidu/Mock）
- `registry`：不同端点的请求组装策略

**装饰器模式**：
- `submitSem`：并发节流装饰器
- `quotaGate`：配额检查装饰器

**模板方法模式**：
- 提交/查询/回调的流程骨架固定
- 具体实现由策略对象提供

#### 2.1.4 可选依赖注入

```go
// 媒体资产存储（可选；nil=产物不转存）
func (uc *GenerationUseCase) SetAssetStore(s port.MediaAssetStore)

// 配额门（可选；generation 场景按次限额）
func (uc *GenerationUseCase) SetQuotaGate(g port.QuotaStore)

// 用量记录器（可选；generation 场景计量）
func (uc *GenerationUseCase) SetUsageRecorder(r port.UsageRecorder)

// 并发上限（P3 节流）
func (uc *GenerationUseCase) SetConcurrency(n int)

// Nonce 判重存储（可选；Redis 实现多实例安全）
func (uc *GenerationUseCase) SetNonceStore(s port.CallbackNonceStore)

// 任务终态通知（可选）
func (uc *GenerationUseCase) SetTaskNotifier(n port.TaskNotifier)

// 公网回调地址（可选）
func (uc *GenerationUseCase) SetCallbackURL(u string)
```

```go
type ContentUseCase struct {

    templateRepo       port.PromptTemplateRepository // 提示词模板（可选）
    quotaGate          port.QuotaStore               // 配额检查门（可选）
    storeRepo          port.StoreLocationRepository  // 门店档案（可选）
    brandRepo          port.BrandRepository          // 品牌仓储（可选）
    diagnoseUC         *DiagnoseUseCase              // GEO 诊断（可选）
    cache              port.CacheStore               // 写后缓存失效（可选）
}
```

#### 2.2.2 核心业务流程

**内容优化流程**：
```
1. 配额检查（quotaGate.Check "content-opt"）
2. 构建系统提示词（systemPrompt）
3. 注入门店 NAP 信号（storeRepo）
4. 注入知识库素材（knowledgeRetriever）
5. 注入 RAG 检索结果（ragRetriever）
6. 调用 LLM 生成优化内容（aiGen.Generate）
7. 规则评分（ruleScorer.Score）——优化前后对比
8. LLM 深度评分（scorer.Score）——落库用
9. 内容落库（contentRepo.Save）
10. 收录通知（urlSubmitter.Submit）
11. 缓存失效（invalidateAfterWrite）
```

**内容原创生成流程**：
```
1. 配额检查（quotaGate.Check "content-gen"）
2. 构建系统提示词（systemPrompt）
3. 注入品牌信息（brandRepo）
4. 注入门店 NAP 信号（storeRepo）
5. 注入知识库素材（knowledgeRetriever）
6. 注入 RAG 检索结果（ragRetriever）
7. 调用 LLM 生成原创内容（aiGen.Generate）
8. LLM 深度评分（scorer.Score）
9. 内容落库（contentRepo.Save）
10. 收录通知（urlSubmitter.Submit）
11. 缓存失效（invalidateAfterWrite）
```

#### 2.2.3 提示词管理策略

**分层提示词**：
```
格式指令（最高优先级）
  ↓
系统提示词（模板仓库 or 内置默认）
  ↓
引擎偏好指令（代码拼接，不可被模板绕过）
```

**模板管理**：
- `templateRepo`：可管理、可热更新的提示词模板
- 内置默认模板：模板仓库无记录时的兜底
- 格式模板：6 种格式（article/faq/list/comparison/guide/review）

#### 2.2.4 RAG 增强策略

**三层 RAG 增强**：
1. **知识库素材**（优先）：平台知识库按行业采集的带来源素材
2. **实时全网检索**（次优先）：RAG 检索器实时搜索全网内容
3. **品牌信息**（兜底）：品牌定位、卖点、竞品等基础信息

### 2.3 MonitorUseCase（监测用例）

**位置**：`internal/usecase/geo/monitor.go`

**业务定位**：GEO 监测的核心编排器

#### 2.3.1 核心职责

```go
type MonitorUseCase struct {
    brandRepo      port.BrandRepository
    keywordRepo    port.KeywordRepository
    resultRepo     port.MonitoringResultRepository
    probe          port.AIEngineProbe        // AI 引擎探测适配器
    quotaGate      port.QuotaStore           // 配额检查门（可选）
    selfBaseDomain string                    // 自营公开站域名（归因）
    storeRepo      port.StoreLocationRepository  // 门店档案（可选）
    questionGen    port.ProbeQuestionGenerator   // 问法池生成器（可选）
    cache          port.CacheStore           // 写后缓存失效（可选）
}
```

#### 2.3.2 核心业务流程

**单次监测流程**：
```
1. 加载品牌和关键词
2. 构建本地上下文（buildLocalContext）
3. 生成问法池（buildQuestions）
4. 配额检查（quotaGate.Check "monitor"）
5. 对每个引擎 × 多次采样：
   a. 选择问法（轮询问法池）
   b. 调用 probe.Probe()
   c. 统计提及/竞品/来源
6. 聚合 MonitoringResult
7. 结果落库（resultRepo.Save）
8. 缓存失效（invalidateAfterWrite）
```

#### 2.3.3 采样降噪设计

**多维度采样**：
- **问法维度**：LLM 生成 8 个真实问法，多引擎分片隔离
- **引擎维度**：每个关键词 × 每个配置的 AI 引擎
- **采样次数**：默认 5 次（可配置）

**归因生命线**：
- `selfBaseDomain`：注入后统计"AI 回答引用的来源里包含自营站内容的次数"
- 区分"提到品牌"和"引用我们的内容"

### 2.4 AccountUseCase（账号管理用例）

**位置**：`internal/usecase/account/account.go`

#### 2.4.1 核心职责

```go
type AccountUseCase struct {
    accountRepo port.AccountRepository
    qrLogin     port.QRLoginSession      // 扫码登录会话

    oauth       port.OAuthProvider       // 平台官方 OAuth（可选）
```

#### 2.4.2 核心业务流程

**扫码绑定流程**：
```

2. 轮询扫码状态（qrLogin.PollStatus）
3. 登录成功 → 获取 cookie
4. cookie 加密（vault.Encrypt）
5. 账号信息落库（accountRepo.Save）
```

**OAuth 授权绑定流程**：
```
1. 生成授权页地址（oauth.ConnectURL）
2. 用户扫码确认
3. 处理回调（HandleOAuthCallback）
   a. 验 state（stateCodec.VerifyState）
   b. code 换 token（oauth.ExchangeCode）
   c. 拉用户信息（oauth.UserInfo）
   d. token 加密（vault.Encrypt）
   e. 账号信息落库（accountRepo.Save）
```

## 3. 用例层设计模式

### 3.1 依赖注入（Dependency Injection）

**构造函数注入**：
```go
func NewGenerationUseCase(
    provider port.GenerationProvider,
    registry port.EndpointRegistry,
    repo port.GenerationTaskRepository,
) *GenerationUseCase
```

**Setter 注入（可选依赖）**：
```go
func (uc *GenerationUseCase) SetAssetStore(s port.MediaAssetStore)
func (uc *GenerationUseCase) SetQuotaGate(g port.QuotaStore)
```

### 3.2 策略模式（Strategy Pattern）

**不同来源策略**：
```go
type KeywordSource interface {
    Generate(ctx context.Context, input KeywordSourceInput) ([]string, error)
}

// 五种来源策略
brandSource   // 品牌信息+全网
textSource    // 用户文本
seedSource    // 种子词拓展
fileSource    // 文件内容
webSource     // 网络爬取
```

### 3.3 装饰器模式（Decorator Pattern）

**配额检查装饰器**：
```go
if uc.quotaGate != nil {
    if err := uc.quotaGate.Check(ctx, tenantID, "content-opt"); err != nil {
        return err
    }
}
```

**缓存失效装饰器**：
```go
if uc.cache != nil {
    _ = uc.cache.Del(ctx, HealthReportCacheKey(tenantID))
}
```

### 3.4 模板方法模式（Template Method）

**生成任务流程骨架**：
```
Submit() → 校验 → 节流 → 翻译 → 提交 → 落库 → 记录
Query()  → 读取 → 判断 → 更新 → 转存 → 通知
Callback() → 判重 → 查找 → 更新 → 通知
```

## 5. 用例层与领域层的边界

### 5.1 用例层职责

- 编排业务流程
- 协调多个领域对象
- 实现应用级业务规则（配额、缓存、通知）
- 定义输入/输出 DTO

### 5.2 领域层职责

- 定义业务实体和值对象
- 实现领域规则（验证、状态判断、计算）
- 定义 Port 接口

### 5.3 边界示例

**用例层调用领域层**：
```go
// 用例层：编排流程
func (uc *ContentUseCase) Optimize(ctx context.Context, input OptimizeInput) (OptimizeOutput, error) {
    // 1. 配额检查（应用级规则）
    if uc.quotaGate != nil {
        if err := uc.quotaGate.Check(ctx, input.TenantID, "content-opt"); err != nil {
            return err
        }
    }
    
    // 2. 构建提示词（调用领域层方法）
    prompt := uc.systemPrompt(ctx, entity.PromptKeyContentOptimize, defaultOptimizePrompt, input.TargetEngine, input.Format)
    
    // 3. 调用 LLM（通过 Port 接口）
    resp, err := uc.aiGen.Generate(ctx, port.AIRequest{Prompt: prompt})
    
    // 4. 评分（调用领域层服务）
    score, err := uc.ruleScorer.Score(ctx, resp.Content, input.Keywords)
    
    // 5. 落库（通过 Port 接口）
    content := entity.OptimizedContent{
        TenantID: input.TenantID,
        BrandID:  input.BrandID,
        Content:  resp.Content,
        Score:    score.Score,
    }
    err = uc.contentRepo.Save(ctx, content)
    
    return OptimizeOutput{Content: content}, nil
}
```

## 6. 总结

用例层的设计体现了整洁架构的核心思想：

1. **业务流程清晰**：每个用例的方法都是一个完整的业务流程
2. **依赖倒置**：通过 Port 接口依赖外部服务，不依赖具体实现
3. **可选依赖注入**：通过 Setter 方法注入可选依赖，保持向后兼容
4. **装饰器模式**：配额检查、缓存失效等横切关注点通过装饰器实现
5. **策略模式**：不同来源、不同引擎通过策略对象实现
6. **可测试性**：通过 Mock Port 接口，用例层可以独立测试
