# WebReaper 项目架构概览

> 基于整洁架构（Clean Architecture）设计的通用数据采集与内容生成平台

## 1. 项目定位

WebReaper 是一个**多功能 Web 平台**，核心能力包括：

- **GEO（生成式引擎优化）**：帮助商户在 AI 搜索引擎中提升品牌可见度
- **内容生成**：统一的任务协议支持视频/图片/音频/数字人等多种媒体生成
- **多平台发布**：支持知乎、小红书、抖音等平台的内容发布
- **数据采集**：多种爬虫策略（静态/动态/搜索/API）的数据抓取

## 2. 整洁架构四层结构

```
┌─────────────────────────────────────────────────────────────┐
│                    外部世界（HTTP/DB/LLM/第三方API）           │
├─────────────────────────────────────────────────────────────┤
│                      Adapter 层（适配器层）                    │
│  ┌─────────────┐ ┌─────────────┐ ┌─────────────┐            │
│  │   Handler    │ │ Repository  │ │   Provider   │           │
│  │  (HTTP API)  │ │  (数据库)   │ │  (Vidu/LLM)  │           │
│  └─────────────┘ └─────────────┘ └─────────────┘            │
├─────────────────────────────────────────────────────────────┤
│                      Usecase 层（用例层）                     │
│  ┌─────────────┐ ┌─────────────┐ ┌─────────────┐            │
│  │  Generation  │ │     GEO     │ │   Account    │           │
│  │  (内容生成)   │ │ (本地生活)   │ │  (账号发布)   │           │
│  └─────────────┘ └─────────────┘ └─────────────┘            │
├─────────────────────────────────────────────────────────────┤
│                      Domain 层（领域层）                      │
│  ┌─────────────────────────────────────────────────────┐    │
│  │  Entity（实体）  +  ValueObject（值对象）  +  Port（接口）  │
│  └─────────────────────────────────────────────────────┘    │
├─────────────────────────────────────────────────────────────┤
│                      Config 层（配置层）                      │
│  ┌─────────────────────────────────────────────────────┐    │
│  │              环境变量 + 运行时配置                      │    │
│  └─────────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────────┘
```

## 3. 依赖规则（核心原则）

**依赖方向：外层 → 内层（单向依赖）**

```
Adapter → Usecase → Domain
   ↓         ↓        ↓
 具体实现   业务逻辑   纯领域模型
```

- **Domain 层**：零依赖，纯 Go struct + 领域规则
- **Usecase 层**：只依赖 Domain 层的实体和 Port 接口
- **Adapter 层**：实现 Port 接口，依赖外部框架（GORM/Gin/Redis 等）

## 5. 核心业务模块

### 5.1 GEO（生成式引擎优化）模块

**业务目标**：帮助商户在 AI 搜索引擎（豆包/Kimi/ChatGPT）中被提及和引用

**核心流程**：
```
品牌配置 → 关键词管理 → AI 引擎监测 → 内容优化 → 多平台发布 → 效果追踪
```

**关键实体**：
- `Brand`：品牌资产（聚合根）
- `Keyword`：监测关键词
- `MonitoringResult`：AI 引擎探测结果
- `OptimizedContent`：优化后的内容
- `StoreLocation`：门店位置（本地生活）

### 5.2 内容生成模块

**业务目标**：统一的任务协议支持多种媒体类型生成

**支持的生成类型**：
- 视频生成（文生视频/图生视频/首尾帧视频/参考生视频/智能多帧）
- 图片生成
- 音频生成（文生音频/音效/语音合成/声音克隆）
- 数字人（数字人口播/数字分身）

**核心设计**：
- 统一任务状态机：`created → queueing → processing → success/failed/cancelled`
- 双通道结果获取：回调（秒级推送）+ 轮询（20s 兜底）
- 策略模式：不同端点/模型通过 `EndpointAdapter` 抽象

### 5.3 多平台发布模块

**业务目标**：支持内容一键发布到多个平台

**支持平台**：
- 知乎（全自动/半自动）
- 小红书（全自动/半自动）
- 抖音（官方 OAuth + RPA）

**核心设计**：
- 通道注册表（工厂模式）
- 传输层抽象（Link/RPA 双通道）
- 账号池管理（最优账号选择）

### 5.4 经济系统模块

**业务目标**：SaaS 级的套餐/订阅/计费管理

**核心功能**：
- 套餐管理（free/basic/pro/enterprise）
- 订阅管理（月付/年付）
- 配额检查（按场景限额）
- 用量计量（token 级成本追踪）
- 支付集成（ZPay 真实收款）

## 6. 关键设计模式应用

### 6.1 策略模式（Strategy Pattern）

**应用场景**：
- `GenerationProvider`：不同服务商（Vidu/Mock）的生成策略
- `EndpointAdapter`：不同端点的请求组装策略
- `GEOScorer`：不同评分器（规则评分/LLM 评分）
- `URLSubmitter`：不同收录渠道（IndexNow/Bing/百度）

### 6.2 工厂模式（Factory Pattern）

**应用场景**：
- `ChannelRegistry`：发布通道注册表
- `EndpointRegistry`：生成端点注册表
- `ToolRegistry`：爬虫工具注册表

### 6.3 装饰器模式（Decorator Pattern）

**应用场景**：
- `RateLimitCrawler`：爬虫限流装饰器
- `LoggingSubmitter`：收录提交日志装饰器
- `CachedEmbedder`：向量嵌入缓存装饰器

### 6.4 适配器模式（Adapter Pattern）

**应用场景**：
- `GormBrandRepository`：GORM 适配 BrandRepository 接口
- `ViduProvider`：Vidu API 适配 GenerationProvider 接口
- `AmapGeoCoder`：高德 API 适配 GeoLocator 接口

### 6.5 观察者模式（Observer Pattern）

**应用场景**：
- `TaskNotifier`：任务终态通知（异步唤醒）
- `CacheInvalidator`：写后缓存失效（健康报告/行业榜）

## 7. 技术栈

### 后端
- **语言**：Go 1.21+
- **Web 框架**：Gin
- **ORM**：GORM
- **数据库**：MySQL 8.0
- **缓存**：Redis 7.0
- **向量数据库**：Milvus / MySQL 向量扩展
- **消息队列**：无（使用定时任务调度器）

### 前端
- **框架**：React 18 + TypeScript
- **UI 库**：Ant Design
- **状态管理**：React Query
- **构建工具**：Vite

### AI/LLM
- **LLM 服务商**：OpenAI / 豆包 / Kimi / 小米 MiMo
- **向量嵌入**：OpenAI Embedding / 本地模型
- **语音识别**：OpenAI Whisper 兼容 API

### 第三方服务
- **视频生成**：Vidu API
- **地图服务**：高德地图 API
- **支付网关**：ZPay
- **内容发布**：知乎/小红书/抖音 API

## 8. 架构优势

### 8.1 可测试性
- 领域层零依赖，纯函数可单测
- Port 接口支持 Mock 注入
- 用例层不依赖框架，易于集成测试

### 8.2 可扩展性
- 新增生成端点 = 实现 EndpointAdapter + 注册
- 新增发布平台 = 实现 Channel + 注册
- 新增 AI 引擎 = 实现 GEOProbe + 注册

### 8.3 可维护性
- 业务逻辑集中在 Usecase 层
- 技术细节隔离在 Adapter 层
- 领域规则内聚在 Domain 层

### 8.4 灵活部署
- 无 DB 时自动降级为 Mock 实现
- 无 Redis 时自动降级为单机模式
- 无 LLM 时自动禁用 AI 相关功能
