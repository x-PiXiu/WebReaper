## 阶段 1：生产基础设施 🔴 进行中

**目标**：补齐生产环境必需的基础设施。**验证假设：系统能否稳定运行在生产环境。**

| 任务 | 优先级 | 状态 |
|---|---|---|
| 统一日志抽象（port.Logger + zap） | P0 | ⬜ |
| 接入 MiniMax LLM（trpc-agent-go） | P0 | ✅ |
| 接入 MySQL（GORM） | P0 | ✅ |
| 统一配置加载（config.Load） | P0 | ✅ |
| HTTP Controller（Gin） | P0 | ✅ |
| colly 通用爬虫 | P0 | ✅ |
| 认证鉴权中间件（JWT） | P1 | ⬜ |
| 数据库迁移工具（goose/atlas） | P1 | ⬜ |
| 监控链路追踪（OpenTelemetry） | P1 | ⬜ |

**本阶段明确不做**：
- ❌ 前端 SPA（等后端 API 稳定）
- ❌ 向量库（等知识点数据量起来）
- ❌ Redis 队列（内存队列够用）

**验收标准**：
- [ ] 日志可结构化输出，支持级别调整
- [ ] API 需认证才能访问
- [ ] 表结构变更有版本化迁移
- [ ] LLM 调用有 trace 链路

## 阶段 2：异步任务与真实推送 🟡 近期

**目标**：让耗时操作异步化，真实推送平台接线。**验证假设：系统能否处理真实业务流量。**

| 任务 | 说明 |
|---|---|
| TaskQueue 消费 worker | 采集/AI 投递队列异步执行 |
| Task 用例（状态机消费） | 用 Task 状态机驱动异步执行 |
| HTTPPlatform 真实接线 | main 注册真实推送平台 |
| 推送重试机制 | 失败自动重试 N 次 |

**本阶段明确不做**：
- ❌ Redis/Kafka（进程内 channel 够用）
- ❌ 分布式任务调度

## 阶段 3：前端 SPA 与多平台联调 🟢 中期

**目标**：提供可视化操作界面，多平台推送真实联调。**验证假设：用户是否真的会用。**

## 阶段 4：向量检索与商业化 ⚪ 远期

**目标**：知识库语义检索，探索商业化。**验证假设：产品是否有付费意愿。**

| 任务 | 说明 |
|---|---|
| 智谱 Embedding 接入 | 文本向量化 |
| Milvus 向量库接入 | 语义检索 |
| 知识点去重（向量相似度） | 比指纹更智能的去重 |
| 用户系统 + 配额 | 商业化基础 |

## 阶段决策原则

### 推迟决策清单（越晚决定越好）
- 向量库选型（Milvus vs pgvector）→ 等数据量起来再定
- 任务队列选型（Redis vs Kafka）→ 等并发量起来再定
- 前端框架（Vue vs React）→ 等用户需求明确再定

### 必须早做的决策
- 依赖方向（已经定好，不可违背）
- 配置系统（已统一）
- 错误码体系（已建立）
