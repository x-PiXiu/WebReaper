## 阶段 2：异步任务与真实推送 ✅ 基本完成（架构转向）

**目标**：让耗时操作异步化，真实推送平台接线。

> ⚠️ **架构转向说明**：原计划为「采集/生成/总结」各投递异步任务。
> 实际转向「单一 Agent + N 工具」模型——采集/加工由 Agent 通过工具调用完成，
> 异步任务子系统现服务于 Agent 异步执行（`agent_run`）。

| 任务 | 状态 | 说明 |
|---|---|---|
| TaskQueue 消费 worker | ✅ | Enqueue/Worker/Dispatch/HandlerRegistry 已实现，main 已启动 |
| Task 用例（状态机消费） | ✅ | Task 状态机驱动异步执行 |
| HTTPPlatform 真实接线 | ✅ | publish.PublishUseCase 真实 HTTP，raw/mapping 双模式 |
| 推送重试机制 | ⬜ | 待实现（worker 已有指数退避，推送层重试待补） |

**本阶段明确不做**：
- ❌ Redis/Kafka（进程内 channel 够用）
- ❌ 分布式任务调度

## 阶段决策原则

### 推迟决策清单（越晚决定越好）
- 向量库选型（Milvus vs pgvector）→ 等数据量起来再定
- 任务队列选型（Redis vs Kafka）→ 等并发量起来再定
- 前端框架（Vue vs React）→ 等用户需求明确再定

### 必须早做的决策
- 依赖方向（已经定好，不可违背）
- 配置系统（已统一）
- 错误码体系（已建立）
