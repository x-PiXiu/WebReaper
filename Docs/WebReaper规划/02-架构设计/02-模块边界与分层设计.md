# 模块边界与分层设计

> 📌 拆分原则：哪里变化速率不同，就在哪里画线。本文档定义 WebReaper 的限界上下文与各模块在整洁架构中的落点。

## 一、业务边界拆分（6 大限界上下文）

按"变化速率差异"识别出 6 个独立的限界上下文：

| # | 限界上下文 | 核心职责 | 变化速率 | 主导模式 |
|---|---|---|---|---|
| ① | **采集** | 从外部数据源抓取招聘需求 | 高（数据源会新增）| 策略+注册表 |
| ② | **AI 加工** | 招聘需求→面试题、文本→知识点 | 高（Prompt/模型会变）| 策略 |
| ③ | **推送** | 把成果分发到外部平台 | 高（平台会新增）| 策略+注册表 |
| ④ | **持久化** | 实体存取与去重 | 中（存储可换）| 仓储接口 |
| ⑤ | **任务调度** | 异步执行耗时操作 | 中（队列可换）| 队列接口 |
| ⑥ | **Web 接入** | HTTP API 对外暴露 | 中（框架可换）| 谦卑对象 |

**关键决策**：①②③ 三个上下文变化最快，因此各自用"接口 + 注册表"隔离，新增类型不改用例。

## 二、各模块在四层中的分层落点

```
internal/
├── domain/                          ← ①②③④⑤ 共享的领域模型
│   ├── entity/        JobPost/Question/Knowledge/Source/Task/Publishable
│   └── valueobject/   Fingerprint/TaskStatus/PublishResult
│
├── usecase/                         ← 用例编排（业务流程）
│   ├── port/          ①~⑤ 的接口声明（依赖倒置边界）
│   ├── collect/       ① 采集用例
│   ├── generate/      ② 生成面试题用例
│   ├── summarize/     ② 总结知识点用例
│   └── publish/       ③ 推送用例
│
├── adapter/                         ← 接口适配器 + 框架驱动
│   ├── spider/        ① colly 实现 Spider
│   ├── ai/            ② trpc-agent-go 实现 AIGenerator
│   ├── publish/       ③ HTTP 实现 Platform
│   ├── repository/    ④ GORM 实现 *Repository
│   ├── handler/       ⑥ Gin 实现 HTTP Controller
│   └── mock/          全部接口的降级实现
│
├── config/                          ← 基础设施：配置加载
└── pkg/                             ← 基础设施：错误码
```

## 三、模块间通信原则

### 原则 1：用例之间不直接调用

```
❌ 错误：GenerateQuestionsUseCase 直接调 CollectJobPostsUseCase
✅ 正确：通过共享的 Repository 间接协作（采集写入 → 生成读取）
```

4 个用例通过 `port.*Repository` 共享数据，而非互相调用。这让每个用例可独立测试、独立演进。

### 原则 2：用例 → 外部依赖 只通过 port 接口

```
用例层                         适配器层
GenerateQuestionsUseCase  →   port.AIGenerator（接口）
                                    ↑ 实现
                              adapter/ai/TrpcAgentGenerator
```

用例永远不知道 AIGenerator 背后是 trpc-agent-go 还是 mock。

### 原则 3：适配器之间不横向依赖

```
❌ 错误：adapter/spider 调 adapter/repository
✅ 正确：spider 只实现 port.Spider，由用例编排 spider + repository
```

适配器层各模块互相独立，编排逻辑统一在用例层。

## 四、扩展点设计（开闭原则落地）

### 新增数据源类型

```
1. 在 adapter/spider/ 下新建实现，实现 port.Spider 接口
2. 在 main.go 调 spiderRegistry.Register(NewXxxSpider())
3. 用例层、domain 层、其他适配器：零修改
```

### 新增推送平台

```
1. 在 adapter/publish/ 下新建实现，实现 port.Platform 接口
2. 在 main.go 调 platformRegistry.Register(NewXxxPlatform())
3. 用例层零修改
```

### 更换 LLM 厂商

```
1. 改 configs/.env 的 LLM_BASE_URL / LLM_MODEL / LLM_API_KEY
2. 代码零修改（trpc-agent-go 通过 openai.WithBaseURL 支持任意兼容端点）
```

### 更换数据库

```
1. 新建 adapter/repository 的 PO + 仓储实现（用新驱动）
2. main.go 注入新实现
3. 用例层零修改
```

## 五、依赖关系图

```
                    ┌──────────┐
                    │  domain  │ ← 零依赖（最稳定）
                    └────┬─────┘
                         │ import
                    ┌────▼─────┐
                    │ usecase  │ ← 只依赖 domain + port
                    │  +port   │
                    └────┬─────┘
                         │ 实现 port 接口
          ┌──────────────┼──────────────┐
          │              │              │
     ┌────▼────┐   ┌────▼────┐   ┌────▼────┐
     │ spider  │   │   ai    │   │  repo   │  ← 适配器层
     │ (colly) │   │ (trpc)  │   │ (gorm)  │     各自依赖框架
     └─────────┘   └─────────┘   └─────────┘
          │              │              │
          └──────────────┼──────────────┘
                         │ 装配注入
                    ┌────▼─────┐
                    │   main   │ ← 装配工（最外层）
                    └──────────┘
```

**铁律**：箭头永远向内。外层知道内层，内层不知道外层。
