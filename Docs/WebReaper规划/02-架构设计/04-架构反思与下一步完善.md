## 一、当前架构健康度

**骨架优秀，血肉已基本补齐。** 整洁架构的"宪法"（依赖向内）执行得很好；早期文档列出的 P0/P1 缺口（日志、认证、迁移、监控、推送、爬虫错误）大多已落地，剩余少量待完善项。

## 二、重大架构转向（必须记录）

> **ADR-006：单一 Agent + N 工具模型取代 4 独立用例**
>
> 项目早期设计了「采集 / 生成面试题 / 总结知识点」三类独立用例 + 异步任务类型。
> 实际演进中整体转向「单一 Agent + N 工具」模型——采集、加工、推送都由 Agent 通过
> 工具调用（tool calling）自主完成。原有 3 个独立用例被吸收：
> - 采集 → `static_crawler` / `api_crawler` / `dynamic_crawler` / `search_crawler` 等工具
> - 加工 → LLM Agent 自主调用工具 + `save_data_item` 工具落库
> - 推送 → `publish` / `list_external_systems` 工具
>
> **决策**：保留异步任务子系统（仍服务于 Agent 异步执行），但删除 3 个无人实现的死任务类型
> （`collect_job_posts` / `generate_questions` / `summarize_knowledge`），仅保留 `agent_run`。
> 这是典型「新架构取代旧架构、旧代码未拆」反模式的修正。

## 五、架构演进原则（不变的铁律）

无论怎么演进，以下 4 条铁律不能违背：

1. **依赖永远向内**：任何新功能，外部依赖必须通过 port 接口隔离，domain/usecase 零框架 import。
   （可观测性新增的 `port.Tracer` 即是此原则的体现——用例不直接 import OTel）
2. **双实现降级保留**：新增真实适配器时，mock 实现保留，保证零配置可启动；降级必须**诚实**（如 Milvus 改动）
3. **扩展用加法不用改法**：新增类型走"实现接口 + 注册"，不改已有用例
4. **测试先行**：每个新适配器/用例都要有对应测试，用例测试用 mock 注入

## 六、一句话总结

> 架构骨架已为所有后续功能预留了正确的扩展点，血肉也已基本补齐。本轮工作的重点是
> **诚实化**（Milvus 不再装成功）、**清理僵尸代码**（裁剪被 Agent 取代的死任务类型）、
> **补齐可观测性**（OTel 埋点 + port.Tracer 抽象），让架构与代码回到一致状态。
> 整洁架构的价值持续验证：**前期投入的分层成本，在后续迭代中以"零修改"方式持续回报**。
