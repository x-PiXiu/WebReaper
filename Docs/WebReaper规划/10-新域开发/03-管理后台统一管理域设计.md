## 二、管理页设计（新增两个）

### 2.1 品牌统一管理 `/admin/brands`

**数据来源**：`BrandRepository.ListAll()`（admin 旁路多租户——admin 看全局，这是"绝对控制"的落点）

```
GET    /api/v1/admin/brands              # 全平台品牌列表（含所属商户）
PUT    /api/v1/admin/brands/:id          # 编辑品牌（定位/卖点/竞品）
DELETE /api/v1/admin/brands/:id          # 删除品牌（级联删除关键词/内容——确认弹窗）
POST   /api/v1/admin/brands/:id/freeze   # 冻结/解冻（商户端不可见）
```

**前端**：品牌表格（商户名/品牌名/定位/关键词数/内容数/状态）+ 详情抽屉 + 编辑表单。

### 2.2 内容统一管理 `/admin/contents`

```
GET    /api/v1/admin/contents            # 全平台优化内容列表（商户/品牌/关键词/状态/评分）
POST   /api/v1/admin/contents/:id/status # 上下架（draft ↔ published 强制流转）
DELETE /api/v1/admin/contents/:id        # 删除内容
GET    /api/v1/admin/contents/:id/preview# 公开页预览（复用 public handler 渲染）
```

**前端**：内容表格（评分/状态筛选）+ 预览弹窗（iframe 公开页）+ 强制下架。

### 2.3 仓储接口扩展（port）

```go
// BrandRepository 增加 admin 旁路方法：
ListAll(ctx context.Context) ([]entity.Brand, error)          // 全平台（admin）
Update(ctx context.Context, b entity.Brand) error             // 编辑
Freeze(ctx context.Context, id string, frozen bool) error     // 冻结

// OptimizedContentRepository 增加：
ListAll(ctx context.Context, status string, limit int) ([]entity.OptimizedContent, error)
```

> 设计说明：admin 旁路方法显式命名（ListAll），与租户方法（ListByTenant）并存——
> 不破坏多租户隔离；admin 能力由"仓储方法 + admin 路由角色守卫"双重控制。

## 三、绝对控制清单（admin 权限边界）

| 控制项 | 实现 |
|---|---|

| 内容全域管理 | 新增 `ListAll/status 强制流转/删除/预览` |
| 收录控制 | ✅ Indexing 三件套（配置/日志/补提交） |
| 工具开关 | ✅ `/tools/:name/toggle` |
| 系统配置 | ✅ crawl-config / agent / llm / tavily |
