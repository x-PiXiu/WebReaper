# 数据采集差异化战略

> 📌 WebReaper 的竞争力不在爬虫本身，而在"采集→AI加工→多平台分发"的闭环架构。

## 一、战场分析：纯爬虫工具的三大局限

| 传统爬虫工具的局限 | WebReaper 如何突破 |
|---|---|
| 只采集不加工，输出原始 HTML/JSON | 采集后 AI 加工（面试题/知识点），输出即用内容 |
| 单一数据源，配置僵硬 | 策略+注册表，任意网站配置化接入，零改代码 |
| 采集完就结束，需人工搬运分发 | 自动推送多平台，闭环到发布 |

## 二、核心论点

> **WebReaper 不是爬虫工具，是"数据→知识→分发"的自动化工厂。**

爬虫只是流水线的第一道工序。真正的价值在 AI 加工（让原始数据变成可用内容）和多平台分发（让内容自动抵达受众）。

```
传统爬虫：  采集 ──→ 结束（人工处理）
                    ❌ 价值断点

WebReaper： 采集 ──→ AI加工 ──→ 多平台推送
            ✅ 全链路自动化闭环
```

## 三、三个护城河（已存在于架构中）

| 护城河 | 架构体现 | 竞争对手难以复制的原因 |
|---|---|---|
| **闭环架构** | 4 用例端到端打通 | 单点工具易做，闭环系统难做（需完整设计）|
| **可扩展性** | 策略+注册表，加平台不改代码 | 耦合的系统改一处动全身，无法快速扩展 |
| **可替换性** | 双实现降级，框架可换 | 绑定单一框架的系统死在框架升级时 |

## 四、与 AgentCore 的协同定位

```
WebReaper（数据侧）                AgentCore（应用侧）
┌────────────────────┐            ┌────────────────────┐
│ 采集 → AI加工      │ ──推送──→  │ 内容接入网关        │
│ （生产内容）        │            │ → 面试题/知识点/面经 │
│                    │            │ → 模拟面试/深度解析  │
│ 定位：内容生产工厂  │            │ 定位：内容消费平台   │
└────────────────────┘            └────────────────────┘
```

- WebReaper 负责"把世界的数据变成结构化内容"
- AgentCore 负责"把结构化内容变成学习体验"
- 两者通过推送 API 解耦，各自独立演进

## 五、三个不要做

| 不要做 | 理由 |
|---|---|
| ❌ 不做目标网站专属爬虫 | 绑定单一网站风险高（反爬/ToS/网站改版），通用配置化爬虫更稳健 |
| ❌ 不做内容存储与展示 | 那是 AgentCore 的职责，WebReaper 只生产不消费 |
| ❌ 不做复杂的工作流编排 | 当前 4 个用例的线性编排足够，不上 graph workflow（过度设计）|

## 六、优先级矩阵

| 方向 | 价值 | 难度 | 优先级 |
|---|---|---|---|
| 真实推送平台接线 | 高 | 低 | 🔴 立即 |
| 异步任务（不阻塞采集）| 高 | 中 | 🔴 近期 |
| 更多数据源接入（掘金/知乎）| 中 | 低 | 🟡 中期 |
| 向量化去重（智能去重）| 中 | 高 | 🟢 远期 |
| 实时增量采集 | 低 | 高 | ⚪ 暂缓 |

## 七、总结

WebReaper 的战略定位：**做数据到知识的自动化转换器，不做又一个爬虫工具**。

架构已经支撑了这个定位——采集是入口，AI 加工是核心，多平台推送是出口。三段闭环，每段都可独立扩展和替换。这是整洁架构带来的战略灵活性：**因为解耦，所以可以专注做好每一段而不被其他段绑架**。
