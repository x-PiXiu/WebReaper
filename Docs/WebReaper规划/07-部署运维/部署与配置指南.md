# 部署与配置指南

> 📌 WebReaper 的部署与配置方式，含降级策略和运行验证。

## 一、环境要求

| 组件 | 版本 | 必需？ |
|---|---|---|
| Go | 1.26+ | ✅ 编译 |
| MySQL | 8.0+ | 🟡 可选（无则降级 mock）|
| MiniMax API Key | — | 🟡 可选（无则降级 mock）|

## 二、配置文件

配置通过 `configs/.env` 加载（参考 `configs/.env.example` 模板）。

### 配置项一览

| 配置块 | 关键变量 | 必需？ | 缺失时降级 |
|---|---|---|---|
| Server | `SERVER_PORT` (默认 8082) | 🟡 | 用默认值 |
| **MySQL** | `DB_HOST/PORT/USER/PASSWORD/NAME` | 🟡 | 降级内存 mock 仓储 |
| **LLM** | `LLM_API_KEY/BASE_URL/MODEL` | 🟡 | 降级 mock AI（规则生成）|
| Embedding | `EMBEDDING_*` | ⬜ | 预留未用 |
| Milvus | `MILVUS_HOST/PORT` | ⬜ | 预留未用 |
| Redis | `REDIS_*` | ⬜ | 预留未用 |
| JWT | `JWT_SECRET/EXPIRATION` | ⬜ | 预留未用 |

### 配置加载优先级

```
环境变量（最高） > configs/.env 文件 > 代码默认值
```

## 三、运行方式

### 方式 1：零配置启动（降级模式）

```bash
go run ./cmd/server
```
- 不需要 MySQL / LLM API Key
- 仓储用内存 mock，AI 用规则生成
- 适合：快速体验、本地开发、CI 测试

### 方式 2：完整配置启动（真实模式）

```bash
# 1. 复制配置模板
cp configs/.env.example configs/.env

# 2. 填入真实配置（MySQL + MiniMax）
# 编辑 configs/.env

# 3. 启动
go run ./cmd/server
```

启动成功标志：
```
[仓储] 连接 MySQL root@localhost:3306/agentcore...
[仓储] MySQL 连接成功，数据将持久化到 agentcore
[AI] 初始化 trpc-agent-go [minimax] MiniMax-M2.5...
[AI] trpc-agent-go 就绪，厂商=minimax 模型=MiniMax-M2.5
WebReaper 服务已启动，监听 :8082
```

### 方式 3：编译后运行

```bash
go build -o bin/webreaper ./cmd/server
./bin/webreaper
```

## 四、API 验证

服务启动后，用 curl 验证：

```bash
# 健康检查
curl http://localhost:8082/healthz
# → {"status":"ok"}

# 采集（mock 爬虫）
curl -X POST http://localhost:8082/api/v1/collect \
  -H "Content-Type: application/json" \
  -d '{"source_name":"test","source_type":"boss"}'

# 生成面试题
curl -X POST http://localhost:8082/api/v1/questions/generate \
  -H "Content-Type: application/json" \
  -d '{"job_post_id":"mock-post-1"}'

# 总结知识点（真实模式会调 MiniMax）
curl -X POST http://localhost:8082/api/v1/knowledge/summarize \
  -H "Content-Type: application/json" \
  -d '{"raw_text":"Go 并发基于 goroutine 和 channel"}'
```

## 六、降级策略详解

降级是 WebReaper 的核心设计——**配置缺失不报错，自动回退到可用实现**：

| 配置缺失 | 降级为 | 影响 |
|---|---|---|
| `DB_PASSWORD` 空 | 内存 mock 仓储 | 数据不持久化，重启丢失 |
| `LLM_API_KEY` 空 | mock AI（规则生成）| 面试题/知识点质量低（示例内容）|

两种实现满足同一 port 接口，**用例层零感知**。这是依赖倒置的直接收益。

## 七、安全注意事项

| 事项 | 措施 |
|---|---|
| .env 含密钥 | ✅ 已 .gitignore 保护 |

## 八、常见问题

**Q: 启动报 `bind: address already in use`？**
A: 端口 8082 被占用。改 `configs/.env` 的 `SERVER_PORT`，或杀掉占用进程。

**Q: MySQL 连接失败？**
A: WSL 环境下 MySQL 绑定 IPv6，`DB_HOST=localhost` 让驱动自动解析。确认 MySQL 服务运行中。

**Q: MiniMax 调用超时？**
A: 检查 `LLM_BASE_URL` 是否正确（`https://api.minimaxi.com/v1`），网络是否可达。
