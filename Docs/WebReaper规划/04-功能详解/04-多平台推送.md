# 多平台推送

> 优先级：🟡 P1 | 阶段：0 接口完成 / 2 真实接线 | 模式：策略+注册表

## 一、需求来源

> "作为外部系统将数据推送到其他平台...需要设计为接口，便于后续添加其他平台" — 用户原话

## 二、现状

- **接口完整**：Platform 接口 + PlatformRegistry + PublishContent 用例 全部就位
- **HTTPPlatform 真实实现**：`adapter/publish/`，net/http + X-API-Key，代码完整可用
- **未接线**：main.go 当前只注册 MockPlatform，真实平台被注释（待填真实 URL/Key）

## 三、实体设计

```go
// domain/entity/publishable.go —— 推送内容归一抽象
type ContentType string // "article" | "question"
type Publishable interface {
    PublishIdentity() (id string, ctype ContentType)
}
// Knowledge → ContentTypeArticle
// InterviewQuestion → ContentTypeQuestion

// domain/valueobject/publish_result.go
type PublishResult struct {
    Success    bool
    Platform   string
    ExternalID string  // 外部平台返回的资源 ID
    Error      string
    At         time.Time
}
```

## 四、设计：策略+注册表（与采集同构）

```go
// usecase/port/platform.go
type Platform interface {
    Name() string
    PublishArticle(ctx, Knowledge) (PublishResult, error)
    PublishQuestion(ctx, InterviewQuestion) (PublishResult, error)
}
type PlatformRegistry struct { ... } // 与 SpiderRegistry 完全同构
```

**真实实现**：`adapter/publish/HTTPPlatform`（通用 HTTP + X-API-Key，适配 OpenAI 风格的 `/ingest/article|question` 端点）
**降级实现**：`adapter/mock/MockPlatform`（假成功）

## 五、用例编排流程

```
POST /api/v1/publish {content_type, content_id, platform}
    │
    ▼
PublishContentUseCase.Execute
    │
    ├─ 1. 校验参数
    ├─ 2. PlatformRegistry.Lookup(platform) 分派平台
    ├─ 3. ExistsSuccess() 去重检查（已推送过则拦截）
    ├─ 4. 按 ContentType 分流：
    │      article  → KnowledgeRepo.FindByID → Platform.PublishArticle
    │      question → QuestionRepo.FindByID  → Platform.PublishQuestion
    ├─ 5. PublishRecordRepository.Save() 记录结果（成功失败都留痕）
    └─ 6. 返回 PublishResult
    │
    ▼
返回 {success, external_id, platform}
```

## 六、推送目标：AgentCore 内容接入网关

WebReaper 的主要推送目标是姊妹项目 AgentCore：

```
WebReaper                         AgentCore
POST /api/v1/publish    ──HTTP──→  POST /api/v1/ingest/article
  {content_type:article,           {title, content, category, tags}
   content_id, platform}
                                  POST /api/v1/ingest/question
                                   {title, stem, answer_good, difficulty...}
```

HTTPPlatform 实现已适配 AgentCore 的 `/ingest/*` 端点契约。

## 七、整洁架构检验

| 检验项 | 结果 |
|---|---|
| 用例是否依赖 net/http？ | ✅ 否，只依赖 port.Platform |
| 新增平台是否改用例？ | ✅ 否，实现接口+注册 |
| 推送去重是否独立于平台？ | ✅ 是，在用例层用 ExistsSuccess |
| 失败是否留痕？ | ✅ 是，PublishRecord 无论成败都记录 |
