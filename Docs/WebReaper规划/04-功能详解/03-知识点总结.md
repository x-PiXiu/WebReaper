# 知识点总结

> 优先级：🔴 P0 | 阶段：0（已完成）| 模式：策略（复用 AIGenerator）

## 一、需求来源

> "爬取网络中的数据然后清洗总结为知识点等" — 用户原话

## 二、现状

已完成。复用面试题生成的 AIGenerator 接口（同为 `adapter/ai/` 实现），无新增接口。

## 三、实体设计

```go
// domain/entity/knowledge.go
type Knowledge struct {
    ID        string
    Title     string
    Content   string   // 清洗后正文
    Summary   string   // 一句话摘要
    Tags      []string
    SourceURL string
    VectorRef string   // 向量库引用 ID（预留，当前为空）
    CreatedAt time.Time
}

func (k Knowledge) IsValid() bool { return k.Title != "" && k.Content != "" }
func (k Knowledge) IsVectorized() bool { return k.VectorRef != "" }
// 实现 Publishable（可推送，类型=article）
func (k Knowledge) PublishIdentity() (string, ContentType) { return k.ID, ContentTypeArticle }
```

## 四、设计：复用 AIGenerator 接口

```go
// 同一个 AIGenerator 接口，增加 SummarizeKnowledge 方法
type AIGenerator interface {
    GenerateQuestions(ctx, JobPost) ([]InterviewQuestion, error)
    SummarizeKnowledge(ctx, rawText string, sourceURL string) (Knowledge, error) // ← 本用例用
}
```

**设计亮点**：不新增接口，AI 能力归一个 AIGenerator 统一管理。Prompt 同样在 `adapter/ai/prompt.go`。

## 五、用例编排流程

```
POST /api/v1/knowledge/summarize {raw_text, source_url}
    │
    ▼
SummarizeKnowledgeUseCase.Execute
    │
    ├─ 1. 校验 raw_text 非空
    ├─ 2. AIGenerator.SummarizeKnowledge() 调 AI 总结
    ├─ 3. 校验 Knowledge.IsValid()（过滤 AI 空输出）
    └─ 4. KnowledgeRepository.Save() 入库
    │
    ▼
返回 Knowledge（含自动生成的 ID）
```

## 六、与向量库的关系（预留）

当前 Knowledge 只存结构化文本。`VectorRef` 字段为后续向量化预留：
- 阶段 4：接入 Embedding 模型（智谱）+ Milvus，对 Content 向量化
- `VectorRef` 存 Milvus 的 primary key，关联回 Knowledge
- 支持语义检索（"Go 并发" → 找到相关知识点，即使标题不含"并发"）

当前不做向量化的理由（YAGNI）：知识点数据量未起来，向量检索是过度设计。
