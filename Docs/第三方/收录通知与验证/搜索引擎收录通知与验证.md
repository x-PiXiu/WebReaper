# 搜索引擎收录通知与验证——技术设计文档

> **范围**：内容发布后通知搜索引擎收录（IndexNow / 百度推送）+ 收录状态验证（Bing Webmaster API）
> **架构定位**：adapter 层（收录协议实现）+ usecase 层（编排触发）+ scheduledtask（定时验证）
> **整洁架构**：用例层只依赖 `port.URLSubmitter` + `port.IndexStatusChecker` 接口，协议细节封在 adapter

---

## 一、整体架构：收录闭环

```
内容发布为 published（ContentUseCase.SetStatus / AdminSetStatus）
      │
      ├─ ① 写入 IndexStatus = "pending"（初始状态：已提交未收录）
      │
      └─ ② 触发收录通知（urlSubmitter.SubmitURLs）
              │
              ├─ IndexNow（通知 Bing / Yandex / Naver）
              │     POST https://api.indexnow.org/indexnow
              │
              └─ 百度主动推送（通知百度爬虫）
                    POST http://data.zz.baidu.com/urls?site=xxx&token=xxx
                        │
                        │  ...数小时~数天后搜索引擎爬取并收录...
                        │
                        ↓
      ③ 定时验证任务（IndexCheckTask，每 24h）
              │
              ├─ 查所有 status=published 且 IndexStatus≠indexed 的内容
              │
              ├─ 调 Bing Webmaster API 逐条查询收录状态
              │     GET https://ssl.bing.com/webmaster/api.svc/json/GetUrlSubmissionStatus
              │
              └─ 回写 IndexStatus：
                    indexed（已收录）→ 记录 IndexedAt 时间
                    pending（未收录）→ 保持等待
                    error（查询失败）→ 不改写，下次重试
```

**核心设计思想**：通知 ≠ 收录。IndexNow 只保证"已通知"，是否真正收录需要二次验证。两条链路构成完整闭环。

### 2.3 IndexNow 实现

**代码位置**：`internal/adapter/indexnow/indexnow.go`

#### 协议说明

IndexNow（https://www.indexnow.org）是一个免费开放的协议，支持 **Bing / Yandex / Naver** 等搜索引擎。提交后新页面在数小时~数天内被收录。

#### 请求格式

```
POST https://api.indexnow.org/indexnow
Content-Type: application/json

{
  "host": "content.example.com",
  "key": "a1b2c3d4e5f6g7h8",
  "keyLocation": "https://content.example.com/public/indexnow-key.txt",
  "urlList": [
    "https://content.example.com/public/articles/oc-123"
  ]
}
```

#### 密钥验证机制

IndexNow 协议要求：
1. 生成一个 8-128 位的十六进制密钥（格式：`[a-zA-Z0-9-]`）
2. 在站点根目录托管一个纯文本文件，内容就是密钥本身
3. 每次提交时带上 `keyLocation` 指向这个文件——搜索引擎会访问它校验密钥有效性

**项目实现**：密钥文件由公开站端点 `/public/indexnow-key.txt` 托管（`public_handler.go`）。
- 同时兼容 IndexNow 协议要求的 `/{key}.txt` 路径（Gin 动态路由 `/:key.txt`）
- 密钥通过 `.env` 的 `INDEXNOW_KEY` 配置，admin 后台收录管理页可自动生成

#### 响应状态码

| HTTP 状态码 | 含义 |
|---|---|
| 200 | 提交成功，搜索引擎已接受 |
| 202 | 提交已接受，稍后处理 |
| 422 | 密钥格式无效或 keyLocation 无法访问 |
| 422 | URL 与 host 不匹配 |
| 其他 4xx/5xx | 提交失败 |

### 2.4 百度主动推送实现

**代码位置**：`internal/adapter/urlsubmit/baidu.go`

#### 协议说明

百度站长平台的主动推送 API，用于通知百度爬虫收录新页面。

#### 请求格式

```
POST http://data.zz.baidu.com/urls?site=content.example.com&token=xxx
Content-Type: text/plain

https://content.example.com/public/articles/oc-123
https://content.example.com/public/articles/oc-456
```

- 每行一个 URL（text/plain，不是 JSON）
- 单次最多 2000 条（代码自动分片）
- 每日配额约 10 万条（与手动提交共享）

#### 响应

```json
{
  "remain": 99998,
  "success": 2,
  "not_same_site": [],
  "not_valid": []
}
```

- `remain`：当日剩余配额
- `success`：成功提交数
- `not_same_site`：与站点不匹配的 URL
- `not_valid`：无效 URL

#### 配置

| 配置项 | 来源 | 说明 |
|---|---|---|
| `BAIDU_SITE` | `.env`（百度站长平台） | 已验证域名 |
| `BAIDU_TOKEN` | `.env`（百度站长平台 → 资源提交 → API 推送） | 准入 token |

### 2.5 多通道组合（MultiSubmitter）

**代码位置**：`internal/adapter/urlsubmit/multi.go`

使用组合模式，并行向所有已配置的渠道提交，失败互不影响：

```go
type MultiSubmitter struct {
    submitters []port.URLSubmitter
}
```

- 并行提交（goroutine + WaitGroup）
- 任一渠道失败不影响其他渠道
- 全部成功返回 nil；任一失败返回聚合错误（errors.Join）

### 2.6 动态配置（CachedProvider）

**代码位置**：`internal/adapter/urlsubmit/cached.go`

支持运行时配置免重启——管理后台改了 IndexNow key 或百度 token 后，30 秒内自动生效：

```go
type CachedProvider struct {
    load     ConfigLoader               // 从 system_settings 加载配置
    ttl      time.Duration              // 30 秒缓存
    cached   port.URLSubmitter          // 缓存的 MultiSubmitter 实例
}
```

- 每次提交时检查缓存：TTL 30 秒内复用已构建的 MultiSubmitter
- 过期则从 ConfigLoader 重新读取并按配置重建（新增/移除渠道自动生效）
- 未配置任何渠道时返回 no-op（提交空转成功，不阻断业务）

## 三、收录状态验证（链路 ③）

### 3.1 port.IndexStatusChecker 接口

**定义位置**：`internal/usecase/port/index_checker.go`

```go
type IndexStatusChecker interface {
    CheckURLs(ctx context.Context, urls []string) (map[string]string, error)
}
```

返回 `map[url]status`，status 取值：`indexed` / `pending` / `error`。

### 3.2 Bing Webmaster API 实现

**代码位置**：`internal/adapter/bing/checker.go`

#### API 端点

```
GET https://ssl.bing.com/webmaster/api.svc/json/GetUrlSubmissionStatus
    ?apikey={BING_API_KEY}        ← Bing 站长 API 密钥
    &siteUrl={BING_SITE_URL}      ← 已验证站点地址
    &url={文章 URL}               ← 如 https://content.example.com/public/articles/oc-123
```

#### 响应解析

Bing 返回 JSON，三种类型对应三种状态：

| Bing 返回 | JSON 类型 | 解析结果 | 含义 |
|---|---|---|---|
| `null` | nil | `"pending"` | Bing 已收到提交，但尚未收录 |
| `"Error"` | string | `"error"` | 查询失败（API 限流 / 密钥过期 / 站点未验证） |
| `{"d":"..."}` | object | `"indexed"` | 已被 Bing 收录 |

#### 解析代码

```go
func (c *Checker) parseBody(body []byte) string {
    var parsed any
    if err := json.Unmarshal(body, &parsed); err != nil {
        return "error"
    }
    switch v := parsed.(type) {
    case nil:           // JSON null → 未收录
        return "pending"
    case string:        // JSON "Error" → 查询失败
        if v == "Error" {
            return "error"
        }
        return "pending"
    default:            // JSON object → 已收录
        return "indexed"
    }
}
```

#### 查询方式

- **串行逐条查询**（非批量）——Bing API 不支持批量查询
- 每条 HTTP 请求超时 10 秒
- 单条失败不阻断其余（标记为 error，下次重试）

### 3.3 定时验证任务

**代码位置**：`internal/adapter/scheduledtask/tasks_index.go`

#### 任务参数

| 属性 | 值 |
|---|---|
| 任务名 | `index-status-check` |
| 执行间隔 | 24 小时 |
| 分布式锁 | `NoopLock`（单机）/ `RedisLock`（多实例） |
| 前置条件 | `BING_API_KEY` + `BING_SITE_URL` 已配置（否则空转） |

#### 执行逻辑

```
1. 检查 checker 是否为 nil → 空转退出（未配置 Bing 凭据）
2. 查所有已发布内容（ListPublished）
3. 过滤：跳过 IndexStatus == "indexed" 的（已确认收录，节省 API 配额）
4. 拼公开站 URL：{PUBLIC_BASE_URL}/public/articles/{contentID}
5. 调 checker.CheckURLs(urls) 逐条查 Bing
6. 回写：
   - indexed → UpdateIndexStatus(indexed, now)  记录收录时间
   - pending → UpdateIndexStatus(pending, zero)  保持等待
   - error   → 不改写（下次重试）
7. 日志输出统计：checked / indexed / pending / failed
```

#### 内容状态流转

```
发布时（ContentUseCase.SetStatus）
  → IndexStatus = "pending"（初始）

定时验证（IndexCheckTask）
  → Bing 查询结果：
     indexed → IndexStatus = "indexed" + IndexedAt = now
     pending → IndexStatus = "pending"（不变）
     error   → 不改写（下次重试）
```

## 四、配置参考

### 4.1 环境变量（.env）

```bash
# IndexNow 密钥（自动生成或手工填写，8-128 位十六进制）
INDEXNOW_KEY=

# 公开站根地址（生成提交 URL + sitemap + JSON-LD 的绝对 URL）
# 必须是公网可达地址
PUBLIC_BASE_URL=http://localhost:8082

# Bing 收录状态验证（可选——不配则收录验证任务空转）
# API Key 在 Bing Webmaster Tools 获取：Settings → API Access → API Key
BING_API_KEY=
# 必须与 PUBLIC_BASE_URL 一致，且在 Bing 站长工具验证过
BING_SITE_URL=

# 百度主动推送（可选——不配则不通知百度）
BAIDU_SITE=
BAIDU_TOKEN=
```

### 4.2 运行时管理（admin 后台）

| 管理位置 | 端点 | 可配置项 |
|---|---|---|
| 收录管理页 | `GET/PUT /admin/indexing/config` | IndexNow key、百度 site/token、开关 |
| 收录日志 | `GET /admin/indexing/logs` | 收录提交记录审计 |
| 自动生成密钥 | `POST /admin/indexing/generate-key` | 自动生成 IndexNow key |
| 验证密钥文件 | `GET /admin/indexing/verify-key` | 验证 key 文件可被搜索引擎访问 |
| 手动补提交 | `POST /admin/indexing/re-submit` | 重新提交所有已发布内容 |

### 4.3 Bing API Key 获取步骤

> 官方文档：https://learn.microsoft.com/en-us/bingwebmaster/getting-access

1. 登录 [Bing Webmaster Tools](https://www.bing.com/webmasters)
2. 添加并验证站点（`BING_SITE_URL` 对应的域名）
   - Meta 标签验证：首页 `<head>` 加 `<meta name="msvalidate.1" content="{验证码}" />`
   - XML 文件验证：根目录放 `BingSiteAuth.xml`
   - CNAME 验证：加 DNS 记录
3. Settings → API Access → API Key → Generate API Key
4. 复制 API Key，填入 `.env` 的 `BING_API_KEY`

**注意**：一个 Bing 账号只有一个 API Key，可用于该账号下所有已验证站点。

### 4.4 百度 Token 获取步骤

1. 登录 [百度搜索资源平台](https://ziyuan.baidu.com/)
2. 添加并验证站点
3. 普通收录 → 资源提交 → API 推送
4. 复制准入 token，填入 `.env` 的 `BAIDU_TOKEN`

## 六、设计原则（整洁架构）

### 6.1 依赖倒置

```
ContentUseCase → port.URLSubmitter（接口）
                     ↑ 实现
        ┌────────────┼────────────┐
  indexnow.Submitter  baidu.Submitter  MultiSubmitter  CachedProvider
```

新增收录渠道（如 Google Indexing API）= 新 adapter 实现 + main 装配，usecase 零改动。

### 6.2 开闭原则

- CachedProvider 内部按配置动态构建 MultiSubmitter —— admin 后台开关某个渠道，30 秒内生效，不重启
- IndexCheckTask 的 checker 参数是接口 —— 未来接 Google Search Console API 只需新 adapter

### 6.3 尽力而为语义

收录通知（SubmitURLs）和收录验证（CheckURLs）都是"尽力而为"：
- 通知失败：`_ = uc.urlSubmitter.SubmitURLs(...)` 忽略错误，不阻断发布
- 验证失败：单条标记 error，不阻断其余条目，下次重试
- 未配置：空转（nil 安全），不影响主业务

### 6.4 失败隔离

MultiSubmitter 并行提交多渠道，任一渠道失败不影响其他渠道。一条 URL 即使百度推送失败，IndexNow 仍能成功通知 Bing。
