# 高德 Web 服务 API —— 地理编码 / 逆地理编码

> 来源：高德开放平台官方文档（最后更新时间：2026-02-02）
> 服务地址：`https://restapi.amap.com`（HTTP/HTTPS，GET 请求）
> 归档位置：`Docs/第三方/高德地图/基础API/`

---

## 1. 产品介绍

地理编码 / 逆地理编码 API 提供**结构化地址 ↔ 经纬度**的相互转化能力，通过 HTTP/HTTPS 协议访问远程服务。

- **结构化地址**：由国家 → 省份 → 城市 → 区县 → 乡镇 → 乡村 → 街道 → 门牌号码 → 建筑物名称，按大区域到小区域组合的字符串。一个有效地址应是独一无二的。
- **地理编码（地址 → 坐标）**：将详细结构化地址转换为高德经纬度坐标；也支持地标性名胜景区、建筑物名称（如"天安门" → 116.397499,39.908722）。
- **逆地理编码（坐标 → 地址）**：将经纬度转换为详细结构化地址，且返回附近周边的 **POI、AOI** 信息（如 116.480881,39.989410 → 北京市朝阳区阜通东大街6号）。

**区域限制**：大陆、港、澳地区编码时国家信息可选择性忽略，但省市城镇等级地址构成不可忽略；**暂不支持返回台湾省的详细地址信息**。

**适用场景（本项目视角）**：
| 场景 | 方向 | 项目用途 |
|---|---|---|
| 门店地址自动定位 | 地理编码 | 商户填写地址 → 经纬度/区划回填（✅ 已实现 `AmapGeoCoder`） |
| 手机定位反查店铺地址 | 逆地理编码 | 老板授权定位 → 免手输地址（P1 扩展） |
| 商圈识别 | 逆地理编码（regeo 返回 businessAreas） | 补全"商圈"维度——本地关键词/监测问法从"区"级精确到"商圈"级（P1 扩展，价值高） |

**使用流程（三步）**：
1. 申请【Web服务 API】密钥（Key）
2. 拼接 HTTP 请求 URL（Key 作为必填参数一并发送）
3. 接收返回数据（JSON 或 XML），解析

> 输入参数和输出数据编码统一为 **UTF-8**。

## 2. 地理编码 API（`v3/geocode/geo`）

### 2.1 服务地址

```
https://restapi.amap.com/v3/geocode/geo?parameters
请求方式：GET
```

### 2.2 请求参数

| 参数名 | 含义 | 规则说明 | 是否必须 | 缺省值 |
|---|---|---|---|---|
| `key` | 高德 Key | 高德官网申请的 **Web 服务 API 类型** Key | 必填 | 无 |
| `address` | 结构化地址信息 | 遵循国家→省份→城市→区县→乡镇→街道→门牌号→建筑物顺序，如"北京市朝阳区阜通东大街6号" | 必填 | 无 |
| `city` | 指定查询的城市 | 支持：中文（北京）、中文全拼（beijing）、citycode（010）、adcode（110000）；**不支持县级市**；为空则全国范围检索 | 可选 | 全国搜索 |
| `sig` | 数字签名 | 见官方"数字签名获取和使用方法" | 可选 | 无 |
| `output` | 返回数据格式 | `JSON` / `XML` | 可选 | JSON |
| `callback` | 回调函数 | 用户定义的函数名，仅 output=JSON 时有效 | 可选 | 无 |

### 2.3 返回参数

| 名称 | 含义 | 说明 |
|---|---|---|
| `status` | 结果状态值 | `0`=失败；`1`=成功 |
| `count` | 返回结果数目 | 结果个数 |
| `info` | 状态说明 | status=0 时返回具体错误原因，否则返回 "OK" |
| `geocodes[]` | 地理编码信息列表 | 见下表 |

`geocodes[]` 子字段：

| 字段 | 含义 | 示例 |
|---|---|---|
| `country` | 国家 | 国内默认"中国" |
| `province` | 省份名 | 北京市（四大直辖市也算省级单位） |
| `city` | 城市名 | 北京市 |
| `citycode` | 城市编码 | 010 |
| `district` | 区 | 朝阳区 |
| `street` | 街道 | 阜通东大街 |
| `number` | 门牌 | 6号 |
| `adcode` | 区域编码 | 110101 |
| `location` | 坐标点 | 经度,纬度 |
| `level` | 匹配级别 | 见 § 4 匹配级别列表 |

### 2.4 服务示例

```
https://restapi.amap.com/v3/geocode/geo?address=北京市朝阳区阜通东大街6号&output=XML&key=<用户的key>
```

## 3. 逆地理编码 API（`v3/geocode/regeo`）

### 3.1 服务地址

```
https://restapi.amap.com/v3/geocode/regeo?parameters
请求方式：GET
```

### 3.2 请求参数

| 参数名 | 含义 | 规则说明 | 是否必须 | 缺省值 |
|---|---|---|---|---|
| `key` | 高德 Key | 同地理编码 | 必填 | 无 |
| `location` | 经纬度坐标 | **经度在前，纬度在后，逗号分隔**，小数点后不超过 6 位 | 必填 | 无 |
| `poitype` | 返回附近 POI 类型 | 仅 `extensions=all` 时生效；支持多个 POI TYPECODE，用 `\|` 分隔（见 POI 分类码表） | 可选 | 无 |
| `radius` | 搜索半径 | 取值范围 **0~3000**，单位米 | 可选 | 1000 |
| `extensions` | 返回结果控制 | `base`=基本地址信息；`all`=基本地址 + 附近 POI + 道路信息 + 道路交叉口信息 | 可选 | base |
| `roadlevel` | 道路等级 | 仅 extensions=all 生效；`0`=显示所有道路；`1`=仅输出主干道路 | 可选 | 无 |
| `sig` | 数字签名 | 见官方文档 | 可选 | 无 |
| `output` | 返回数据格式 | JSON / XML | 可选 | JSON |
| `callback` | 回调函数 | 仅 output=JSON 时有效 | 可选 | 无 |
| `homeorcorp` | 是否优化 POI 返回顺序 | 仅 extensions=all 生效；`0`=不干扰；`1`=居家相关 POI 优先；`2`=公司相关 POI 优先 | 可选 | 0 |

### 3.3 返回参数

| 名称 | 含义 | 说明 |
|---|---|---|
| `status` | 结果状态值 | 0=失败 / 1=成功 |
| `info` | 状态说明 | 失败时返回具体原因 |
| `regeocode` | 逆地理编码结果 | 包含 addressComponent / businessAreas / roads / roadinters / pois / aois |

`regeocode.addressComponent`（地址元素）：

| 字段 | 含义 | 注意 |
|---|---|---|
| `country` | 国家 | 例如：中国 |
| `province` | 省名称 | 例如：北京市 |
| `city` | 城市名称 | ⚠️ **直辖市（北京/上海/天津/重庆）与省直辖县时该字段返回为空** |
| `citycode` | 城市编码 | 例如：010 |
| `district` | 区 | 例如：海淀区 |
| `adcode` | 行政区编码 | 例如：110108 |
| `township` | 乡镇/街道（社区街道） | 例如：燕园街道 |
| `towncode` | 乡镇街道编码 | 例如：110101001000 |
| `neighborhood` | 社区信息 | name（社区名称）/ type（POI 类型） |
| `building` | 楼信息 | name（建筑名称）/ type |
| `streetNumber` | 门牌信息 | street（街道）/ number（门牌号）/ location（坐标）/ direction（方位）/ distance（距请求坐标距离，米） |
| `seaArea` | 所属海域 | 例如：渤海 |

`regeocode.businessAreas`（**商圈列表——本项目扩展价值高**）：

| 字段 | 含义 | 示例 |
|---|---|---|
| `businessArea.location` | 商圈中心点经纬度 | — |
| `businessArea.name` | 商圈名称 | 例如：颐和园 |
| `businessArea.id` | 商圈所在区域 adcode | 例如：朝阳区/海淀区 |

`regeocode.roads`（道路信息，extensions=all 返回）：`id` / `name` / `distance`（米）/ `direction` / `location`

`regeocode.roadinters`（道路交叉口，extensions=all 返回）：`distance` / `direction` / `location` / `first_id` / `first_name` / `second_id` / `second_name`

`regeocode.pois`（**附近 POI 列表，extensions=all 返回**）：

| 字段 | 含义 |
|---|---|
| `id` / `name` | POI ID / 名称 |
| `type` | POI 类型（如"餐饮服务;中餐厅"） |
| `tel` | 电话 |
| `distance` | POI 中心点到请求坐标距离（米） |
| `direction` | 相对输入点方位 |
| `address` | POI 地址信息 |
| `location` | 坐标点 |
| `businessarea` | POI 所在商圈名称 |

`regeocode.aois`（AOI 信息，extensions=all 返回）：`id` / `name` / `adcode` / `location` / `area`（平方米）/ `distance`（0=在 AOI 内，其余=距 AOI 距离）/ `type`

### 3.4 服务示例

```
https://restapi.amap.com/v3/geocode/regeo?output=xml&location=116.310003,39.991957&key=<用户的key>&radius=1000&extensions=all
```

## 5. 关键注意事项（对接踩坑点）

1. **经纬度顺序**：`location` 一律"经度,纬度"，小数点不超过 6 位——本项目 `parseLngLat` 已按此解析。
2. **直辖市 city 为空**：逆地理编码在北京/上海/天津/重庆时 `city` 返回空——本项目门店定位用 `district` 优先、`city` 兜底，与官方行为对齐。
3. **字段类型漂移**：部分返回值存在时是字符串、不存在时是数组（`[]`）——解析需做类型兜底（本项目 JSON 解析用字符串字段，需注意空值形态）。
4. **港澳台**：不支持台湾省详细地址；港澳地区可省略国家信息但省市不可省。
5. **配额**：详细服务调用量限制见控制台"配额管理"（政策会调整）。
6. **poitype/roadlevel/homeorcorp 均依赖 extensions=all**：base 模式不返回 POI/道路信息。

## 6. 项目对接现状与扩展建议

### 6.1 已实现（地理编码）

- 对接点：`internal/adapter/geo/amap.go` → `AmapGeoCoder.Geocode`
- 已解析字段：`location`（经纬度）、`province/city/district`、`adcode`、`formatted_address`
- 落库：`geo_store_locations`（lat/lng/city/district/adcode/geo_status）

### 6.2 扩展建议（逆地理编码，P1）

| 扩展点 | 用 regeo 的哪个返回 | 落地设想 |
|---|---|---|
| **商圈补全** | `businessAreas[0].name` | 门店档案增加 `business_area` 字段——本地关键词生成/监测问法从"朝阳区"精确到"望京"，匹配度质变 |
| 手机定位建档 | `addressComponent` + `streetNumber` | 老板授权浏览器定位 → 逆编码自动填充地址表单 |
| 附近 POI 快查 | `pois`（extensions=all + poitype 限定餐饮） | 无需另调周边搜索即可拿到 1km 内同行（radius ≤ 3000 有上限，替代/兜底 `place/around`） |
| 门店电话补全 | `pois[].tel` | 建档时若用户未填电话，尝试从逆编码 POI 补全 |

> 对接骨架：`AmapGeoCoder` 增加 `ReverseGeocode(ctx, lng, lat, radius)` 方法（同文件新增实现 + 响应解析），mock 降级策略沿用（未配置返回 `port.ErrGeoNotConfigured`）。
