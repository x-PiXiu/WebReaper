# 高德 Web 服务 API —— 距离测量

> 来源：高德开放平台官方文档（最后更新时间：2026-02-02）
> 服务地址：`https://restapi.amap.com`（HTTP/HTTPS，GET 请求）
> 归档位置：`Docs/第三方/高德地图/基础API/`

---

## 1. 产品介绍

距离测量 API 提供**批量距离计算**能力：多个起点（最多 100 个）到**一个目的地**的距离与耗时。

支持三种计算方式（`type` 参数）：

| type | 方式 | 说明 |
|---|---|---|
| `0` | **直线距离** | 纯几何距离（不受路况影响） |
| `1` | **驾车导航距离**（默认） | **考虑实时路况**，不同时间请求结果可能不同；策略≈驾车路径规划的 strategy=4（"躲避拥堵，可能绕路"）；仅支持国内坐标 |
| `3` | **步行规划距离** | **仅支持 5km 内**的距离 |

> 若要实现高德客户端效果（完整路线/导航），应使用驾车路径规划接口（`v3/direction/driving`）。

**适用场景（本项目视角）**：
| 场景 | 用途 |
|---|---|
| 附近同行"距离+耗时" | 地图榜从"直线距离"升级为"**距你 1.2km，驾车约 5 分钟**"——老板感知真实可达性 |
| 到店转化文案 | 内容/公开页"一键导航"卡片配驾车耗时 |
| 配送范围分析 | 批量测门店到周边商圈的距离矩阵（P3） |

**使用流程（三步）**：申请 Web 服务 Key → 拼接 URL（Key 必填）→ 解析返回 JSON/XML。

---

## 2. 服务地址与请求方式

```
https://restapi.amap.com/v3/distance?parameters
请求方式：GET
```

---

## 3. 请求参数

| 参数名 | 含义 | 规则说明 | 是否必填 | 缺省值 |
|---|---|---|---|---|
| `key` | 请求服务权限标识 | 高德官网申请的 Web 服务 Key | 必填 | 无 |
| `origins` | 出发点 | **支持 100 个坐标对**，坐标对用 `\|` 分隔；经纬度用 `,` 分隔（经度在前） | 必填 | 无 |
| `destination` | 目的地 | 格式 `lon,lat`（经度,纬度），如 `117.500244,40.417801`，小数 ≤6 位 | 必填 | 无 |
| `type` | 路径计算方式 | `0` 直线 / `1` 驾车（默认）/ `3` 步行（仅 5km 内） | 可选 | 1 |
| `sig` / `output` / `callback` | 签名 / 格式 / 回调 | output=JSON/XML；callback 仅 output=JSON 时有效 | 可选 | — |

---

## 4. 返回参数

| 名称 | 说明 |
|---|---|
| `status` | 结果状态值（1=成功 / 0=失败） |
| `info` | 状态说明（失败时返回原因） |
| `results[]` | 距离信息列表（与 origins 一一对应） |

`results[].result`：

| 字段 | 说明 |
|---|---|
| `origin_id` | 起点坐标序列号（**从 1 开始**） |
| `dest_id` | 终点坐标序列号（从 1 开始） |
| `distance` | **路径距离，单位：米** |
| `duration` | **预计行驶时间，单位：秒** |
| `info` | 仅出错时显示（多数为"未知错误"）——**⚠️ 建议不论批量与否都用此字段判断单条是否成功**（而非顶层 status） |
| `code` | 仅出错时显示（驾车模式）：`1`=地点间无可行车道路；`2`=起点/终点距道路过远（如海洋/矿区）；`3`=起点/终点不在中国境内 |

---

## 5. 服务示例

```
# 3 个起点 → 1 个目的地
https://restapi.amap.com/v3/distance?origins=116.481028,39.989643|114.481028,39.989643|115.481028,39.989643&destination=114.465302,40.004717&output=xml&key=<用户的key>
```

---

## 6. 关键注意事项

1. **批量 100 个起点**：一次请求算完整个竞品列表，配额友好。
2. **单条失败判断**：批量时顶层 status 可能成功但个别点失败——必须读 `results[].info`/`code` 判断每条结果。
3. **type=1 结果不稳定**：考虑路况，不同时间返回不同（属正常，文案标注"约"）。
4. **type=3 步行限 5km**：超过 5km 的步行距离请用驾车或直线。
5. **type=0 直线 vs 周边搜索的 distance**：`place/around` 返回的 distance 本身就是直线距离，与 type=0 一致——**想要"驾车耗时"才需要调本接口**。
6. 配额：调用量限制见控制台"配额管理"（政策会调整）。

## 7. 项目对接建议

| 用途 | 拼接要点 | 落点设想 |
|---|---|---|
| **地图榜"距离+耗时"**（P2 主场景） | `origins=各竞品坐标（≤100）&destination=门店坐标&type=1` | `NearbyUseCase` 在双榜返回后批量调距离测量 → `MapRankEntry` 增加 `DriveDistanceM` / `DriveDurationSec` → 前端显示"驾车约 5 分钟" |
| 直线距离换算 | type=0 | 与周边搜索 distance 一致，可做一致性校验 |
| 步行可达性 | type=3（仅 ≤5km） | "步行 10 分钟可达"文案（高转化场景） |
| 配送范围 | 批量矩阵 | 门店到周边商圈的驾车时间热力（P3，需循环多次调用） |

> 对接骨架：`adapter/geo/amap.go` 新增 `MeasureDistances(ctx, origins []Location, dest Location, typ int)`——一次 HTTP 调用，响应 `results[]` 按 `origin_id` 映射回入参顺序（⚠️ 注意 1 起始的序号），失败条目跳过不阻断（`code`/`info` 非空即跳过）；mock 降级返回空（未配置 Key 时前端只显示直线距离，行为不变）。
