# 21 - 视频链接拉取多平台架构与部署指南

> 日期：2026-08-28
> 范围：文案提取链路（`POST /api/v1/generation/transcript/extract`）的视频链接解析与下载架构改造、新增部署依赖、各部署形态的操作步骤与验证方法。

---

## 1. 背景与改造内容

本轮改造解决三类问题（均有实测记录）：

| 问题 | 根因 | 解法 |
|---|---|---|
| 抖音下载偶发 403 | play_addr 轮换返回的 `v26-web.douyinvod.com` 节点校验 Referer，代码未带 | `safeDownload` 按域补 Referer + 候选列表依次尝试 |
| 抖音详情接口空响应 | 接口级风控（登录 cookie 也会触发），旧提示误导用户重新扫码 | 换会话重试（3 次）+ 错误语义修正 |
| Go 无法走通抖音分享页 | **抖音 WAF 按 TLS 指纹分流**：Python requests（OpenSSL）拿 SSR 数据页（8/9），Go crypto/tls 只拿 JS 壳页（0/6） | Python sidecar 子挂载 |

新增能力：yt-dlp 通用解析（1800+ 长尾平台兜底）。

## 2. 解析链架构全景

```
用户贴链接（share_url 字段）
  │
  ├─ B站（b23.tv / bilibili.com/video/BV…）
  │    └─ biliweb 公开 API（view → playurl qn=16 html5 → durl mp4 直链）【最快 ~0.4s】
  │
  ├─ 快手 → 明确拒绝（JS 渲染 + pkey 会话签名双层风控，2026-08-26 评估放弃）
  │
  ├─ 抖音（口令 / v.douyin.com / www.douyin.com / iesdouyin.com）
  │    ├─ ① Python sidecar【主力 1~5s】：纯 HTTP 走 iesdouyin 分享页 SSR
  │    │     _ROUTER_DATA（iteminfo API → 分享页 → WAF PoW 破解三级降级）
  │    │     免浏览器、免登录账号、不消耗爬虫账号配额
  │    └─ ② chromedp【深度兜底】：视频页上下文 XHR 调详情接口
  │          （游客/爬虫账号 cookie，空响应换会话重试 3 次）
  │
  ├─ 其他平台（YouTube/微博/西瓜/...）
  │    └─ yt-dlp 子进程【长尾兜底】：`yt-dlp -J --no-playlist` → info_dict
  │         → 筛「音视频合一 + http(s)」格式按分辨率降序生成候选
  │
  └─ og:video 页面 → og resolver【收尾】（分享页 meta 解析）

下载：safeDownload 多候选依次尝试 + 按域自动补 Referer
      （douyinvod/douyin/snssdk/iesdouyin → douyin.com；bilivideo/hdslb → bilibili.com）
提取：ffmpeg 抽音轨（16k 单声道 mp3）→ ASR → 文案（24h 缓存）
```

**字段语义注意**：`share_url` 走解析链（贴分享口令/网页地址）；`video_url` 是**视频文件直链**（跳过解析直接下载）——传网页地址到 `video_url` 会把 HTML 当视频下载（待优化项：自动识别转链）。

## 3. 新增部署依赖清单

| 依赖 | 用途 | 缺失时影响 | 安装方式 |
|---|---|---|---|
| **python3（≥3.8）** | 抖音 sidecar 宿主 | 抖音走 chromedp 兜底（慢 ~10s+，游客模式仍可用） | Windows: 官网安装包；Linux: 系统包管理器 |
| **requests（pip 包）** | sidecar HTTP 库 | 同上（sidecar 报错自动降级） | `pip install requests` |
| **yt-dlp** | 长尾平台解析 | YouTube/微博/西瓜等不可用（抖音/B站不受影响） | `pip install yt-dlp` 或[官方单文件 exe](https://github.com/yt-dlp/yt-dlp/releases) 放 PATH |
| **ffmpeg** | 抽音轨（16k mp3） | ASR 降级为 ≤25MB 整文件直传（超限报错）；**此项非本轮新增**，但 Docker 镜像此前也缺失，已一并补 | Windows: 下载放 PATH；Linux/Docker: 包管理器/apt |

依赖间关系：互相独立，任一缺失只影响对应通道，服务正常启动。

## 4. 部署步骤（按形态）

### 4.1 裸机 Windows（当前开发机形态）

```powershell
# ① Python 依赖（python3 已装则只跑 pip）
pip install --user requests yt-dlp

# ② ffmpeg（若 PATH 里没有；已有 MediaAVTool 则跳过）
#    下载 https://www.gyan.dev/ffmpeg/builds/ 解压后把 bin 加入 PATH

# ③ 编译 + 启动
go build -o server.exe ./cmd/server
./server.exe
```

### 4.2 裸机 Linux

```bash
apt-get install -y python3 python3-pip ffmpeg   # 或 yum 等价命令
pip3 install --break-system-packages requests yt-dlp   # PEP 668 环境需此参数（debian/ubuntu 新版）
# Chromium 仍为 chromedp 通道必需（原有要求，不变）
./webreaper
```

### 4.3 Docker

Dockerfile **已更新**（Stage 2 运行时镜像新增 `python3 + python3-pip + ffmpeg` 的 apt 层和 `pip3 install requests yt-dlp` 层，pip 走阿里云镜像）。

```bash
docker build -t webreaper:latest .    # ⚠️ 本次 Dockerfile 变更尚未实际构建验证（本机无 Docker），首次构建请在有 Docker 的环境执行并确认 pip 层成功
docker compose up -d                   # docker-compose.yml 无需改动
```

镜像体积会增大约 300~400MB（python + ffmpeg + yt-dlp python 包）。

## 5. 新增配置项

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `YT_DLP_CMD` | 空 | yt-dlp 调用形态（空格分词）。空 = 自动探测：`yt-dlp` → `yt-dlp.exe` → `python -m yt_dlp` → `python3 -m yt_dlp`（探测一次缓存）。例：`YT_DLP_CMD=python -m yt_dlp` |

无新增必填项；`JWT_SECRET`/`PUBLISH_COOKIE_SECRET`/DB 等原有要求不变。

| 缺失 | 抖音 | B站 | 长尾平台 | 其他功能 |
|---|---|---|---|---|
| python3 / requests | ⚠️ 降级 chromedp（慢但可用） | ✅ | ✅（若 yt-dlp 用独立 exe） | 不影响 |
| yt-dlp | ✅ | ✅ | ❌ 报"暂不支持"（文案待更新） | 不影响 |

## 8. 原理注记与运维注意

1. **为什么抖音要 Python**：抖音 WAF 按 TLS 指纹（JA3/JA4）分流。Go `crypto/tls` 访问 iesdouyin 分享页只返回 JS 渲染壳页（`_ROUTER_DATA` 无数据，实测 0/6）；Python requests（OpenSSL 指纹）返回 SSR 数据页（实测 8/9）。sidecar 脚本由 `go:embed` 内嵌进二进制（`internal/adapter/douyinweb/py/douyin_resolver.py`），运行时落临时文件执行，stdin/stdout 各一行 JSON，45s 超时强杀。
2. **CDN 下载不受 TLS 分流影响**：解析（WAF 层）必须 Python，下载（CDN 层）Go 直连即可——已实测 Go 直接下载 sidecar 返回的直链 200/mp4。
3. **抖音协议时效**：sidecar 依赖 iesdouyin 分享页 SSR 的 `_ROUTER_DATA.videoInfoRes.item_list` 结构，抖音改版可能失效（历史上已变体过）；失效表现为抖音全部降级 chromedp（日志可见 `Python sidecar 失败...降级`），不是静默故障。壳页变体内置重试（3 次），WAF 算力挑战（"Please wait"）内置 PoW 破解。
4. **yt-dlp 只取音视频合格式**：分离流（bv+ba）需要 ffmpeg 合并、超出下载层单文件契约，被有意过滤；文案提取场景低清即够。yt-dlp 的抖音 extractor 需要 cookie（实测），所以抖音不指望 yt-dlp，由 sidecar 负责。
5. **爬虫账号现状**：抖音主链路（sidecar）不消耗账号配额；管理后台健康检测已改为按账号解密检测（带失败原因），unhealthy 账号可被重新检测救回（修复了"被标不健康→池子不再选→检测永远失败"死锁）。
