# 26 - 资产物化与任务表解耦计划

> 日期：2026-08-31
> 定位：**架构修复计划**——分身/音色/作品等长期资产从 `generation_tasks`（过程记录）
> 物化到独立资产表，修复"任务与对象绑定"的结构性问题。
> 背景：用户端"我的分身/我的音色"直接过滤任务表导致失败任务泄漏到资产列表；
> 深挖发现 30 天任务清理器会**无差别删除终态任务**（含 success 的 subject/
> voice_clone/成片），资产随任务行一起消失。与 25 号 §6 平台资产共用表结构。

---

## 1. 问题清单（现状核实）

| # | 问题 | 证据 |
|---|---|---|
| 1 | **失败任务泄漏**：failed/cancelled 任务行出现在"我的分身/我的音色"资产列表 | 前端 useSubjectList 从 `GET /generation/tasks` 过滤 sub_type，无 state 过滤 |
| 2 | **任务与对象绑定**：分身/音色是长期资产，却寄生在"一次生成行为"的任务行里（state/轮询/终态语义） | 无独立主体表；server_id/voice_id 全在任务 params/creations JSON |
| 3 | **★30 天清理删资产**：generation-cleanup（24h）→ DeleteTerminalOlderThan(30d) 无差别删除所有终态任务——**用户的分身（server_id 丢失）、克隆音色、成片作品、B-Roll timeline 全部 30 天后消失** | `generation_task_repo.go:172`：`state IN (success,failed,cancelled) AND created_at < -30d`，无 sub_type 排除；`generation_cleanup.go:25` retainDays=30 |
| 4 | **50 条窗口挤掉资产**：任务列表固定返回租户最近 50 条，生成任务一多，较早的分身/音色被挤出窗口"看不见" | `generation_handler.go` HandleList 固定 limit 50 |
| 5 | 任务行无运营字段：无法给资产排序/上下架/打标签 | —— |

问题 3 是隐性数据丢失（文件有引用排除不删，但任务行没了，数据成孤儿）；
问题 1/4 是用户可见的体验缺陷。

## 2. 方案：资产物化（Materialization）

核心思想：**任务表回归"过程记录"语义，终态成功的对象快照落独立资产表；
任务随便清理，资产永生。**

```
创建分身：POST submit(sub_type=subject) → 任务行(created) → Vidu 同步成功
  → ★物化钩子：server_id/name/portrait_url/voice_id 快照写入 subject_assets
  → 链式形象视频成功 → 回填 subject_assets.avatar_video_url
清理器：照删 30 天前任务（过程记录本就该清）——资产表不受影响
用户查询：GET /subjects/mine 读 subject_assets——失败任务从未物化，天然不出现
```

## 3. 表设计（081/082 迁移）

```sql
-- 081: 主体资产（个人分身/环境 + 官方主体统一表——25 号二′b 的 official_subjects 并入）
CREATE TABLE subject_assets (
  id            VARCHAR(64) PRIMARY KEY,
  tenant_id     VARCHAR(64) NOT NULL,            -- 官方行用平台运营租户
  scope         VARCHAR(16) NOT NULL DEFAULT 'personal',  -- personal / official
  kind          VARCHAR(16) NOT NULL DEFAULT 'person',    -- person / scene（25 号 §6.5）
  name          VARCHAR(128) NOT NULL,
  server_id     VARCHAR(128) NOT NULL,           -- Vidu 主体 id（唯一索引）
  portrait_url  VARCHAR(512) NOT NULL DEFAULT '',
  avatar_video_url VARCHAR(512) NOT NULL DEFAULT '',  -- 链式形象视频产物（成功后回填）
  voice_id      VARCHAR(128) NOT NULL DEFAULT '',
  tags          VARCHAR(512) NOT NULL DEFAULT '',
  sort_order    INT NOT NULL DEFAULT 0,          -- 官方行排序
  status        VARCHAR(16) NOT NULL DEFAULT 'active',  -- active / disabled（官方上下架）
  source_task_id VARCHAR(64) NOT NULL DEFAULT '',-- 溯源任务（仅记录，不做外键依赖）
  created_at    DATETIME NOT NULL,
  updated_at    DATETIME NOT NULL,
  UNIQUE KEY uk_server (server_id),
  KEY idx_tenant (tenant_id, scope, kind, status)
);

-- 082: 音色资产（个人克隆并入；官方复刻音色同表 scope=official）
ALTER TABLE generation_voices
  ADD COLUMN scope VARCHAR(16) NOT NULL DEFAULT 'vidu',   -- vidu(官方表seed) / platform(官方复刻) / clone(用户克隆)
  ADD COLUMN tenant_id VARCHAR(64) NOT NULL DEFAULT '',   -- clone 行归属；官方行空
  ADD COLUMN source_task_id VARCHAR(64) NOT NULL DEFAULT '',
  ADD COLUMN status VARCHAR(16) NOT NULL DEFAULT 'active';
-- 用户"我的音色"改查 scope=clone AND tenant_id=?；官方复刻 scope=platform 置顶
```

设计要点：
- **官方/个人一表两用**（scope 字段）：25 号二′b 的 official_subjects 不再单独建表，
  管理后台创建官方主体=写 scope=official 行，用户端即显可管。
- 物化**快照**必要字段（server_id/URL），任务行仅留 source_task_id 溯源——清理任务
  不影响资产可用性。

## 4. 写路径：终态物化钩子

- 挂载点：任务终态通知处（与 notifyTerminal 同模式），`generation.go` 内：
  - `sub_type=subject && state=success` → upsert subject_assets（server_id 唯一键幂等）
  - `sub_type=voice_clone && state=success` → upsert generation_voices(scope=clone)
  - `sub_type=reference2video && params.avatar_video && state=success` → 回填
    对应 subject_assets.avatar_video_url（按 subjects[0].server_id 定位）
- 失败/取消：**不物化**——留在任务中心可重试，资产列表天然干净（问题 1 解）。

## 5. 读路径切换

| 查询 | 现状 | 改为 |
|---|---|---|
| 我的分身/环境 | tasks 过滤 sub_type=subject | `GET /api/v1/subjects/mine`（subject_assets 分页/搜索/按 kind） |
| 我的克隆音色 | tasks 过滤 voice_clone | `GET /api/v1/generation/voices?scope=clone`（资产表） |
| 官方主体（用户端官方区） | 静态占位卡 | `GET /api/v1/subjects?scope=official`（已建端点改读资产表，按 sort_order） |
| 分身创建中过渡态 | 任务行即资产行 | 前端提交后轮询任务到终态：成功→刷资产列表；失败→留任务中心 |
| 形象视频三态 | join 任务 params.avatar_task_id | 读 subject_assets.avatar_video_url（空=生成中/失败，可走重试端点） |
| 重试/补建（avatar-video 端点） | 写回任务 params | 成功后走物化钩子回填资产行（端点不变） |

前端 `subjectTask.ts` 的任务解析逻辑保留用于"创建中过渡态"，资产列表改消费新端点。

## 6. 清理器与文件安全

- 任务清理：不变（30 天删终态任务——过程记录语义正确）。
- 文件清理排除集 `referencedMediaURLs`：**扩展为从资产表收集**
  portrait_url/avatar_video_url/sample_url（现状只扫任务行，任务删了引用也丢了）。

## 7. 存量迁移（backfill）

一次性回填：扫现存 `state=success` 的 subject / voice_clone 任务 → 按物化规则写入
资产表（server_id 唯一键去重）。随 081/082 迁移后首启执行（或 cmd/backfill 工具）。

## 8. 成片/作品物化（第二批，另行设计）

作品（lip_sync/compose 等 success 任务）同样 30 天后从作品库消失——涉及 works 三源
聚合、发布关联、media_urls 匹配，范围大。本计划先做 subject/voice（直接救分身与音色）；
`work_assets` 物化作为第二批，届时 ListWorks 增加资产表为主源、任务表降级为过程补充。
