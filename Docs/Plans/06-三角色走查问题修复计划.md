## 二、修复设计

### P0-1 online 官网必填改为阻断式校验（R2-1 / X-4，安全门）

**根因**：创建弹窗的官网字段校验只渲染了警示文案，未挂接到 antd Form 的提交校验链（rules 的条件校验依赖 `watchedBizType`，但提交按钮未走 `validateFields` 或规则缺少 `dependencies`）。

**方案**（`Brands.tsx`，创建+编辑两处表单同步）：
```tsx
// 官网字段规则：线上业务必填（阻断），本地可选
{ name: 'website_url', dependencies: ['biz_type'], rules: [{
  validator: (_, v) => {
    if (watchedBizType === 'online' && !(v || '').trim())
      return Promise.reject(new Error('线上品牌必填——官网是 AI 引用你的核心信源（NAP 注入）'))
    return Promise.resolve()
  },
}] }
```
提交统一走 `form.validateFields()`（确认创建按钮的 htmlType/onClick 路径）；**后端双保险**：`BrandUseCase.Create/Update` 对 `biz_type=online && website_url==""` 返回 400（防绕过前端）。

**验收**：online + 空官网 → 点击创建 → 弹窗不关闭、官网字段红框聚焦、不产生请求；填官网后成功。
**成本**：0.5d ｜ **涉及**：`web/Brands.tsx`、`internal/usecase/geo/brand.go`

### P0-2 首选率"数据积累中"态（R1-1 / X-3，信任门）

**根因**：旧数据无 `first_pick_count`，健康报告回退 `avg_position==1` 近似——1 条命中即 100%，与提及率并排展示自相矛盾。

**方案**（展示可信度门槛，数据不动）：
1. 后端 `health.go`：`HealthIndicators.FirstPickRate` 语义升级——返回 `first_pick_rate` + 新增 `first_pick_samples`（参与聚合的采样总数）：
   - 真实计数路径：`sampleSum >= 3` 才出数值，否则 rate=-1（积累中）；
   - 近似路径（旧数据）：`ranked >= 3` 才出数值且标注 `approximate: true`，否则 -1。
2. 前端 `HealthScorePanel`：indicator value 为负 → 显示"积累中"灰态 + hint"发起 ≥3 次采样后展示"；OverviewTab"进阶路径"卡同理。
3. `geoHealth.ts` 兜底同口径（latest 结果采样和 <3 → 积累中）。

**验收**：蜀香居（1 条采样）驾驶舱首选提及显示"积累中"，不再出现 100%；矩阵详情面板的首选率块在有 ≥3 采样时显示百分比+`N/M 次第一`。
**成本**：1d ｜ **涉及**：`health.go`/`geo_handler.go` 视图、`HealthScorePanel.tsx`、`OverviewTab.tsx`、`geoHealth.ts`

### P0-3 引导 CTA 直达创建弹窗（R2-2）

**方案**：零品牌引导页 CTA 改为 `navigate('/m/brands', { state: { openCreate: true } })`；`Brands.tsx` 挂载时读 `location.state?.openCreate` → `setBrandModalOpen(true)` 并清 state（`navigate('.', { replace: true, state: {} })`）。四步向导条中"创建品牌"步骤同理。
**验收**：新账号从引导页一次点击即见表单弹窗。
**成本**：0.5h ｜ **涉及**：`Home.tsx`（两处）、`Brands.tsx`

### P0-4 行业分布口径统一 + 未分类治理入口（R3-1）

**根因**：Dashboard 同页两图——上方"品牌行业分布"实际按 `biz_type` 分（本地/线上），下方行业榜按 `industry` 字段分（全空→未分类）。两套口径并列即矛盾。

**方案**（分两步走）：
1. **止血（口径统一）**：上方分布图改名"品牌业务类型分布"（如实标注维度），消除"行业"字样误用；行业榜"未分类"条目附提示 Tag"去引导商户补填行业"。
2. **治理（治填写率）**：
   - 商户端：品牌表单行业改为**下拉建议+可输入**（行业常见清单：餐饮/美业/家装/教育/电商/SaaS工具/跨境电商…），创建弹窗中标注"影响行业看板与知识库检索范围"；GEO 体检的"行业未填写 ✗"项可点击直接定位到编辑框（现仅有文案）。
   - 管理端：Dashboard 加"数据治理"提示卡："N 个品牌未填行业——影响行业看板"，admin 可复制商户名单（不代填，品牌资产归商户）。

**验收**：Dashboard 两图无口径冲突文案；新创建品牌时行业下拉出现；行业榜未分类数随填写下降。
**成本**：止血 0.5d + 治理 1d ｜ **涉及**：`admin/Dashboard.tsx`、`Brands.tsx`、行业清单常量（`web/src/constants/industries.ts` 新建）

### P0-5 admin 默认口令提醒（R3-4，安全）

**方案**：后端 seed admin 时打标（users 表已有字段可复用则复用，否则 `login` 响应附带 `must_change_password: username=="admin" && 密码校验通过的是默认口令`——用 bcrypt 比对默认口令常量）；admin 前端 AdminLayout 顶部常驻 `Alert`："当前使用默认密码 admin123，请立即修改" + 跳转；配套**修改密码端点** `PUT /api/v1/auth/password`（旧密码验证 + bcrypt 更新）。
**验收**：默认口令登录 admin 必见提醒；改密后提醒消失。
**成本**：1d ｜ **涉及**：`auth/`、`data_handler`/`router_core`、`AdminLayout.tsx`

### P1-2 详情抽屉遮罩残留修复（R1-5）

**排查**：`MatrixTab` 详情容器确认是 Modal 还是 Drawer；现象是点"关闭"后 `.ant-modal-wrap` 仍在 DOM 且拦截点击。常见根因：嵌套弹层（详情 Modal 里又开了 message/confirm）关闭顺序错误，或 Modal 未设 `destroyOnClose` 且 onClose 只清了内容态。
**方案**：确认 onClose 链路 `setDetailRow(null)` 真正触发 `open=false`；Modal 加 `destroyOnClose`；若为嵌套，内层关闭后再关外层。修复后回归：开详情→点行尾"监测"（内层操作）→关闭，侧栏可点击。
**成本**：0.5d（含复现）

### P1-3 商户管理增强（R3-3）

**后端**：`GET /admin/users` 聚合扩展——每商户附 `plan_name`（billing 订阅）、`brand_count`、`keyword_count`、`last_active_at`（usages 表最近一行 / 无则 created_at）。实现：admin users handler 一次扇出（量小可接受），或 stats 聚合复用。

**验收**：管理员能按"免费/团队版/沉睡"扫描商户，定位跟进对象。
**成本**：1.5d

### P1-4 问题词意图分类落地（R2-4 后半）

**后端**（`keyword_sources.go` QuestionSource）：蒸馏 prompt 输出 `{terms: [{term, intent}]}`，intent ∈ informational/comparative/recommendational（映射到 Keyword.Intent 现有字段，新增合法值——迁移无需，VARCHAR 已容纳）；`distillKeywords` 响应携带每词 intent。
**前端**（`Keywords.tsx`）：蒸馏结果列表每词加意图 Tag（信息型🟢/比较型🔵/推荐型🟡）；添加入库透传真实 intent（删除三处硬编码 `informational` 的其中两处——速查自动入库保留默认可接受，注释说明）；"我的关键词"意图筛选下拉同步新值。
**验收**：蒸馏"云笔记哪个好用"→ 至少出现 比较型/推荐型 两类标签；入库后词库筛选可按意图过滤。
**成本**：1d

### P1-5 信源域名榜净化（R3-2）

**方案**（`industry.go` `sourceDomain`）：URL → host（不变）；非 URL 文本 → 匹配**平台/媒体白名单**（大众点评/美团/知乎/小红书/抖音/微博/B站/央视/BBC…含常见别名），命中返回标准名；未命中 → 归入"其他来源"计数（单独一条 `domain: "__other__"` 前端显示"其他"），**不再 12 字符截断**。
**验收**：榜单只出现真域名/标准平台名/其他；"搜索到的…"消失。
**成本**：0.5d

**方案**：`HealthScorePanel` 的"信源完整"indicator hint 扩充："AI 回答实际引用你公开站的比例。2026-08-15 后的新监测开始记录引用来源，历史结果不计入"；驾驶舱卡片区加一个"数据口径"说明入口（Popover 汇总：各指数的数据起点/采样口径），一次性解决同类疑问。

## 四、关键设计决策说明

1. **首选率选"展示门槛"而非"隐藏指标"**：数据继续按真实口径积累（FirstPickCount），展示层加可信度门槛（≥3 采样）——兼顾"两阶段叙事"的进阶指标露出与不误导；`approximate` 标记保留旧数据平滑过渡。
2. **行业字段用"下拉建议+可输入"而非强选**：强制必填会拦住冷启动（用户进来就想看监测），用 GEO 体检 ✗ 引导 + admin 治理卡双向驱动填写率。
3. **online 官网必填前后端双保险**：前端拦截是体验，后端 400 是底线（防 API 直调绕过）——延续 05 计划"契约守护"思想。
4. **术语替换放 P2**：文案改动面大（回归成本高于收益排序），先以 hint 白话化缓解，统一替换在功能稳定后一次做。
