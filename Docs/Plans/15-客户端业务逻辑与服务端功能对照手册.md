## 二、按页面逐项的修改建议

### 2.1 Creation.tsx（高级生成页）——**优先级最高**

| # | 修改 | 原因 | 具体操作 |
|---|------|------|---------|
| 1 | **隐藏"音乐生成"卡片**（text2audio） | 提交后实际生成的是语音朗读（TTS），不是音乐——功能名不符 | 在 SUBTYPE_META 中移除或加 `disabled: true` 标记，卡片置灰标注"即将上线" |
| 2 | **隐藏"音效生成"卡片**（sound_effect） | 同上——被映射为 TTS | 同上 |
| 3 | **"智能多帧"卡片加提示**（multiframe） | 上传 2 张图会被自动判成"首尾帧"模式——用户意图落空 | 卡片描述加一句"传 3-9 张关键帧生效；2 张会自动走首尾帧"；或前端 2 图时弹确认"检测到 2 张图，将按首尾帧模式生成，确认？" |
| 4 | **"主体创建"卡片描述更新** | 现已可用（资产库一键注册）——但描述仍为旧文案 | 改为"注册数字分身形象，生成视频时可复用同一人物"；点击跳转 `/m/assets`（而非本页表单提交） |
| 5 | **失败重试建议显示** | 后端已下发 `retry_hint` 字段（RetryAuto/RetryManual/RetryTerminal），前端当前未消费 | 失败任务卡片按 retry_hint 显示：RetryAuto="稍后自动重试或手动重试" / RetryManual="请修改参数后重试" / RetryTerminal="配额耗尽，请升级或等待" |

**涉及文件**：`web/src/pages/merchant/Creation.tsx`

### 2.2 LipSyncWizard.tsx（口播向导）

| # | 修改 | 原因 | 具体操作 |
|---|------|------|---------|
| 1 | **第③步出镜视频显示时长** | 用户不知道自己的视频多长、和文案是否匹配 | 上传完成后显示"视频时长 X 秒"（前端可用 video 元素 duration 属性，无需后端） |
| 2 | **第②步文案字数→预计时长提示** | 文案 500 字 ≈ 2.5-3 分钟音频——用户对时长无感 | 文案确认页底部显示"预计口播时长约 X 分钟"（字数÷180字/分钟）；超 10 分钟标红"文案过长，建议精简" |
| 3 | **时长不匹配预警** | 出镜视频 13 秒 + 文案 3 分钟 → 对口型结果不可控 | 第③步选择视频后，与第②步预计时长对比：差距 >2 倍时黄色提示"视频时长与文案时长差距较大，建议匹配（可循环拍摄多段或精简文案）" |
| 4 | **长文案提示** | 普通生成（数字人/图生视频）单段 ≤16 秒 ≈ 45 字 | 文案 >60 字且选择"数字分身"出镜时提示："文案较长，将生成长视频（等待分段功能上线前建议压缩到 60 字内获得最佳效果）"——当前先提示，分段功能上线后改为自动进度条 |
| 5 | **第①步占位符已改**（"抖音 / B站"） | ✅ 已完成 | 无需操作 |
| 6 | **快手链接即时提示** | 粘贴快手链接提交后才报错 | Input.onChange 检测 `kuaishou.com` 或 `v.kuaishou.com` 时即显示灰色提示"快手暂不支持链接提取，请下载视频后用上传方式" |

**涉及文件**：`web/src/pages/merchant/compose/LipSyncWizard.tsx`

## 三、全局性修改建议

### 3.1 能力诚实化扫描（一次性清理）

对 Creation.tsx 的 13 张卡片逐一核对后端真实支持：

| 卡片 | 后端状态 | 客户端动作 |
|------|---------|-----------|
| 文生视频 | ✅ | 保留 |
| 图生视频 | ✅ | 保留 |
| 首尾帧 | ✅ | 保留 |
| 参考生视频 | ✅ | 保留 |
| 智能多帧 | ⚠️ 2图走首尾帧 | 加提示（§2.1 #3） |
| 文生图 | ✅ | 保留 |
| 音乐生成 | ❌ 走TTS | **隐藏** |
| 音效生成 | ❌ 走TTS | **隐藏** |
| 语音合成 | ✅ | 保留 |
| 声音克隆 | ✅ | 保留 |
| 对口型 | ✅ | 保留 |
| 数字人 | ✅ | 保留 |
| 主体创建 | ✅（新通） | 描述更新+跳资产库 |

### 3.2 提取链路占位符与错误信息统一

- 输入框占位符：**"粘贴抖音 / B站分享链接（其他平台请下载后上传）"** ✅ 已改
- 快手链接即时灰提示（§2.2 #6）
- 提取失败错误信息直接透传后端 msg（已有）——无需额外处理

### 3.3 数字分身全链路引导

```
资产库创建分身（✅已通）
    → 向导第③步选分身（✅列表可选）
    → 空列表引导跳转（§2.4 #3——加按钮）
    → 分身复用一致性生成（❌ 服务端 subjects 未接线——向导当前仍走图+音路径，
      客户端不阻断，正常可用，一致性效果等后续升级）
```

### 3.4 全局重试提示组件（可选增强）

利用后端 `retry_hint` 字段做一个全局小组件 `<RetryHint code={...}/>`：
- RetryAuto → 黄色 Tag "网络繁忙，可重试"
- RetryManual → 橙色 Tag "请检查参数"
- RetryTerminal → 红色 Tag "配额耗尽"

用在：Creation 任务卡片、ComposeHub 任务列表、MyWorks 失败项。
