## 一、需求理解（业务链路）

```
┌─────────────────────────────────────────────────────────────────────┐
│  ① 平台级采集（持续、按行业）                                          │
│     不同用户属于不同行业（餐饮/美业/电商/线上服务…）                      │
│     → 平台按行业配置关键词，定期爬取相关内容                              │
│     → 入库：正文 + 来源 URL + 原文出处（"来自哪一篇文章"）               │
└──────────────────────────────┬──────────────────────────────────────┘
                               │ 知识库（kb_materials，按行业组织）
┌──────────────────────────────▼──────────────────────────────────────┐
│  ② 生成前检索（用户操作时）                                            │
│     用户选择关键词 + 品牌 → 按"品牌行业 + 关键词"检索知识库素材            │
│     → 素材必须带来源（标题/摘要/来源 URL）                               │
└──────────────────────────────┬──────────────────────────────────────┘
                               │ 素材 + 来源标注
┌──────────────────────────────▼──────────────────────────────────────┐
│  ③ 规格化生成（现状闭环，改造注入点）                                    │
│     system prompt（prompt_templates 表规格化模板，引擎偏好代码拼接）      │
│     + user prompt（品牌信息/NAP/关键词 + 参考资料段落[带来源]）           │
│     → 上游 LLM 生成 → 现有质量护栏（校验重生成/五维评分/低分不提交）       │
└─────────────────────────────────────────────────────────────────────┘
```

**核心语义**：通知 ≠ 收录 ≠ 引用。本需求解决的是"**生成有据可依**"——LLM 创作时引用真实来源素材（"不编造数据"从口号变能力），且素材可溯源（生成内容里的数据可回到原始出处）。

### 3.2 领域实体（domain/entity）

**`knowledge_material.go`（新）**：

```go
// KnowledgeMaterial 知识库素材——一条带来源的采集结果。
// SourceURL + URLFingerprint 是溯源与去重的双保险：
//   - SourceURL：原始出处（生成内容时标注给 LLM）
//   - URLFingerprint：sha256(URL)，唯一索引做持久化去重
type KnowledgeMaterial struct {
    ID             string
    Industry       string    // 所属行业（平台级维度，如 "餐饮"）
    SourceURL      string    // 来源 URL（原文出处）
    URLFingerprint string    // sha256(SourceURL)，唯一索引
    Title          string    // 页面标题
    Content        string    // 清洗后正文（入库截断，如 3000 字）
    Summary        string    // 摘要（入库截断，如 300 字）
    Tags           []string  // 标签（预留；LLM 打标 P2）
    CrawlKeyword   string    // 本次采集命中的关键词（溯源）
    Embedding      []float32 // 向量（title+summary+正文前 800 字）
    Status         string    // active / rejected
    CreatedAt      time.Time
}

// MaterialRef 检索返回的素材引用（带来源，供生成注入）。
type MaterialRef struct {
    Title     string  // 标题
    Summary   string  // 摘要（前 300 字）
    SourceURL string  // 来源 URL —— 需求核心字段
    Score     float32 // 相似度（0-1）
}

// IndustryCrawlConfig 行业采集配置（system_settings JSON 存储）。
type IndustryCrawlConfig struct {
    Industry string   `json:"industry"`  // 行业名（须与 Brand.Industry 对齐）
    Keywords []string `json:"keywords"`  // 采集关键词组
    PerRound int      `json:"per_round"` // 每轮每关键词上限（默认 10）
}
```

**`geo.go`（改）**：`Brand` 加 `Industry string`（空则检索时从定位推断兜底）。

**`system_setting.go`（改）**：`SettingKeyKnowledgeCrawl = "kb_crawl_industries"`。

## 四、关键流程

### 4.1 采集管线（KnowledgeCrawlTask，每 6h）

```
读 system_settings[kb_crawl_industries]（空 → 空转）
└─ 每行业 × 每关键词（每行业每轮 ≤20 条）：
   ① SearchCrawler.Execute({query, num:10})
       → 候选列表 [{title, url, snippet}]
   ② URL 规范化 → sha256 → repo.ExistsByFingerprint（持久化去重，替代内存 map）
   ③ 未爬过：StaticCrawler.Execute({url}) → DataItem{Content, RawContent, SourceURL}
       （robots.txt / 登录态 / 付费墙合规检查由爬虫内置）
   ④ 确定性清洗：
       - 正文 ≥200 字（rune 计数），不足丢弃
       - Content 截断 3000 字，Summary = 正文前 300 字
   ⑤ 入库 + 向量化（embedder.Embed(title + summary + 正文前 800 字)）
       embedding 失败不阻断入库（降级：该条无向量，检索不到但保留原文）
   ⑥ 单条失败不阻断；任务日志统计：候选 / 去重 / 入库 / 失败
```

### 4.2 检索（生成时）

```
Retrieve(industry, query, num=3)：
 ① embedder.Embed(query)
 ② repo.SearchSimilar(industry, vec, num×3 预取)
    → SQL 取该行业全部带向量行 → Go 余弦相似度排序
 ③ 阈值过滤（Score < 0.25 剔除）→ 取 top3
 ④ 返回 MaterialRef{Title, Summary, SourceURL, Score}
```

## 五、质量保障（三端闭环）

| 环节 | 保障措施 |
|---|---|
| 采集端 | 持久化指纹去重（URL 唯一索引）、正文 ≥200 字门槛、robots/登录/付费墙合规（复用）、每行业每轮配额防失控 |
| 检索端 | 行业精确过滤 + 相似度阈值（<0.25 剔除）→ 只把高相关素材送 LLM |
| 生成端 | 现有护栏**零改动**：A1 校验重生成（2 轮）、五维评分、低分不提交；素材带来源标注 → 内容可溯源 |
| 降级链 | embedding 不可用 → 检索返回空 → 自动回退现有在线 RAG（与现状行为一致） |

### 6.1 管理后台动态配置（30s 生效，免重启）

| 端点（admin） | 内容 |
|---|---|
| `GET/PUT /admin/knowledge/embedding-config` | 向量嵌入模型（model/base_url/api_key/**dimensions**）+ 向量库（vector_db：mysql/milvus + milvus 连接参数） |

| `GET/PUT /admin/knowledge/crawl-interval` | **采集间隔（分钟，30-1440；默认 360=6h）**——下个周期生效免重启 |
| `GET /admin/knowledge/stats` | 知识库素材统计 |

**采集间隔动态化**（2026-08-14）：`scheduler` 新增"每周期刷新 Interval"通用能力（每周期结束重读 `task.Interval()`，向后兼容现有常量间隔任务）；`KnowledgeCrawlTask.Interval()` 从 `system_settings[kb_crawl_interval_minutes]` 读取（30s TTL 缓存），管理后台改间隔 → 下个周期生效，**免重启**。冷启动阶段可调短（如 60 分钟）密集采集，稳定后调长（如 12-24h）节省配额。

**配置归属原则**（整洁架构）：
- 运营变量（间隔/行业/向量模型/向量库）→ system_settings 运行时配置（管理后台可改）
- 领域不变量（正文长度门槛/截断/检索数量）→ 代码常量（改=发版，防运营误配破坏数据质量）
- 环境凭据兜底 → env（EMBEDDING_* / LLM_*）

**智谱（bigmodel）embedding-3 配置示例**（OpenAI 兼容，开箱即用）：

| 字段 | 值 |
|---|---|
| model | `embedding-3` |
| base_url | `https://open.bigmodel.cn/api/paas/v4` |
| api_key | 智谱开放平台 API Key（Bearer 认证，自动兼容） |
| dimensions | `0` = 模型默认 **2048 维**；可显式设 256/512/768/1024/2048（⚠️ 修改后必须重建向量） |

> 兼容性说明：`HTTPEmbedder` 按 OpenAI 兼容协议实现——端点/认证/请求（model+input+可选 dimensions）/响应解析（data[].embedding）与智谱 v4 embeddings API 完全一致；dimensions=0 时请求体不携带该字段（MiniMax 等不支持该参数的厂商零影响）。

**动态生效机制**（对齐 IndexingConfig 30s TTL 先例）：

```
管理后台改配置 → system_settings[kb_embedding_config]
  → CachedEmbedder（30s TTL 重建 HTTPEmbedder）       ← 换向量模型免重启
  → VectorStoreProvider（30s TTL 按配置路由驱动）       ← 换向量库免重启
  → 采集任务 / 生成检索自动用新配置
```

**向量库切换语义**：
- `vector_db=mysql`（默认）：MySQL JSON 列 + Go 余弦——零依赖可运行
- `vector_db=milvus`：**Milvus 驱动已接入（2026-08-14）**——按运行时配置连接（host/port/collection），集合懒创建（含 industry 过滤列 + IVF_FLAT 余弦索引）；连接失败明确报错（Provider 失败缓存 30s），不静默降级
- 接入方式验证了开闭原则：`MilvusVectorStore` 实现 `port.VectorStore` + `MilvusFactory` 注入 Provider，仓储/检索/生成链路零改动

### 6.2 换模型后的向量重建（动态配置的配套操作）

管理后台换 embedding 模型后，**存量素材的向量是旧模型产物**（维度/语义空间不一致，检索会错乱）。配套操作：

| 端点 | 行为 |
|---|---|
| `POST /admin/knowledge/reindex?only_missing=false` | 全量重建向量（遍历素材重新 embed，自动同步向量库） |
| `POST /admin/knowledge/reindex?only_missing=true` | 增量补向量（仅处理无向量的素材——采集时向量化失败的可补齐） |
| `POST /admin/knowledge/reindex?industry=餐饮` | 按行业重建（可与 above 组合） |

响应：`{processed, updated, failed}`——单条失败不阻断，返回统计供运营排查。

### 6.3 生成注入的检索策略（"本地优先，不牺牲召回"）

```
知识库命中 ≥1 条 → 素材引用（带来源可溯源）
   └─ 命中不足 3 条 → 在线检索补齐差额（num = 3 - 命中数，精确控制成本）
知识库无命中/检索失败 → 回退实时全网检索（旧行为）
都不可用 → 空串（纯 LLM 推断）
```
