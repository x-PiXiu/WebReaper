## 1. 现状事实（P0 核查结论）

- subject 是**同步端点**（`IsSync()=true`，`endpoints.go:406`）：注册成功即任务终态，
  无链式视频任务、无"形象视频生成中"中间态、形象视频 URL 无处存放
  （creations[0] 只有 server_id）。
- 前端已按 §2.1③ 先行提交 `params.scene_image / scene_description`（24 号批次），
  服务端接住即生效。
- **Vidu 官方主体列表 API 存在**（此前误判为可能没有）：
  `GET /ent/v2/subjects?ownership=system&count≤100&next_page_token=…`
  → `{subjects:[{id,name,images[],videos[],voice_id}], next_page_token}`；
  官方主体不返回 style/description。适配器未实现该方法。
- Vidu 产物 URL 24h 过期；转存机制（`local_media.go` → stored_url 永久化）已上线，
  链式形象视频产物天然享受转存。转存上线前的历史任务 URL 已失效不可救（B-Roll 对
  旧作品不可用——运营已知）。

## 2. 设计 A：链式形象视频（23 号 §2.1②）

### 2.1 触发与链路

```
POST /generation/submit sub_type=subject
  → 同步注册主体（现状不变，拿 server_id）
  → 【新增】自动创建 reference2video 任务：
       subjects=[{name, server_id}]      // 主体一致性
       duration=10                        // 10s 形象视频
       无音频（纯形象展示，不说话）
       prompt = scene_description（用户填写的场景描述）
                || 默认形象展示模板（"正面特写，微笑看向镜头，缓慢自然的肢体动作"）
  → 链式任务 ID 写回 subject 任务记录（新字段 avatar_task_id）
```

### 2.2 数据模型（最小改动）

- `generation_tasks` 加列 `avatar_task_id VARCHAR(64) NULL`（迁移 078）——subject 任务
  指向其形象视频任务。
- 查询聚合：`GET /generation/tasks` 视图对 sub_type=subject 的行附带
  `avatar_task_id` + 内联 `avatar_video`（链式任务的 state/url 摘要，服务端 Join 一次），
  前端零额外请求。
- 三态推导（前端）：注册中（subject 任务非终态）→ 形象视频生成中（subject success 且
  avatar_task 非终态）→ 可用（avatar success，URL 来自 avatar creations.stored_url）。
  **不引入新 state 枚举**——由两任务状态组合表达，服务端无需状态机改动。

### 2.3 评审决策点（D1-D5）

| # | 决策点 | 选项与倾向 |
|---|---|---|
| D1 | **场景图如何注入** | Vidu reference2video 主体模式只收 prompt+subjects；场景图可能的路径：a) 拼入 prompt 文字描述（弱）；b) `images` 非主体模式（失去主体一致性，不可接受）；c) Vidu 是否支持 subject+附加参考图（**需查参考生视频 API 文档确认**）。倾向：先实现 a（描述驱动），c 查证后升级 |
| D2 | 链式是否默认开启 | 新增系统配置 `gen_chain_avatar_video`（默认 true）。关闭时回退现状（注册即用），防计费争议 |
| D3 | 计费与配额 | reference2video 10s 计入 generation 场景配额。用户可见提示：创建分身将消耗一次视频生成额度 |
| D4 | 链式失败 | 分身仍可用（注册已成功），前端徽标"形象视频失败可重试"——重试=对同 subject 重新提交链式任务（不重复注册） |
| D5 | 删除级联 | 删除 subject 任务时：avatar_task 非终态先 cancel，再删本地记录（与现有 DeleteTask 语义一致） |

### 2.3.1 决策点定案（2026-08-31 评审通过）

| # | 定案 | 依据 |
|---|---|---|
| D1 | **场景图作为附加图片主体注入**：`subjects=[{name:分身名, server_id}, {name:"场景", images:[scene_image]}]`，prompt 以主体名同时引用两者（"@"分身在"@"场景中做什么）；场景描述融入 prompt。**优于**初评倾向的纯文字描述（a） | 参考生视频 API 已查证：`subjects` 数组支持多主体混合（q3/q2/q1/2.0 最多 7 个图片/文字主体，每个主体 images≤3）——见 `Docs/第三方/Vidu/创建视频任务/参考生视频.md` |
| D2 | 链式默认开启，系统配置 `gen_chain_avatar_video`（默认 true）可关 | 计费争议出口 |
| D3 | 链式任务计入 generation 配额；创建分身 UI 提示"将消耗一次视频生成额度" | 与现有配额体系一致 |
| D4 | 链式失败不影响分身可用性；重试=对同 server_id 重新提交链式（不重复注册） | 口播生成不依赖形象视频 |
| D5 | 删除分身时级联：avatar_task 非终态先 cancel，再删本地记录 | 与 DeleteTask 现语义一致 |

### 2.4 前端配套（本设计落地后）

- AvatarModule 我的作品区分身卡：三态徽标（创建中/形象视频生成中/可用）；
  卡片封面优先用形象视频首帧/缩略图（cover_url），无则形象照。
- 分身预览弹窗（§2.3）：形象视频 10s 循环播放 +「用此分身去创作」。
- 向导 SubjectPicker：可用的判定改为"avatar 可用或注册成功"（注册成功即可用，
  形象视频只是预览价值——**口播生成不依赖形象视频**，链路仍是 subjects+文案）。

## 3. 设计 B：官方主体端点（23 号 §2.2 / #1）

### 3.1 服务端

1. `viduendpoint` 新增 `subjectListAdapter`：`GET /ent/v2/subjects`，
   参数 ownership/count/next_page_token 透传，`IsSync()=true`。
2. `port.GenerationProvider` 接口加 `ListSubjects(ctx, ownership, pageToken, count)`。
3. 新端点 `GET /api/v1/subjects?ownership=system&page_token=&count=`：
   - 服务端内存缓存（TTL 5min，键=ownership+page_token）——官方主体基本静态，
     防止多租户高频刷 Vidu；
   - 响应透传 `{subjects:[{server_id,name,portrait_url(images[0]),voice_id}], next_page_token}`；
   - **不落库**（无租户归属，缓存即可；后续要"官方主体使用计数"再考虑落表）。

### 3.2 前端

- AvatarModule 官方区：静态 `OFFICIAL_SHOWCASE` 替换为 API 分页网格（即选即用——
  点击直接带 server_id 进向导，与"我的分身"行为一致）；
- 向导 `SubjectPicker` 双源合并：官方（API）+ 个人（subject 任务）分区展示；
- 官方主体 `voice_id` 可作为 B 路径（文本直生）的默认音色提示。

### 3.3 风险与实测结论（2026-08-31 端点上线后实测）

**服务端已交付并实测通过**：`GET /api/v1/subjects` 缓存代理端点（5min TTL，实测第二次
请求 0.001s 命中缓存）、Vidu `ListSubjects` 适配、switching 委派（mock 演示模式明确报错）。

**实测推翻"官方主体=官方数字人"的产品假设**：Vidu 官方库共 **183 个主体（2 页）**，
全部为——特效脸（闪亮决心脸/猫嘴…）、运镜转场（水墨晕染/维度折叠…）、道具静物
（咖啡杯/名牌汽车…）、场景（咖啡店/雨夜小巷/太空舱…）、武术动作（太极拳/金钟罩…）。
**没有任何口播数字人（人物）主体**。官方主体定位是"视频创作的参考素材主体"，
不是"即选即用的出镜数字人"。

**方案形态调整（待产品定案，三选项）**：

| 选项 | 做法 | 适配度 |
|---|---|---|
| A | 分身管理页官方区**撤下**"官方数字人"概念（显示"官方数字人库暂无"），`/api/v1/subjects` 端点保留备用 | 诚实但浪费 183 个素材 |
| B | 官方区改造为**"官方素材主体"**：场景/道具类主体 → reference2video 生成画面素材 → 存素材库 → **用作 B-Roll 插入片段**（口播链路的天然联动：官方场景主体生成"咖啡店"画面插到第 N 句） | 价值最大，需新建"主体生素材"入口（后续计划） |
| C | 官方区原样展示但点击引导到创作工具（reference2video 自由生成），不进口播向导 | 折中，交互预期需文案说明 |

> **定案（2026-08-31 产品决策）：官方主体 = 平台方后台自建的人物数字分身**，
> 不再依赖 Vidu system 库。Vidu 183 个主体的口播价值实测分类见 §6.1
> （场景 9 + 道具 10 ≈ 19 个可作为 B-Roll 素材生成的可选来源，低优先级保留）。
> 完整方案见 §6。

- count 上限 100，翻页用 next_page_token（前端"加载更多"模式，不做服务端全量拼接）。

## 6. 平台官方资产：自建官方主体与官方音色（2026-08-31 产品定案）

> 决策：**官方主体/官方音色 = 平台方自建资产**，不再直接露出 Vidu 官方库。
> 与 Vidu 的关系从"转发官方库"变为"用 Vidu 的生产能力铸造平台自有资产"。

### 6.1 Vidu system 库的口播价值实测分类（183 个主体）

| 类别 | 数量 | 口播价值 |
|---|---|---|
| 场景（咖啡店/雨夜小巷/太空舱/森林/宴会厅/教室/古建筑/居酒屋/记忆宫殿） | 9 | **B-Roll 高价值**——口播"看我们店里"时插对应场景画面 |
| 道具/静物（咖啡杯/名牌汽车/古钟/电视机/齿轮/书/气球…） | 10 | **B-Roll 中价值**——产品/环境特写 |
| 运镜/转场（水墨晕染/维度折叠/环绕镜头/无人机拉远…） | 27 | 风格化 B-Roll（生成的片段自带运镜） |
| 特效脸/表情（猫嘴/爱心眼/生无可恋脸…） | 14 | 无用（动漫贴纸风） |
| 动作/武术（太极拳/降龙十八掌…） | 12 | 无用 |
| 特效/其他（自燃/背景爆炸/拘灵遣将…） | 111 | 无用 |

**结论（2026-08-31 二次定案，产品纠正）**：口播出镜 0 个；B-Roll 也**不可用**——
本地生活获客的命门是真实性，Vidu 官方的"咖啡店/太空舱"再精美也是**别人家的店**，
插进用户自己的酸菜鱼口播里属于虚假宣传。用户口播要展示的是**自己的产品、自己店内的
环境、自己的形象**——因此场景/道具/运镜主体**全部弃用**，官方库整体不接入前端。
（已建的 `/api/v1/subjects` Vidu 代理端点代码保留、改路径 `/api/v1/subjects/vidu-library`
归档备用，不注册到前端任何入口。）

### 6.2 官方主体 = 平台自建（人物 + 环境两类，方案）

- **数据模型**：新表 `official_subjects`（server_id, name, portrait_url, tags,
  sort_order, enabled, created_at）。不复用 subject 任务过滤的原因：subject 任务挂
  租户维度，官方主体需全租户可见 + 运营字段（排序/上下架）。
- **创建链路**：管理后台新增「平台资产 · 官方主体」页（admin 角色）：
  上传形象照 1-3 张 + 名称 + 可选场景图/场景描述/绑定音色 → 走现有 subject 提交
  （挂平台运营租户/品牌）→ 注册成功登记 official_subjects。
  计费消耗平台自有 Vidu 积分；后续同样享受 §2 链式形象视频（预览更完整）。
- **端点改造**：`GET /api/v1/subjects` 改读 official_subjects 表（即选即用，
  server_id 直进向导）。现有 Vidu system 代理实现**保留**、路径改为
  `/api/v1/subjects/vidu-library`（供 §6.1 B-Roll 场景素材生成用，低优先级）。
- **前端**：AvatarModule 官方区接真数据（ selectable/即选即用/分页）；
  SubjectPicker 双源合并（官方+个人）。运营主体建议起步量：8-12 个（覆盖
  男/女 × 青年/中年 × 亲和/专业）。

### 6.3 官方音色 = 平台复刻音色 + 试听品牌化（技术澄清后定案）

**技术事实**：TTS 的产物是**音频文件**，不是音色；音色只有两种来源——
① Vidu 官方音色表（voice_id 直接引用）② **声音复刻**（voice_clone 用参考音频
克隆出归我们的新 voice_id）。"用 Vidu 音色生成一段 TTS 当官方音色"不可行
（音频不能作为 voice_id 参与后续生成），但两个真实意图都可落地：

| 意图 | 落地形态 |
|---|---|
| **拥有自主品牌音色**（不直接依赖 Vidu 音色露出/变动） | 声音复刻：选 1-3 个声源（创始人/签约配音 30s 干声）→ voice_clone 克隆出平台 voice_id → generation_voices 打 `kind=platform` 标记，置顶默认选中。注意复刻音色 **7 天内需在语音合成中调用一次转永久保留**。*（不推荐"Vidu 音色生成音频再复刻"的曲线方案——一代音质损失，且声线本质还是 Vidu 的）* |
| **试听品牌化**（点试听听到平台内容而非 Vidu 通用示例） | 运营一次性操作：对置顶音色用「平台介绍词」跑 TTS → 产物自托管 → 替换该音色 sample_url。用户试听即听品牌口播 |

- **数据模型**：generation_voices 加 `kind`（platform / vidu，默认 vidu）；
  platform 音色前端置顶 + 默认选中 + 「官方」徽标。
- **运营链路**：管理后台「平台资产 · 官方音色」页：发起复刻任务（上传参考音频）→
  成功后生成介绍词试听（TTS）→ 上下架/置顶。

### 6.5 环境主体回归（2026-08-31 产品定案：以"组合出镜资产"形态回归）

> 背景：旧"场景主体"概念曾于 24 号批次删除（当时是内容创作向、创建时人物/场景
> 二选一、与口播向导未打通）。本次以**新定位**回归：环境主体是与分身平级的独立
> 口播资产，在向导里与分身**乘法组合**（分身 × 环境），不是二选一。

**价值分析（真实性原则下的资源定位）**：

| 资产 | 通用性 | 结论 |
|---|---|---|
| 人物主体 | 通用（人设/风格可复用） | **官方定制高价值**（8-12 个人设覆盖男女/年龄/气质） |
| 音色 | 通用 | **官方定制高价值**（复刻 1-3 个平台音色） |
| 环境 | **个人资源**（用户自己的店/产品才有真实性） | 官方环境仅兜底价值（通用棚拍/直播间风格，用户无素材时用）；**用户自建环境才是主角** |

**用户自建环境主体的两个用途**：
1. **组合出镜（核心）**：注册"我的店面/后厨/门头"环境主体 → 向导第②步与分身组合
   → 生成"我的分身**在我的店里**口播"——跨视频环境一致（矩阵号视觉统一的另一半）。
2. B-Roll 直接用原始图片：用户拍的环境照片**直接作为图片片段插入**（已支持——图片
   按句时长转视频），**无需**"环境主体→生成视频→插入"的间接链路。环境主体生视频
   的增强路径**不做**（避免过度建设，真实性也不如实拍）。

**数据模型（服务端零 schema 改动）**：
- 环境主体 = subject 任务（`sub_type=subject` + `params.kind='scene'`）——params 自由
  透传，服务端已支持；前端 `subjectTask.ts` 恢复 kind 解析（语义从"创建二选一类型"
  变为"资产分类标签"）。
- `official_subjects` 表加 `kind`（person/scene）字段（078 迁移与链式合并）。

**组合生成技术现状（已核实，改造成本极小）**：
