# 视频/图文/文章发布客户端配置设计

> **版本**：v2.0（重构定位：客户端设计文档）
> **创建时间**：2026-08-25
> **读者**：前端开发 / 产品设计
> **配套**：服务端能力接口 `ChannelCapabilities`（参数约束的数据源）

---

## 一、设计目标与原则

| 原则 | 说明 |
|------|------|
| **能力声明驱动** | 表单项和校验规则由服务端 `/channel-capabilities` 返回的 `Constraints` 动态生成——平台改规则只改后端配置，前端零改动 |
| **一稿多发** | 用户填一份内容，系统按各平台规则自动适配（截断/Emoji/换行），客户端提供适配预览 |
| **分阶段填充** | 内容 → 素材 → 平台参数 三段可分离填写，支持草稿态，发布前统一完备性检查 |
| **不撒谎的能力** | 某平台某形态未实现全自动时不展示该选项（服务端 `SupportedContentTypes` 已诚实化，前端直接消费） |

## 二、发布参数总模型

一次发布请求的全部参数，按来源分三类：

### 2.1 通用参数（所有平台共用）

| 参数 | 必填 | 说明 | 客户端控件 |
|------|------|------|-----------|
| platform | ✅ | 目标平台（可多选→一稿多发） | 平台卡片多选 |
| contentType | ✅ | video / image / article | 随平台可选项联动 |
| title | ✅* | 标题（长度按平台约束） | 单行输入 + 字数计（按最严平台显示） |
| content | ✅* | 正文/描述（Markdown，提交时服务端转纯文本） | 多行富文本 |
| accountID | 自动 | 发布账号；空 = 账号池自动选号 | 账号下拉（默认"自动选择"） |
| mode | ✅ | semi-auto（生成链接手动发）/ auto（全自动） | 开关，默认半自动 |
| scheduledAt | 可选 | 定时发布（空=立即） | 日期时间选择 |

\* 标题必填性按平台：抖音无独立标题（并入描述）；正文对视频平台可空。

### 2.2 形态差异参数（按 contentType 出现）

| 参数 | video | image | article |
|------|-------|-------|---------|
| mediaURLs | ✅ 1 个 mp4 | ✅ 1~18 张图 | 可选头图 1 张 |
| coverURL | 可选封面 | —（首图即封面） | 可选 |
| tags | 正文内 #话题 或独立标签框（B站） | 正文内话题 | 话题（可选） |

### 2.3 平台差异参数（仅所选平台需要时出现）

| 参数 | 平台 | 控件 |
|------|------|------|
| category 分区 | B站（**必选**） | 下拉（生活/知识/科技…，默认"生活"） |
| tags 标签 | B站（**必填 ≥1**） | 标签输入（最多 N 个） |
| storeAddress 门店地址 | 本地生活商户可选 | 地址输入/POI 选择 |

## 四、客户端分阶段设计（五步向导）

### 阶段① 选择平台与形态

- 平台卡片多选（展示账号绑定状态：未绑定平台的卡片置灰 + "去绑定"）
- 每个平台展示其可用形态（从能力接口拉取），勾选后进入下一步
- **形态冲突处理**：多平台混选时若形态不一致（如 B站只支持 video、小红书选了 image），提示分组发布或取交集

### 阶段② 核心内容（一次填写，多平台复用）

- 标题 + 正文编辑器（正文支持 Markdown，服务端提交时转纯文本）
- 字数计量按**所选平台中最严约束**实时显示（如选了小红书：标题 ≤20 红线提示）
- 内容可存草稿（草稿不校验完备性）

### 阶段③ 素材上传（可后补）

- 按形态出现对应上传区：视频（1 个 mp4）/ 图片（拖拽多张，可排序——小红书首图即封面）/ 头图
- **素材允许暂缺**：缺素材仍可保存草稿；点"发布"时才做完备性检查
- 素材来源两种：本地上传 / 从素材库（内容工作台生成的视频/配图）选取

### 阶段④ 平台差异参数（动态渲染）

- 仅对所选平台需要的参数出项：B站 → 分区下拉（必选）+ 标签输入（必填 ≥1）；抖音 → 话题标签；本地生活 → 门店地址
- 通用补充项：定时发布时间、发布模式（半自动/全自动）、账号选择（默认自动）
- 全自动选项仅对矩阵中 ✅ 的平台×形态开放

### 阶段⑤ 适配预览与确认

- **多平台适配预览**：同一内容在所选各平台的最终形态（标题截断效果、Emoji 剥离、换行折叠、CTA 追加）——预览即真实适配结果（复用服务端 ContentAdapter 接口）
- 完备性检查汇总：缺失项清单（"B站缺标签""视频未上传"），点击可跳回对应阶段
- 确认后按平台逐一生成发布任务（半自动返回链接列表；全自动进入队列）

### 分阶段填充的实现要点

```
草稿（Draft）──── 任意阶段可保存，只存已填部分，不做完备性校验
   ↓ 发布时
完备性检查 ──── 按「平台×形态参数矩阵」逐项核对，缺口清单化
   ↓ 通过
提交 ─────────── 每平台一个 PublishJob（含适配后内容）
```

- 草稿数据结构 = 完整参数模型的子集（JSON），前端 localStorage + 服务端草稿接口（可选二期）
- 回到向导任意前序阶段修改后，后序已填数据保留（只重算受影响平台的适配预览）

## 五、与后端的接口契约

| 接口 | 用途 | 客户端消费点 |
|------|------|-------------|
| `GET /channel-capabilities` | 各平台形态/约束/DisplayName | 阶段①平台卡片、阶段②字数红线、阶段④动态表单 |
| `POST /publish` | 创建发布（含 ScheduledAt） | 阶段⑤提交；参数=第二章总模型 |
| `GET /publish/jobs` | 任务列表与状态 | 发布记录页（含 published-uncertain 待核对态） |
| `POST /publish/:id/mark-published` | 半手动发布后回填实际链接 | 半自动流程闭环 |

发布请求体（阶段⑤提交的最终形态）：

```json
{
  "platforms": ["bilibili", "xiaohongshu"],
  "contentType": "video",
  "title": "…", "content": "…",
  "mediaURLs": ["https://…/video.mp4"],
  "coverURL": "https://…/cover.jpg",
  "tags": ["本地生活"],
  "category": "生活",
  "accountIDs": {},
  "mode": "auto",
  "scheduledAt": "2026-08-26T10:00:00+08:00",
  "storeAddress": "…"
}
```

## 六、边界与体验细节

- **平台限流提示**：某平台当日发布数达到上限（限流接线后）时，阶段⑤对应平台卡片显示"今日已达上限，转为定时明日"，而非直接报错
- **登录态过期**：阶段①平台卡片显示账号健康度（active/expired）；expired 时提示重新扫码绑定
- **半自动流程**：提交后展示各平台预填链接列表 + "我已发布"回填按钮（mark-published）
- **风控高危平台**（小红书）：全自动选项旁常驻提示"平台审核严格，建议优先半自动"

## 七、客户端现状盘点（2026-08-25 实读代码）

前六章描述的是目标态。本章起记录**现状与差距**——客户端尚未具备向导能力，需按第十章路线分阶段建设。

### 7.1 现有资产（Distribution.tsx，733 行）

| 已有 | 实现位置 | 可复用性 |
|------|---------|---------|
| 平台多选卡片（六平台 + 账号健康状态展示） | Distribution 页"发布" Tab | ✅ 直接作为阶段①素材 |
| 内容选择（从内容工作带 OptimizedContent 进入）+ 标题/正文可编辑 | `selectedContent` / `publishContentText` | ✅ 阶段②素材 |
| AssetPicker 配图（与多媒体创作共用） | `components/AssetPicker` | ✅ 阶段③素材（需扩展视频选取） |
| 定时发布、模式切换（半自动/全自动）、全自动结果轮询 | Distribution 发布区 | ✅ 阶段④素材 |
| 发布形态预判（视频产物 → video） | `contentType` 推断逻辑 | ✅ 保留 |
| 发布记录 + 数据回读 + 复测 | PublishJobTable | ✅ 不动 |
| 扫码绑定闭环 | QRLoginModal | ✅ 不动 |

### 7.2 差距清单（现状 → 目标态）

| # | 差距 | 现状 | 目标（章节） |
|---|------|------|-------------|
| 1 | **无向导分步** | 全部参数一屏平铺，平台差异参数混在一起 | 五步向导（四） |
| 2 | **无草稿态** | 发布参数只在内存，切页即丢 | 分阶段填充 + 草稿（四/九） |
| 3 | **B站分区/标签无入口** | 参数模型就没这两个字段，发布必失败于前端校验 | 平台差异参数（2.3） |
| 4 | **字数约束硬编码/缺失** | 前端不按平台显示红线 | 能力驱动动态校验（一） |
| 5 | **能力接口未消费** | 后端 `ChannelCapabilities` 已有，前端未拉取做动态表单 | 阶段①④动态渲染（四） |
| 6 | **无适配预览** | 提交后才知道截断结果 | 阶段⑤预览（四） |
| 7 | **无完备性检查** | 缺素材/缺标签直接发，靠后端报错 | 发布前缺口清单（四） |
| 8 | **多平台循环串行提交** | 前端 for 循环逐平台调 publishContent，无事务感 | 一次提交多平台任务（五） |

### 7.3 API 现状

`publishContent` 已支持 `content_type/media_urls/cover_url/mode/scheduled_at`——参数模型基本齐；**缺 `tags`、`category` 字段**（差距 #3 的后端配套）。能力接口后端已存在（`PublishUseCase.ChannelCapabilities`），需补 HTTP 路由暴露。

## 八、页面与组件设计

### 8.1 组件树（目标态）

```
Distribution 页（保留三 Tab 结构）
└── "发布" Tab 改造为
    PublishWizard（发布向导容器，管理步骤与草稿）
    ├── StepPlatform    阶段①：平台多选卡片（复用现有）+ 形态选择（能力接口驱动）
    ├── StepContent     阶段②：标题/正文编辑（复用现有编辑状态）+ 最严约束红线
    ├── StepMedia       阶段③：AssetPicker 扩展（图片多选排序 / 视频选取 / 头图）
    ├── StepParams      阶段④：动态平台参数（B站分区标签/话题/门店/定时/模式/账号）
    ├── StepPreview     阶段⑤：多平台适配预览 + 完备性缺口清单 + 提交
    └── WizardStatusBar 底部常驻：草稿保存 / 上一步 / 下一步 / 发布
```

### 8.2 状态管理

向导状态用**单一 reducer + Context**（不引入新库，与项目 React Query 分工：React Query 管服务端数据，向导状态是纯客户端表单态）：

```ts
interface WizardState {
  step: 1|2|3|4|5
  platforms: string[]            // 阶段①
  contentType: 'video'|'image'|'article'
  title: string; content: string // 阶段②
  mediaURLs: string[]; coverURL: string  // 阶段③
  params: {                      // 阶段④：平台差异 + 通用补充
    tags?: string[]; category?: string; storeAddress?: string
    scheduledAt?: string; mode: 'semi-auto'|'auto'; accountIDs: Record<string,string>
  }
  contentId?: string; brandId?: string   // 从内容工作台带入
}
```

- 回退任意前序步骤修改，后序已填数据保留（reducer 天然支持）
- 草稿 = `WizardState` 序列化：**P1 存 localStorage**（切页不丢），**P3 升级服务端草稿**（多端同步，复用 publish-plans 表或新建 draft 字段）

### 8.3 路由与入口

- 保留 Distribution 页三 Tab；"发布" Tab 内容替换为向导（URL 加 `?step=N` 便于回退刷新）
- 内容工作台"发布"按钮 → 携 `contentId` 跳转向导并预填阶段②
- 灵感广场/创作中心产物 → 携 `mediaURLs` 预填阶段③

## 九、数据流与校验链

```
ChannelCapabilities（React Query 缓存）
   ↓ 派生
constraintsByPlatform → 阶段①形态可选项 / 阶段②字数红线 / 阶段④动态表单 / 阶段⑤完备性检查
   ↓ 提交时
POST /publish { ...WizardState 展开为多平台任务 }
```

**完备性检查函数（纯函数，阶段⑤与实时提示共用）**：

```ts
checkCompleteness(state, constraints): Gap[] {
  // 逐平台×形态核对第三章矩阵：
  // B站缺 category/tags、video 缺 mediaURLs、小红书标题>20、
  // 全自动勾选了未验证平台形态……每条 Gap 带 step 跳转目标
}
```

**适配预览（阶段⑤）**：P1 用前端本地规则（第三章数字）即时渲染截断效果；P2 切换为服务端 ContentAdapter 预览接口（真实适配，含 CTA 追加）。
