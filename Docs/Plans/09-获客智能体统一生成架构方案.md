# 获客智能体统一生成架构方案

> 基于整洁架构设计的获客智能体与统一生成抽象层

## 一、方案概述

### 1.1 背景

当前系统存在以下问题：
- 用户需要选择端点类型（text2video/img2video/reference2video等）
- 用户需要填写复杂参数（duration/resolution/aspect_ratio等）
- 用户需要理解模型和厂商的区别
- 新增厂商需要修改多处代码

### 1.2 目标

设计一个**傻瓜式**的获客智能体系统：
- 用户只需要上传素材、输入文本
- 系统自动选择端点、模型、参数
- 新增厂商只需实现翻译层
- 管理后台配置默认值

### 1.3 核心设计原则

```
┌─────────────────────────────────────────────────────────────┐
│                    设计原则（不可违反）                        │
├─────────────────────────────────────────────────────────────┤
│ 1. 用户无感：不选模型、不选服务商、不关心技术细节              │
│ 2. 管理后台配置：模型/服务商/能力路由 全部后台管理             │
│ 3. 适配器扩展：新增服务商 = 新增适配器，不改已有逻辑          │
│ 4. 工具封装：素材生成必须通过项目内 tool，不能直接调厂商 API  │
│ 5. 权限驱动：用户可设置决策权限，LLM根据权限决定是否询问用户  │
│ 6. 执行计划确认：最终执行计划需要用户确认，可修改             │
│ 7. 厂商能力查询：LLM可查询厂商能力描述，智能决策              │
│ 8. 失败通知：重试失败自动通知管理后台+用户                    │
└─────────────────────────────────────────────────────────────┘
```

## 三、素材定义与统一输入格式

### 3.1 素材实体定义（扩展现有MediaAsset）

**现状分析**：现有系统使用 `MediaAsset` 实体，但缺少一些必要字段。

**方案**：扩展 `MediaAsset` 实体，新增 `Type`, `Name`, `Width`, `Height`, `Duration` 字段。

```go
// entity/media_asset.go（扩展后）
type MediaAsset struct {
    ID        string     `json:"id"`         // 数据库主键（素材ID）
    TenantID  string     `json:"tenant_id"`  // 租户ID
    BrandID   string     `json:"brand_id"`   // 品牌ID（归属品牌）
    OwnerType string     `json:"owner_type"` // material/creation
    Type      string     `json:"type"`       // 素材类型：image/video/audio（新增）
    Name      string     `json:"name"`       // 素材名称（用户可见，新增）
    SourceURL string     `json:"source_url"` // 素材访问URL
    StoredURL string     `json:"stored_url"` // 转存URL
    Mime      string     `json:"mime"`       // MIME类型（如 image/png）
    SizeBytes int64      `json:"size_bytes"` // 文件大小（字节）
    Width     int        `json:"width"`      // 图片/视频宽度（像素，新增）
    Height    int        `json:"height"`     // 图片/视频高度（像素，新增）
    Duration  float64    `json:"duration"`   // 音频/视频时长（秒，新增）
    MetaJSON  string     `json:"meta_json"`  // 扩展元数据JSON
    CreatedAt time.Time  `json:"created_at"`
    ExpiresAt *time.Time `json:"expires_at"`
}

// 素材类型常量（新增）
const (
    MaterialTypeImage = "image"  // 图片：png/jpeg/jpg/webp
    MaterialTypeVideo = "video"  // 视频：mp4/avi/mov
    MaterialTypeAudio = "audio"  // 音频：mp3/wav/m4a/aac
)
```

**素材类型识别规则**：
| 类型 | MIME前缀 | 文件扩展名 | 说明 |
|------|----------|------------|------|
| image | image/* | .png/.jpg/.jpeg/.webp/.gif | 图片素材 |
| video | video/* | .mp4/.avi/.mov/.mkv | 视频素材 |
| audio | audio/* | .mp3/.wav/.m4a/.aac/.ogg | 音频素材 |

**字段获取方式**：
- `Type`：根据MIME前缀自动识别（image/*→image, video/*→video, audio/*→audio）
- `Name`：用户上传时的文件名（去掉扩展名）
- `Width`, `Height`：图片/视频上传时自动获取（使用image库解析）
- `Duration`：音频/视频上传时自动获取（使用ffprobe或类似工具）

**迁移脚本**：
```sql
-- 060_extend_media_asset.sql
ALTER TABLE media_assets ADD COLUMN type VARCHAR(20) DEFAULT '' AFTER owner_type;
ALTER TABLE media_assets ADD COLUMN name VARCHAR(255) DEFAULT '' AFTER type;
ALTER TABLE media_assets ADD COLUMN width INT DEFAULT 0 AFTER size_bytes;
ALTER TABLE media_assets ADD COLUMN height INT DEFAULT 0 AFTER width;
ALTER TABLE media_assets ADD COLUMN duration DOUBLE DEFAULT 0 AFTER height;

-- 根据MIME类型回填type字段
UPDATE media_assets SET type = 'image' WHERE mime LIKE 'image/%';
UPDATE media_assets ADD INDEX idx_type (type);
```


## 四、端点自动选择（详细设计）

### 4.1 设计原则

**核心思想**：根据用户上传的素材类型和数量，自动选择最合适的端点。

**设计依据**：参考 Vidu 端点完整参数限制文档，每个端点对素材有明确要求：
- `text2video`：只需要文本（prompt）
- `img2video`：需要恰好1张图片
- `start_end2video`：需要恰好2张图片（首帧+尾帧）
- `reference2video`：需要1-7张图片，或使用主体模式
- `multiframe`：需要1张首帧 + 2-9张关键帧
- `lip_sync`：需要1个视频 + 音频或文本
- `digital_human`：需要1张图片 + 音频或文本
- `tts`：需要文本 + 音色ID
- `voice_clone`：需要参考音频 + 文本
- `text2audio`：只需要文本描述
- `text2image`：只需要文本描述

### 4.2 端点选择决策树

```
用户输入：文本 + 素材列表
    ↓
┌─────────────────────────────────────────────────────────────┐
│ Step 1: 统计素材类型和数量                                   │
├─────────────────────────────────────────────────────────────┤
│ imageCount = 图片数量                                        │
│ videoCount = 视频数量                                        │
│ audioCount = 音频数量                                        │
│ hasText = 文本是否非空                                       │
└─────────────────────────────────────────────────────────────┘
    ↓
┌─────────────────────────────────────────────────────────────┐
│ Step 2: 根据素材组合选择端点（优先级从高到低）               │
├─────────────────────────────────────────────────────────────┤
│ 情况1: videoCount > 0 && audioCount > 0                     │
│   → lip_sync（对口型）                                      │
│   原因：有视频+音频，最适合做对口型                          │
│   参数：video_url, audio_url                                │
├─────────────────────────────────────────────────────────────┤
│ 情况2: videoCount > 0 && audioCount == 0 && hasText         │
│   → lip_sync（对口型，文本驱动）                            │
│   原因：有视频+文本，用文本生成语音做对口型                  │
│   参数：video_url, text, voice_id                           │
├─────────────────────────────────────────────────────────────┤
│ 情况3: imageCount == 1 && audioCount > 0                    │
│   → digital_human（数字人口播）                             │
│   原因：单张图片+音频，适合做数字人口播                      │
│   参数：image, audio_url                                    │
├─────────────────────────────────────────────────────────────┤
│ 情况4: imageCount == 1 && audioCount == 0 && hasText        │
│   → img2video（图生视频）                                   │
│   原因：单张图片+文本，适合做图生视频                        │
│   参数：images[1], prompt                                   │
├─────────────────────────────────────────────────────────────┤
│ 情况5: imageCount == 2                                      │
│   → start_end2video（首尾帧视频）                           │
│   原因：恰好2张图片，适合做首尾帧视频                        │
│   参数：images[2], prompt                                   │
├─────────────────────────────────────────────────────────────┤
│ 情况6: imageCount >= 3                                      │
│   → reference2video（参考生视频）                           │
│   原因：多张图片，适合做参考生视频                           │
│   说明：multiframe需要特殊的"关键帧"语义，普通用户不会使用   │
│   参数：images[3-7], prompt                                 │
├─────────────────────────────────────────────────────────────┤
│ 情况7: audioCount > 0 && imageCount == 0 && videoCount == 0 │
│   → tts（语音合成）                                         │
│   原因：只有音频，做语音合成                                 │
│   参数：text, voice_id                                      │
├─────────────────────────────────────────────────────────────┤
│ 情况8: 只有文本（无素材）                                   │
│   → text2video（文生视频）                                  │
│   原因：只有文本，做文生视频                                 │
│   参数：prompt                                              │
└─────────────────────────────────────────────────────────────┘
```

### 4.3 端点选择规则表（详细版）

| 素材组合 | 端点类型 | 设计原因 | 参数要求 |
|----------|----------|----------|----------|
| 无素材，只有文本 | text2video | 文本生成视频 | prompt |
| 1张图片 | img2video | 单图生成视频 | images[1], prompt |
| 2张图片 | start_end2video | 首尾帧视频 | images[2], prompt |
| 3-7张图片 | reference2video | 参考生视频 | images[3-7], prompt |
| 1张图片+音频 | digital_human | 数字人口播 | image, audio_url |
| 1张图片+文本 | img2video | 图生视频 | images[1], prompt |
| 1个视频+音频 | lip_sync | 对口型 | video_url, audio_url |
| 1个视频+文本 | lip_sync | 对口型（文本驱动） | video_url, text, voice_id |
| 只有音频 | tts | 语音合成 | text, voice_id |
| 只有文本 | text2video | 文生视频 | prompt |

**说明**：
- **multiframe（智能多帧）**：需要特殊的"关键帧"语义（每帧有独立prompt和duration），普通用户不会使用，不纳入自动选择
- **reference2video vs multiframe**：reference2video更通用，multiframe是特殊场景
- **优先级**：按素材组合从特殊到通用排序，优先匹配更具体的场景

### 4.4 端点选择实现

```go
// usecase/generation/endpoint_selector.go
type EndpointSelector struct {
    materialRepo port.MaterialRepository
}

// MaterialStats 素材统计
type MaterialStats struct {
    ImageCount int
    VideoCount int
    AudioCount int
    Images     []entity.Material
    Videos     []entity.Material
    Audios     []entity.Material
}

func (s *EndpointSelector) Select(ctx context.Context, req UnifiedGenerationRequest) (string, entity.GenerationParams, error) {
    // 1. 获取素材信息
    materials, err := s.materialRepo.ListByIDs(ctx, req.Materials)
    if err != nil {
        return "", nil, err
    }
    
    // 2. 统计素材类型
    stats := s.analyzeMaterials(materials)
    hasText := req.Text != ""
    
    // 3. 根据素材组合选择端点
    subType, params, err := s.selectEndpoint(req, stats, hasText)
    if err != nil {
        return "", nil, err
    }
    
    // 4. 应用默认值
    params = s.applyDefaults(params, req)
    
    return subType, params, nil
}

func (s *EndpointSelector) analyzeMaterials(materials []entity.Material) MaterialStats {
    stats := MaterialStats{}
    for _, m := range materials {
        switch m.Type {
        case entity.MaterialTypeImage:
            stats.ImageCount++
            stats.Images = append(stats.Images, m)
        case entity.MaterialTypeVideo:
            stats.VideoCount++
            stats.Videos = append(stats.Videos, m)
        case entity.MaterialTypeAudio:
            stats.AudioCount++
            stats.Audios = append(stats.Audios, m)
        }
    }
    return stats
}

func (s *EndpointSelector) selectEndpoint(req UnifiedGenerationRequest, stats MaterialStats, hasText bool) (string, entity.GenerationParams, error) {
    // 情况1: 有视频+音频 → 对口型
    if stats.VideoCount > 0 && stats.AudioCount > 0 {
        return "lip_sync", s.buildLipSyncParams(req, stats), nil
    }
    
    // 情况2: 有视频+文本 → 对口型（文本驱动）
    if stats.VideoCount > 0 && hasText {
        return "lip_sync", s.buildLipSyncTextParams(req, stats), nil
    }
    
    // 情况3: 单张图片+音频 → 数字人口播
    if stats.ImageCount == 1 && stats.AudioCount > 0 {
        return "digital_human", s.buildDigitalHumanParams(req, stats), nil
    }
    
    // 情况4: 单张图片+文本 → 数字人口播（文本驱动）
    if stats.ImageCount == 1 && hasText {
        return "digital_human", s.buildDigitalHumanTextParams(req, stats), nil
    }
    
    // 情况5: 恰好2张图片 → 首尾帧视频
    if stats.ImageCount == 2 {
        return "start_end2video", s.buildStartEndParams(req, stats), nil
    }
    
    // 情况6: 3-9张图片 → 智能多帧
    if stats.ImageCount >= 3 && stats.ImageCount <= 9 {
        return "multiframe", s.buildMultiframeParams(req, stats), nil
    }
    
    // 情况7: 2-7张图片 → 参考生视频
    if stats.ImageCount >= 2 && stats.ImageCount <= 7 {
        return "reference2video", s.buildReference2VideoParams(req, stats), nil
    }
    
    // 情况8: 只有音频 → 语音合成
    if stats.AudioCount > 0 && stats.ImageCount == 0 && stats.VideoCount == 0 {
        return "tts", s.buildTTSParams(req, stats), nil
    }
    
    // 情况9: 只有文本 → 文生视频
    if hasText && stats.ImageCount == 0 && stats.VideoCount == 0 && stats.AudioCount == 0 {
        return "text2video", s.buildText2VideoParams(req), nil
    }
    
    return "", nil, fmt.Errorf("无法根据素材组合确定端点类型")
}
```

### 4.5 各端点参数构建

```go
// 文生视频参数
func (s *EndpointSelector) buildText2VideoParams(req UnifiedGenerationRequest) entity.GenerationParams {
    return entity.GenerationParams{
        "prompt":     req.Text,
        "duration":   req.Duration,
        "resolution": req.Quality,
    }
}

// 图生视频参数
func (s *EndpointSelector) buildImg2VideoParams(req UnifiedGenerationRequest, stats MaterialStats) entity.GenerationParams {
    return entity.GenerationParams{
        "images":     []string{stats.Images[0].URL},
        "prompt":     req.Text,
        "duration":   req.Duration,
        "resolution": req.Quality,
    }
}

// 首尾帧参数
func (s *EndpointSelector) buildStartEndParams(req UnifiedGenerationRequest, stats MaterialStats) entity.GenerationParams {
    return entity.GenerationParams{
        "images":     []string{stats.Images[0].URL, stats.Images[1].URL},
        "prompt":     req.Text,
        "duration":   req.Duration,
        "resolution": req.Quality,
    }
}

// 智能多帧参数
func (s *EndpointSelector) buildMultiframeParams(req UnifiedGenerationRequest, stats MaterialStats) entity.GenerationParams {
    startImage := stats.Images[0].URL
    var keyFrames []map[string]any
    for i := 1; i < len(stats.Images); i++ {
        keyFrames = append(keyFrames, map[string]any{
            "key_image": stats.Images[i].URL,
            "prompt":    "",
            "duration":  5,
        })
    }
    return entity.GenerationParams{
        "start_image":    startImage,
        "image_settings": keyFrames,
        "resolution":     req.Quality,
        "aspect_ratio":   req.AspectRatio,
    }
}

// 参考生视频参数
func (s *EndpointSelector) buildReference2VideoParams(req UnifiedGenerationRequest, stats MaterialStats) entity.GenerationParams {
    var imageURLs []string
    for _, img := range stats.Images {
        imageURLs = append(imageURLs, img.URL)
    }
    return entity.GenerationParams{
        "images":       imageURLs,
        "prompt":       req.Text,
        "duration":     req.Duration,
        "resolution":   req.Quality,
        "aspect_ratio": req.AspectRatio,
    }
}

// 对口型参数（音频驱动）
func (s *EndpointSelector) buildLipSyncParams(req UnifiedGenerationRequest, stats MaterialStats) entity.GenerationParams {
    return entity.GenerationParams{
        "video_url": stats.Videos[0].URL,
        "audio_url": stats.Audios[0].URL,
    }
}

// 对口型参数（文本驱动）
func (s *EndpointSelector) buildLipSyncTextParams(req UnifiedGenerationRequest, stats MaterialStats) entity.GenerationParams {
    return entity.GenerationParams{
        "video_url": stats.Videos[0].URL,
        "text":      req.Text,
        "voice_id":  "default",  // 默认音色
    }
}

// 数字人口播参数（音频驱动）
func (s *EndpointSelector) buildDigitalHumanParams(req UnifiedGenerationRequest, stats MaterialStats) entity.GenerationParams {
    return entity.GenerationParams{
        "image":     stats.Images[0].URL,
        "audio_url": stats.Audios[0].URL,
        "resolution": req.Quality,
    }
}

// 数字人口播参数（文本驱动）
func (s *EndpointSelector) buildDigitalHumanTextParams(req UnifiedGenerationRequest, stats MaterialStats) entity.GenerationParams {
    return entity.GenerationParams{
        "image":      stats.Images[0].URL,
        "text":       req.Text,
        "voice_id":   "default",
        "resolution": req.Quality,
```

```go
    return enabled[0].Model, nil
}
```

## 六、流程设计（无需额外翻译层）

### 6.1 关键发现

**现有系统已有的功能**：
- `EndpointAdapter.Validate()` - 校验参数
- `EndpointAdapter.BuildRequest()` - 构建请求体（包含model、参数格式转换）

**结论**：不需要额外的翻译层，EndpointAdapter已经实现了"翻译"功能。

### 6.2 subType分析

**原有系统中subType的用途**：
1. **客户端传入**：`json:"sub_type" binding:"required"`
2. **获取EndpointAdapter**：`uc.registry.Get(ctx, in.SubType)`
3. **获取模型能力向量**：`uc.registry.Capability(ctx, in.SubType, model)`
4. **翻译引用**：`translateRefs(in.SubType, cap, in.Params, in.Refs)`
5. **生成哈希**：`paramsHash(in.SubType, model, params)`
6. **记录到任务**：`SubType: in.SubType`

**新系统中的变化**：
- 客户端不再传入subType
- subType由EndpointSelector根据素材自动选择
- subType仍然需要，用于EndpointRegistry.Get()获取EndpointAdapter

### 6.3 正确的流程设计

```
客户端输入（统一格式：text + materials）
    ↓
EndpointSelector（新增）← 根据素材自动选择subType，构建端点特定参数
    ↓
GenerationUseCase.Submit()（修改）← 接收subType（自动选择的）和端点特定参数
    ↓
EndpointRegistry.Get(subType) → EndpointAdapter（现有）
    ↓
EndpointAdapter.BuildRequest()（现有）← 构建请求体（添加model等）
    ↓
ViduProvider.Submit()（现有）← 调用厂商API
```

### 6.4 EndpointSelector的职责

**EndpointSelector**是新增的核心组件，职责：
1. 根据素材类型自动选择端点（subType）
2. 将统一格式参数转换为端点特定参数
3. 填充默认值（duration、resolution等）

**输入**：UnifiedGenerationRequest（text + materials）
**输出**：subType + GenerationParams（端点特定参数）

```go
// usecase/generation/endpoint_selector.go
type EndpointSelector struct {
    materialRepo port.MaterialRepository
}

// SelectResult 端点选择结果
type SelectResult struct {
    SubType string                    // 端点类型（自动选择）
    Params  entity.GenerationParams   // 端点特定参数
}

func (s *EndpointSelector) Select(ctx context.Context, req entity.UnifiedGenerationRequest) (SelectResult, error) {
    // 1. 获取素材信息
    materials, err := s.materialRepo.ListByIDs(ctx, req.Materials)
    if err != nil {
        return SelectResult{}, err
    }

    // 2. 统计素材类型
    stats := s.analyzeMaterials(materials)
    hasText := req.Text != ""

    // 3. 根据素材组合选择端点
    subType, params, err := s.selectEndpoint(req, stats, hasText)
    if err != nil {
        return SelectResult{}, err
    }

    // 4. 应用默认值
    params = s.applyDefaults(params, req)

    return SelectResult{
        SubType: subType,
        Params:  params,
    }, nil
}
```

### 6.6 EndpointAdapter.BuildRequest()的作用

**现有EndpointAdapter的BuildRequest()已经实现了**：
1. 添加model参数
2. 参数名映射（如有需要）
3. 参数格式转换
4. 默认值填充

**示例**（img2videoAdapter.BuildRequest()）：
```go
func (img2videoAdapter) BuildRequest(ctx context.Context, model string, p entity.GenerationParams, payload string) (map[string]any, error) {
    body := map[string]any{
        "model":  model,  // 自动添加model

    }
    if payload != "" {
        body["payload"] = payload
    }
    return body, nil
}
```

### 6.7 为什么不需要额外的翻译层

**原因**：
1. **EndpointAdapter已经实现了翻译功能**：BuildRequest()负责构建请求体
2. **EndpointSelector负责端点选择**：根据素材选择subType
3. **职责清晰**：EndpointSelector选端点，EndpointAdapter构建请求

**对比**：
```
旧设计（有翻译层）：
客户端 → EndpointSelector → 翻译层 → EndpointAdapter → 厂商API

新设计（无翻译层）：
客户端 → EndpointSelector → EndpointAdapter → 厂商API
```

**优势**：
- 更简洁：减少一层抽象
- 复用现有：充分利用现有EndpointAdapter
- 职责清晰：EndpointSelector选端点，EndpointAdapter构建请求

### 6.8 厂商扩展性分析

**问题**：这套实现是否可以用于不同厂商？

**分析**：各组件的厂商相关性

| 组件 | 厂商相关性 | 说明 |
|------|------------|------|
| **EndpointSelector** | ❌ 厂商无关 | 根据素材类型选择端点，通用逻辑 |
| **EndpointAdapter** | ✅ 厂商特定 | 不同厂商的端点路径、参数格式不同 |
| **GenerationProvider** | ✅ 厂商特定 | 不同厂商的API地址、认证方式不同 |

**结论**：可以用于不同厂商，但需要为每个厂商实现不同的EndpointAdapter和GenerationProvider。

**厂商无关部分**（可复用）：
- EndpointSelector：根据素材选择端点
- GenerationUseCase：业务逻辑
- 统一输入格式

**厂商特定部分**（需要实现）：
- EndpointAdapter：不同厂商的端点路径、参数格式
- GenerationProvider：不同厂商的API地址、认证方式

**示例**：
```
Vidu厂商：
- EndpointAdapter: text2videoAdapter, img2videoAdapter, ...
- GenerationProvider: ViduProvider

新厂商（如可灵）：
- EndpointAdapter: klingText2VideoAdapter, klingImg2VideoAdapter, ...
- GenerationProvider: KlingProvider
```

### 6.9 流程澄清

**问题**：客户端请求是直接到达厂商适配器吗？

**回答**：不是，客户端请求经过多层处理：

```
客户端请求
    ↓
Handler层（参数校验、权限检查）
    ↓
EndpointSelector（厂商无关）← 根据素材选择subType
    ↓
GenerationUseCase（厂商无关）← 业务逻辑
    ↓
EndpointAdapter（厂商特定）← 构建请求体
    ↓
GenerationProvider（厂商特定）← 调用厂商API
    ↓
厂商API
```

**各层职责**：
1. **Handler层**：参数校验、权限检查、DTO转换
2. **EndpointSelector**：根据素材类型自动选择端点（厂商无关）
3. **GenerationUseCase**：业务逻辑（配额检查、任务管理等）
4. **EndpointAdapter**：构建请求体（厂商特定）
5. **GenerationProvider**：调用厂商API（厂商特定）

```go
    // 1. 端点自动选择（根据素材类型）
    subType, params, err := h.endpointSelector.Select(c.Request.Context(), req)
    if err != nil {
        fail(c, err)
        return
    }
    
    // 2. 翻译层：统一格式 → 厂商格式（包含模型选择）
    translatedParams, err := h.translator.Translate(c.Request.Context(), subType, params)
    if err != nil {
        fail(c, err)
        return
    }
    
    // 3. 提交任务
    task, err := h.genUC.Submit(c.Request.Context(), generation.SubmitInput{
        TenantID: middleware.CurrentTenantID(c),
        BrandID:  req.BrandID,
        SubType:  subType,
        Params:   translatedParams,
    })
    if err != nil {
        fail(c, err)
        return
    }
    
    success(c, generationTaskToView(task))
}
```

```go
5. 用户确认后执行，可修改
6. 发布前必须得到用户确认
7. 超时未确认自动停止
`, permissionLevel)
    parts = append(parts, coreRules)

    // 3. 加载补充规则（管理后台配置，可选）
```

```go
// agent/orchestrator.go
type AgentOrchestrator struct {
    llm          port.AIGenerator
    toolRegistry *port.ToolRegistry
    permissionUC *AgentPermissionUseCase
    promptBuilder *PromptBuilder
}

func (o *AgentOrchestrator) Execute(ctx context.Context, tenantID, userID, task string) error {
    // 1. 获取用户权限
    permission, _ := o.permissionUC.Get(ctx, tenantID, userID)
    
    // 2. 构建系统提示词（动态配置 + 硬编码）
    systemPrompt, _ := o.promptBuilder.Build(ctx, tenantID, permission.Level)
    
    // 3. 工具列表从 ToolRegistry 自动获取
    tools := o.toolRegistry.List()
    
    // 4. 调用 LLM 执行
    resp, _ := o.llm.Generate(ctx, port.AIRequest{
        System: systemPrompt,
        Prompt: task,
        Tools:  tools,
    })
    
    // 5. 处理工具调用
    for _, toolCall := range resp.ToolCalls {
        // 检查权限
        if o.needsConfirm(permission, toolCall) {
            // 等待用户确认
            confirmed := o.waitUserConfirm(ctx, toolCall)
            if !confirmed {
                continue
            }
        }
        
        // 执行工具
        result, _ := o.toolRegistry.Execute(ctx, toolCall)
        
        // 继续对话
        resp, _ = o.llm.Generate(ctx, port.AIRequest{
            System: systemPrompt,
            Prompt: fmt.Sprintf("工具执行结果：%v", result),
        })
    }
    
    return nil
}
```

```go
// usecase/generation/retry.go
type RetryStrategy struct {
    maxRetries int
    backoff    time.Duration
}

func (s *RetryStrategy) Execute(ctx context.Context, fn func() error) error {
    var lastErr error
    for i := 0; i <= s.maxRetries; i++ {
        if err := fn(); err != nil {
            lastErr = err
            time.Sleep(s.backoff * time.Duration(i))
            continue
        }
        return nil
    }
    return fmt.Errorf("重试 %d 次后失败: %w", s.maxRetries, lastErr)
}
```

## 十三、总结

### 13.1 核心设计要点

| 设计点 | 方案 | 说明 |
|--------|------|------|
| **素材定义** | 扩展MediaAsset | 新增Type/Name/Width/Height/Duration字段 |
| **端点选择** | 素材组合自动判断 | 根据图片/视频/音频数量自动选择最合适的端点 |
| **模型选择** | 数据库动态配置 | 按厂商区分，管理后台可修改默认模型 |
| **翻译层** | 不需要 | EndpointAdapter已实现翻译功能 |
| **模板管理** | 数据库动态配置 | 管理后台可增删改查，不是硬编码 |
| **API策略** | 只保留统一提交API | 删除原有高级提交API，简化设计 |
| **系统提示词** | 动态配置+硬编码 | 核心规则硬编码，补充规则管理后台配置 |

### 13.2 流程设计说明

**关键发现**：不需要额外的翻译层，EndpointAdapter已经实现了"翻译"功能。

**正确流程**：
```
客户端输入（统一格式：text + materials）
    ↓
EndpointSelector（新增）← 根据素材自动选择subType
    ↓
GenerationUseCase.Submit()（修改）← 接收subType（自动选择的）
    ↓
EndpointRegistry.Get(subType) → EndpointAdapter（现有）
    ↓
EndpointAdapter.BuildRequest()（现有）← 构建请求体（添加model等）
    ↓
ViduProvider.Submit()（现有）← 调用厂商API
```

**subType分析**：
- 原有系统：客户端传入subType
- 新系统：EndpointSelector根据素材自动选择subType
- subType仍然需要，用于EndpointRegistry.Get()获取EndpointAdapter

**优势**：
- 更简洁：减少一层抽象
- 复用现有：充分利用现有EndpointAdapter
- 职责清晰：EndpointSelector选端点，EndpointAdapter构建请求

### 13.3 API设计策略

**策略**：只保留统一提交API，删除原有高级提交API

| API | 方法 | 说明 | 状态 |
|-----|------|------|------|
| `/api/v1/generation/submit` | POST | 统一提交（傻瓜式） | **新增** |
| `/api/v1/generation/tasks` | POST | 高级提交 | **删除** |
| `/api/v1/generation/tasks/:id` | GET | 查询任务状态 | 保留 |
| `/api/v1/generation/tasks` | GET | 查询任务列表 | 保留 |
| `/api/v1/generation/templates` | GET | 查询模板列表 | 新增 |
| `/api/v1/generation/voices` | GET | 查询音色库 | 保留 |

**原因**：
1. 简化设计：只保留一种提交方式，降低维护成本
2. 用户无感：用户不需要选择端点、模型、参数
3. 统一入口：所有生成任务都通过同一个API提交

### 13.4 系统提示词管理

**设计原则**：
- 硬编码部分：核心规则、安全约束（不可修改）

## 十六、多厂商动态选择（v3.1新增）

### 16.1 问题描述

原有架构存在一个关键缺陷：`GenerationUseCase` 只支持单一 `provider`，无法实现不同业务使用不同厂商。

### 16.2 解决方案

**修改 `GenerationUseCase`，支持多厂商动态选择**：

```go
type GenerationUseCase struct {
    providers map[string]port.GenerationProvider  // 多厂商
    resolver  port.CapabilityResolver            // 能力路由
    // ...
}

// subType → capID 映射
var subTypeToCapID = map[string]string{
    "text2video":      "video",
    "img2video":       "video",
    "tts":             "tts",
    "voice_clone":     "voice-clone",
    // ...
}

// 根据 subType 动态选择 provider
func (uc *GenerationUseCase) getProvider(ctx context.Context, subType string) (port.GenerationProvider, error) {
    capID := subTypeToCapID[subType]
    cap, err := uc.resolver.Resolve(ctx, capID)
    if err == nil && cap.VendorID != "" {
        if provider, ok := uc.providers[cap.VendorID]; ok {
            return provider, nil
        }
    }
    return uc.providers[uc.defaultProvider], nil
}
```

### 16.3 配置示例

**能力路由配置**：
```sql

VALUES 
('tts#xiaomi-mimo', 'tts', 'xiaomi-mimo', 1),
('voice-clone#xiaomi-mimo', 'voice-clone', 'xiaomi-mimo', 1);

-- 视频/图片能力 → Vidu
INSERT INTO integration_capabilities (id, cap_id, vendor_id, is_default)
VALUES 
('video#vidu', 'video', 'vidu', 1),
('image#vidu', 'image', 'vidu', 1);
```
