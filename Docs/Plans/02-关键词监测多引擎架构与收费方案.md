## 一、问题 ①：为什么 5 次采样关键词全一样？

### 1.1 根因（代码实证）

| 链路 | 现状 | 影响 |
|---|---|---|
| `MonitorUseCase.Monitor`（monitor.go:83） | 默认 `sample_size=5`，EngineName 为空 → `RoutingProbe` 落到 **AgentProbe** | 5 次采样 |
| `AgentProbe.Probe`（agent_probe.go:46-103） | 每轮用**完全相同**的任务文本 + systemPrompt 调 LLM（工具：search_crawler/tavily_search） | **无问法轮换、无 temperature 随机** |
| 采样拼装（agent_probe.go:81） | `fmt.Sprintf("【搜索：%s】\n%s", keyword, answer)` | 5 段前缀相同 |

结论：**AgentProbe 没有问法多样化设计**——5 次采样的唯一差异来自 LLM 自身随机性与搜索结果，所以看起来"一模一样"。
对比：`DirectProbe`（direct_probe.go:169-189）已有 `generateProbeQuestions`（原词/推荐一些 X/X 哪家好/有了解过 X 吗/关于 X 推荐 + 本地化问法），但按 `i % len(questions)` **固定轮换、无随机**。

### 1.2 修复方案（P0，小改动）

按"策略 + 模板方法"抽取问法生成，AgentProbe/DirectProbe 共用：

```
port.AIEngineProbe (接口, 现状不变)
  ├── AgentProbe   → 改用 ProbeQuestioner 生成多样化任务（每采样一题，模拟"不同用户问法"）
  └── DirectProbe  → 复用 ProbeQuestioner（删重复实现）

port.ProbeQuestioner (新增接口)
  ├── DefaultQuestioner  基础 5 问法（原词/推荐/哪家好/了解过吗/关于X）
  └── LocalQuestioner    本地化问法（"望京附近有什么川菜馆"——有门店时前置）
```

关键改动点：
1. `internal/usecase/port/geo_engine.go`：新增 `ProbeQuestioner` 接口 + `ProbeOptions{Temperature}`（随机化：`math/rand` 打乱问法顺序 + temperature 0.8~1.2）
2. `internal/adapter/ai/probe_questions.go`（新文件）：把 direct_probe.go:169-189 的 generateProbeQuestions 上移为共享实现
3. `agent_probe.go`：每轮采样换用 `questioner.Next(ctx, keyword, localContext, i)`，raw_sample 前缀保留【问：xx】格式
4. 采样独立性：解析 LLM（analyzeMention）不受影响（仍独立解析，防自评 bias）

验收：同关键词监测 5 次采样应出现 ≥3 种不同问法（如"望京 川菜馆"、"望京附近有什么川菜馆"、"望京川菜馆哪家好"）。

## 二、问题 ②：多引擎（豆包/千问）接入——准备什么？

### 2.1 好消息：引擎抽象已存在，接入 = 加配置

现有架构（整洁架构，依赖方向向内）已天然支持多引擎：

```
usecase 层                      port 层                          adapter 层
MonitorUseCase ──调用──▶ AIEngineProbe (接口) ◀──实现── RoutingProbe (工厂)
                                ▲  ▲                               │
                                │  └──── DirectProbe（真实引擎直测）──┘
                                └─────── AgentProbe（模拟 Agent 搜索兜底）

RoutingProbe 路由规则（routing_probe.go:30-37）：
  EngineName 非空 且 llm_configs 表命中 → DirectProbe（真实引擎）
  否则 → AgentProbe（模拟引擎，免费兜底）
```

- `llm_configs` 表 = **引擎注册表**（Name/Provider/APIKey/BaseURL/Model，OpenAI 兼容协议）
- 前端"监测引擎"下拉已存在（`listLLMConfigs()`），选引擎 → `engine_name` 参数 → DirectProbe
- `MonitorMultiEngine` 已支持同一关键词多引擎批量监测（每引擎独立结果，详情页已有"AI 引擎提及率对比"）
- LLM 调用层 `trpc_agent.go:96-117` `resolveLLM`：按 Name 查配置 → `llmadapter.Build` → 30s TTL 缓存

### 2.3 架构改进点（为"多引擎对比"产品化）

| 层级 | 现状 | 改进（P1） |
|---|---|---|
| port | `AIEngineProbe` 单一接口 | 不变（已符合开闭原则——新引擎=新配置行） |
| adapter | 解析器固定 default 引擎（agent_probe.go:84） | 解析 LLM 可配（`AnalyzerConfig`），避免"模型自评 bias"（豆包监测豆包回答时解析也换非本引擎） |
| usecase | `MonitorKeyword`/`MonitorMultiEngine` 不查配额门、不注入 monitor scene（monitor.go:212） | **补配额门 + `WithUsageContext(ctx, tenant, "monitor")`**（当前缺陷：单关键词刷新既不扣配额也不进成本报表） |
| 数据 | usages 已有 `llm_config_name/model` 列 | 成本分析按引擎分组（见 §3.2） |
| 前端 | 引擎下拉 + 多引擎对比条已存在 | 详情页引擎 Tab 化（每引擎独立视图）+ 引擎成本预估展示（P2） |

## 三、收费调整方案

### 3.1 现状

- usages 表：每次 LLM 调用 1 行（AgentProbe 每采样 1 行——搜索调用 `RunWithTools` 不计；DirectProbe 每采样 2 行：提问+解析）
- 配额按场景计数（monitor 500/8000/-1）
- CostAnalysis 用**全局单一参考价**（`LLM_COST_PER_MToken` 默认 ¥1/百万 tokens）——**不区分模型**，豆包便宜 GPT 贵的问题无法体现

### 3.2 调整方案（P1-P2）

**① 引擎差异化成本（LLMConfig 加字段）**

```sql
ALTER TABLE llm_configs ADD COLUMN cost_per_mtok DECIMAL(8,2) NOT NULL DEFAULT 100;
-- 单位：分/百万 tokens；default 100（¥1），豆包 ~20（¥0.2），千问 ~60（¥0.6）
```

- `billing.CostAnalysis`：`SumBySceneSince` 改为按 `scene + llm_config_name` 分组，`cost = Σ(tokens × 该引擎 cost_per_mtok) / 1e6`
- 运营在管理后台维护各引擎参考价（随供应商调价更新，零发版）

**② 多引擎计量折算（配额语义）**

监测配额按"引擎数 × 采样数"折算（一次 MonitorMultiEngine = N 引擎 × M 采样 × (1+解析) 次调用）：
- `MonitorMultiEngine` 每次引擎监测计 `engine_count × sample_size` 行 usages（近似）
- free 版：默认引擎 only（下拉禁用多引擎）；pro：≤3 引擎；team：不限（Features 加 `multi-engine`，参照 `auto-monitor` 做法）
- 前端"监测引擎"下拉在 free 版只渲染 default（配合现有 quota 提示）

**③ 补计量漏洞（P0，顺手修）**

`MonitorKeyword`/`MonitorMultiEngine` 当前不扣配额不记场景——修复后与 `Monitor` 一致（402 拦截 + scene=monitor 进成本报表）。

**④ 订阅定价建议（供运营参考）**

| 维度 | 免费版 | 专业版 ¥299 | 团队版 ¥899 |
|---|---|---|---|
| 引擎数 | 1（default） | ≤3 | 不限 |
| 监测配额 | 30 次/月（现 DB 值，建议随引擎成本重估） | 8000 | 无限 |
| 采样数上限 | 5 | 10 | 20 |
| 成本模型 | 纯模拟引擎 ≈0 | 混用豆包/千问/DeepSeek ≈¥6-10/月 | 全量 ≈¥30-60/月 |
